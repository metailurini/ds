# v0.1.0 Test Plan — Lexer, Parser, AST, and Diagnostics

## Purpose

This test plan verifies the `v0.1.0` frontend milestone.

The goal is to prove that `ds` can read source files, tokenize them, parse them into an AST, and report useful syntax errors.

There is no runtime execution and no Bash emission in this version.

## Test categories

`v0.1.0` should include tests for:

- lexer;
- parser;
- AST output;
- diagnostics;
- CLI behavior;
- edge cases.

`docs/language.ds` is a syntax catalog, not a parser fixture for the full language. It may contain future syntax that is intentionally unsupported in `v0.1.0`.

Golden tests are strongly recommended because language frontend output should remain stable.

## Lexer tests

### Basic tokens

- Tokenizes `let` keyword.
- Tokenizes `if` keyword.
- Tokenizes `else` keyword.
- Tokenizes `true` and `false` boolean keywords.
- Tokenizes identifiers.
- Tokenizes integer literals.
- Tokenizes string literals.
- Tokenizes `{` and `}`.
- Tokenizes `(` and `)` if supported by the expression parser.
- Tokenizes `=`.
- Tokenizes comparison operators:
  - `==`
  - `!=`
  - `>`
  - `>=`
  - `<`
  - `<=`
- Tokenizes unary `!`.
- Tokenizes newlines.

### Comments

- Ignores full-line comments.
- Ignores trailing comments after code.
- Does not treat `#` inside a string as a comment.
- Preserves line numbers after comments.

### Strings

- Tokenizes simple string:

```ds
"hello"
```

- Tokenizes empty string:

```ds
""
```

- Tokenizes string containing spaces.
- Tokenizes string containing `#`.
- Handles escaped quote if escapes are implemented:

```ds
"hello \"world\""
```

- Reports unterminated string.
- Reports invalid escape if invalid escapes are rejected.

### Identifiers

- Tokenizes lowercase identifier.
- Tokenizes uppercase identifier.
- Tokenizes identifier with underscore.
- Tokenizes identifier with digits after the first character.
- Rejects or splits invalid identifier beginning with a digit, depending on chosen lexer behavior.

### Source locations

- First token starts at line `1`, column `1`.
- Tokens after spaces have correct columns.
- Tokens after blank lines have correct lines.
- Tokens after comments have correct lines.
- Unterminated string diagnostic reports correct start location.

## Parser tests

### Empty and comments

- Parses empty file.
- Parses file with only blank lines.
- Parses file with only comments.
- Parses file with comments between statements.

### Let statements

- Parses string variable declaration:

```ds
let name = "Danh"
```

- Parses integer variable declaration:

```ds
let count = 3
```

- Parses boolean variable declaration:

```ds
let ok = true
```

- Rejects missing identifier:

```ds
let = "Danh"
```

- Rejects missing `=`:

```ds
let name "Danh"
```

- Rejects missing expression:

```ds
let name =
```

### If statements

- Parses `if` without `else`:

```ds
if ok {
  echo "ok"
}
```

- Parses `if` with `else`:

```ds
if ok {
  echo "ok"
} else {
  echo "no"
}
```

- Parses nested `if`:

```ds
if ok {
  if ready {
    echo "ready"
  }
}
```

- Rejects missing condition:

```ds
if {
  echo "bad"
}
```

- Rejects missing opening brace:

```ds
if ok
  echo "bad"
}
```

- Rejects missing closing brace:

```ds
if ok {
  echo "bad"
```

### Command statements

- Parses simple command:

```ds
git status
```

- Parses command with multiple words:

```ds
docker compose up
```

- Parses command with string argument:

```ds
echo "hello world"
```

- Parses command after `let` statement.
- Parses command inside `if` block.
- Preserves command word order.
- Preserves quoted string as a single command word.

### Expressions

- Parses identifier expression.
- Parses string literal expression.
- Parses integer literal expression.
- Parses boolean literal expression.
- Parses unary `!` expression.
- Parses equality expression:

```ds
name == "Danh"
```

- Parses inequality expression:

```ds
name != "Other"
```

- Parses numeric comparisons:

```ds
count > 1
count >= 1
count < 10
count <= 10
```

- Parses grouped expression if parentheses are supported.
- Rejects incomplete binary expression:

```ds
name ==
```

## AST golden tests

AST output should be stable enough to test.

Fixtures should include:

```txt
input.ds
expected.ast
```

Recommended golden fixtures:

- empty file;
- comments-only file;
- simple `let` declarations;
- command statement;
- `if` without `else`;
- `if` with `else`;
- nested `if`;
- mixed statements;
- expression operators.

AST output should include enough structure to reveal parsing errors.

It does not need to expose internal memory addresses or unstable IDs.

## Diagnostics tests

### Invalid syntax

- Missing expression after `=` reports error.
- Missing closing brace reports error.
- Unterminated string reports error.
- Invalid `let` statement reports error.
- Invalid `if` statement reports error.
- Unexpected token reports error.

### Diagnostic quality

Each diagnostic should include:

- filename;
- line;
- column;
- `error` severity;
- clear message.

Where practical, diagnostic should include:

- source line;
- caret marker;
- short help text.

### Parser resilience

- Invalid input should not crash.
- Multiple invalid files in a test run should not corrupt global state.
- Very small invalid files should not crash.

## CLI tests

### `ds tokens`

- Exits `0` for valid file.
- Prints token output.
- Exits non-zero for missing file.
- Exits non-zero for lexical error.

### `ds ast`

- Exits `0` for valid file.
- Prints AST output.
- Exits non-zero for syntax error.
- Exits non-zero for missing file.

### `ds check`

- Exits `0` for valid file.
- Prints nothing or a short success message, depending on chosen UX.
- Exits non-zero for syntax error.
- Exits non-zero for missing file.

## Edge cases

- Empty file.
- File without trailing newline.
- File with many blank lines.
- File with only comments.
- Very long line.
- Very long string.
- Unicode inside string.
- Tabs before statements.
- Spaces before statements.
- Command with many arguments.
- Command after closing brace.
- Nested blocks.

## Manual smoke tests

Create temporary examples and run:

```sh
ds tokens examples/basic.ds
ds ast examples/basic.ds
ds check examples/basic.ds
ds check examples/bad.ds
```

Expected:

- valid example succeeds;
- invalid example fails with useful diagnostic.

## Syntax catalog checks

- Confirms `docs/language.ds` exists under `docs/`.
- Confirms `docs/language.ds` begins with comments explaining that it is a syntax catalog and not a runnable script.
- Confirms `docs/language.ds` documents status markers such as planned, stable, candidate, deferred, or rejected.
- Confirms `docs/language.ds` includes the `v0.1.0` supported syntax subset: comments, `let`, literals, `if/else`, expressions, and command statements.
- Confirms future syntax examples in `docs/language.ds` are not used as required parser acceptance fixtures for `v0.1.0`.
