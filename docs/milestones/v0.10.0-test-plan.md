# v0.10.0 Test Plan — Arrays, Maps, and Loops

## Purpose

This test plan verifies the `v0.10.0` collections and loops milestone without
expanding into the `v0.11.0` shell-oriented standard library.

The central requirement remains VM/Bash parity. Every supported collection and
loop program must behave the same when run directly by `ds` and when emitted to
standalone Bash.

The plan is intentionally broad because arrays, maps, and loops touch parsing,
lowering, runtime values, scopes, function bodies, imports, bytecode/VM
execution, Bash emission, diagnostics, and prior command semantics.

## Scope under test

Covered:

- array literals;
- empty arrays;
- array indexing;
- array append through `push` if implemented by the milestone;
- map literals with identifier and quoted string keys;
- map field access;
- map bracket access;
- duplicate map-key diagnostics;
- `for item in array` loops;
- `for key, value in map` loops if implemented by the milestone;
- `while condition { ... }` loops if implemented by the milestone;
- loop scoping;
- arrays/maps/loops inside functions;
- arrays/maps/loops across imports;
- command statements inside loops;
- captured `run` commands inside loops;
- redirection inside loops;
- standalone Bash emission;
- Bash 4 guard behavior for scripts that use associative maps;
- source-located diagnostics.

Not covered as supported behavior unless the spec is amended:

- nested destructuring;
- generic types;
- advanced collection methods;
- ordered map guarantees;
- nested arrays/maps;
- collection equality;
- index assignment;
- slices;
- ranges;
- `break` and `continue`;
- globbing and `lines()` iteration;
- file/path/cmd standard-library helpers;
- collection return values from functions.

Unsupported items still need negative tests so they fail clearly.

## Lexer tests

Validate tokenization for new syntax.

Cases:

- `let xs = []`;
- `let xs = ["api", "web"]`;
- `let x = xs[0]`;
- `xs.push("worker")`;
- `let ports = { api: 3000, web: 5173 }`;
- `let label = labels["api-service"]`;
- `let port = ports.api`;
- `for service in services { echo "{service}" }`;
- `for name, port in ports { echo "{name}:{port}" }` if map loops are
  implemented;
- `while i < 3 { i += 1 }` if while loops are implemented.

Assertions:

- brackets, commas, colons, dots, and braces tokenize deterministically;
- `for`, `in`, and `while` are tokenized as keywords if keyword-specific output
  exists;
- map literals are distinguishable from blocks by parser context;
- comments and newlines around array/map elements and loop heads do not change
  token order unexpectedly;
- token debug output remains pointer-free and stable.

## Parser and AST tests

### Valid array parse cases

Run `ds ast` and `ds check` for:

```ds
let empty = []
let services = ["api", "web", "worker"]
let nums = [1, 2, 3]
let flags = [true, false]
let mixed = ["api", 3, true]
```

```ds
let services = [
  "api",
  "web",
  "worker"
]
```

```ds
let services = ["api", "web"]
let first = services[0]
echo "first={first}"
```

Assertions:

- AST includes array literal nodes with ordered elements;
- empty arrays have an explicit representation;
- multiline array literals preserve source locations;
- index expressions include target and index expression;
- AST output remains pointer-free and stable.

### Valid map parse cases

Run `ds ast` and `ds check` for:

```ds
let ports = {
  api: 3000,
  web: 5173
}

let api_port = ports.api
let web_port = ports["web"]
```

```ds
let labels = {
  "api-service": "api",
  "web-service": "web"
}

let label = labels["api-service"]
```

Assertions:

- AST includes map literal nodes with key/value entries;
- identifier keys and string keys are represented distinctly or normalized
  deliberately;
- field access and bracket access are distinct where needed by lowering;
- map literals are not parsed as blocks;
- AST output remains stable.

### Valid loop parse cases

Run `ds ast` and `ds check` for:

```ds
let services = ["api", "web"]

for service in services {
  echo "{service}"
}
```

If map iteration is implemented:

```ds
let ports = { api: 3000, web: 5173 }

for name, port in ports {
  echo "{name}:{port}"
}
```

If `while` is implemented:

```ds
let i = 0

while i < 3 {
  echo "{i}"
  i += 1
}
```

Assertions:

- AST includes loop variable names, iterable/condition expressions, and body;
- loop bodies are parsed as blocks;
- loop syntax is not confused with shell command statements;
- nested `if` and function calls inside loop bodies parse correctly.

### Parser recovery and syntax diagnostics

Each invalid fixture should fail `ds check` with a source-located diagnostic:

```txt
let xs = [
let xs = ["a",]
let xs = ["a",, "b"]
let x = xs[]
let x = xs[0
let ports = { api }
let ports = { api: }
let ports = { : 3000 }
let ports = { api: 3000,, web: 5173 }
let x = ports.
for in services {}
for service services {}
for service in {}
for service in services echo "missing block"
for name, in ports {}
while {}
while i < 3 echo "missing block"
```

Assertions:

- diagnostics include filename, line, and column;
- parser recovery does not crash or loop;
- invalid fixtures do not execute commands during `check`;
- invalid fixtures do not emit Bash output.

## Semantic/lowering tests

### Array validation

Valid:

```ds
let services = ["api", "web"]
let first = services[0]
echo "{first}"
```

```ds
let services = []
services.push("api")
services.push("web")

for service in services {
  echo "{service}"
}
```

Reject:

```ds
let services = ["api"]
let bad = services["0"]
```

```ds
let service = "api"
service.push("web")
```

```ds
["api"].push("web")
```

```ds
let services = ["api"]
let bad = services[-1]
```

Assertions:

- invalid index type diagnostics mention integer indexes;
- `push` diagnostics mention arrays and mutable variables;
- negative literal indexes are rejected before execution where possible;
- semantic failure prevents VM execution and Bash emission.

### Map validation

Valid:

```ds
let ports = { api: 3000, web: 5173 }
let api = ports.api
let web = ports["web"]
echo "{api}:{web}"
```

```ds
let labels = { "api-service": "api" }
let api = labels["api-service"]
echo "{api}"
```

Reject:

```ds
let ports = { api: 3000, api: 3001 }
```

```ds
let ports = { "api": 3000, api: 3001 }
```

```ds
let not_map = "api"
let bad = not_map.api
```

```ds
let ports = { api: 3000 }
let bad = ports[0]
```

If empty maps are deferred:

```ds
let ports = {}
```

Assertions:

- duplicate key diagnostics identify the repeated key;
- field access on non-map values fails clearly;
- bracket access with unsupported key types fails clearly;
- deferred empty-map syntax has an intentional diagnostic.

### Loop validation

Valid:

```ds
let services = ["api", "web"]

for service in services {
  echo "{service}"
}
```

Reject:

```ds
let service = "api"

for item in service {
  echo "{item}"
}
```

```ds
let services = ["api"]

for service, other in services {
  echo "bad"
}
```

If map iteration is implemented, valid:

```ds
let ports = { api: 3000, web: 5173 }

for name, port in ports {
  echo "{name}:{port}"
}
```

If map iteration is deferred, the same fixture must fail with a clear diagnostic
that map iteration is not supported yet.

Assertions:

- array loops reject non-array iterables;
- array loops reject map-style two-variable heads;
- map loops reject one-variable heads if the final design requires two names;
- loop variables do not leak after the body;
- duplicate loop variable names are rejected.

### Scope validation

Cases:

```ds
let services = ["api"]

for service in services {
  let inside = service
  echo "{inside}"
}

echo "{service}"
```

Expected: reject `service` outside the loop, or reject earlier according to the
existing unknown-variable diagnostic style.

```ds
let services = ["api"]

for service in services {
  let temp = service
}

echo "{temp}"
```

Expected: reject `temp` outside the loop.

```ds
let service = "outer"
let services = ["inner"]

for service in services {
  echo "{service}"
}
```

Expected: either accept deliberate shadowing or reject it, matching the existing
block-scope rule. Lock the chosen behavior in tests.

## VM/Bash parity tests

Every valid fixture below should be exercised through direct VM execution and
emitted Bash:

```sh
ds fixture.ds > vm.out 2> vm.err
ds emit bash fixture.ds -o fixture.sh
bash -n fixture.sh
bash fixture.sh > bash.out 2> bash.err
```

Compare stdout, stderr where deterministic, and exit status.

### Arrays and indexing

Fixture:

```ds
let services = ["api", "web", "worker"]
let first = services[0]
let second = services[1]
let third = services[2]

echo "{first}"
echo "{second}"
echo "{third}"
```

Expected stdout:

```txt
api
web
worker
```

### Function parameters and collections

```txt

```

### Imports with collections


```txt

```


## Runtime error tests

Runtime errors should match in exit status and have useful diagnostics in both
VM and emitted Bash. Exact wording may differ if tests assert stable substrings.

Cases:

```ds
let services = ["api"]
let bad = services[2]
echo "{bad}"
```

```ds
let ports = { api: 3000 }
let bad = ports.web
echo "{bad}"
```

```ds
let ports = { api: 3000 }
let key = "web"
let bad = ports[key]
echo "{bad}"
```

Assertions:

- exit status is non-zero;
- VM error mentions array index or missing map key;
- Bash error mentions array index or missing map key;
- no later commands run after the failing access.

## Command behavior inside loops

### Plain command fail-fast

Fixture:

```ds
let cmds = ["before"]

for cmd in cmds {
  false
  echo "SHOULD_NOT_PRINT"
}

echo "AFTER"
```

Expected:

- non-zero exit;
- stdout does not contain `SHOULD_NOT_PRINT` or `AFTER`;
- VM and Bash agree.

### Captured `run` is inspectable

Fixture:

```ds
let names = ["one", "two"]

for name in names {
  let result = run false

  if result.failed {
    echo "failed:{name}:{result.code}"
  }
}
```

Expected stdout:

```txt
failed:one:1
failed:two:1
```

### Redirection inside loops

Fixture:

```ds
let names = ["one", "two"]

for name in names {
  echo "{name}" |>> "out.txt"
}
```

Expected:

- VM and emitted Bash both create `out.txt` in the test temp working directory;
- file content is exactly:

```txt
one
two
```

## Bash emission tests

For every valid fixture:

- run `ds emit bash fixture.ds -o fixture.sh`;
- run `bash -n fixture.sh`;
- run the generated script;
- assert no generated script calls `ds`;
- assert generated scripts are executable or runnable through `bash` according
  to existing emitter conventions.

Additional Bash-specific checks:

- array-only scripts should not emit unnecessary associative-array guards;
- map-using scripts should emit a Bash 4+ guard if associative arrays are used;
- generated variable names should avoid collisions when loop variables share
  names with top-level variables or function-local variables;
- generated Bash should quote array and map values safely, including spaces,
  quotes, dollar signs, braces, and glob characters.

Quoting fixture:

```ds
let values = ["a b", "quote\"x", "dollar$HOME", "star*"]

for value in values {
  echo "<{value}>"
}
```

Expected stdout:

```txt
<a b>
<quote"x>
<dollar$HOME>
<star*>
```

## Diagnostics edge cases

Each case should fail with a source-located diagnostic and must not execute or
emit partial Bash:

```ds
let xs = ["a"]
let y = xs[true]
```

```ds
let xs = ["a"]
let y = xs[-1]
```

```ds
let xs = ["a"]
xs.push()
```

```ds
let xs = ["a"]
xs.push("b", "c")
```

```ds
let xs = ["a"]
xs.missing("b")
```

```ds
let ports = { api: 3000 }
ports.push("bad")
```

```ds
let ports = { api: 3000 }
let value = ports.missing
```

```ds
let ports = { api: 3000 }
for key, key in ports {
  echo "bad"
}
```

```ds
let xs = ["a"]
for item in xs {
  let item = "bad"
}
```

```ds
break
```

```ds
continue
```

Assertions:

- diagnostics identify unsupported syntax or invalid operation;
- duplicate-name diagnostics point to the duplicate where possible;
- unsupported `break`/`continue` are not silently parsed as commands if they are
  reserved for future loop control.

## Completion checklist

- [ ] Lexer tests cover arrays, maps, field/bracket access, `for`, and `while`
  syntax as scoped.
- [ ] Parser/AST tests cover valid and invalid collection/loop syntax.
- [ ] Semantic tests cover invalid indexes, invalid map keys, duplicate keys,
  invalid loop heads, invalid `push`, and scope leaks.
- [ ] VM tests execute supported arrays, maps, indexes, loops, and `push`.
- [ ] Bash emission tests generate standalone `bash -n` valid scripts.
- [ ] VM/Bash parity tests compare stdout, stderr where deterministic, and exit
  status.
- [ ] Runtime error tests cover out-of-range indexes and missing map keys.
- [ ] Command behavior inside loops preserves fail-fast and captured-run rules.
- [ ] Import/function/script-args integration tests are covered.
- [ ] Map iteration ordering is either tested according to the chosen contract
  or explicitly rejected as deferred.
- [ ] Empty-map behavior is explicitly tested according to the chosen design.
- [ ] Previous version regression suites still pass.
- [ ] Docs/examples are updated only for implemented behavior.
- [ ] Deferred items are recorded in the spec before closing the milestone.
