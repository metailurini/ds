# v0.11.0 Test Plan — Shell-Oriented Standard Library

## Purpose

This test plan verifies the `v0.11.0` shell-oriented standard-library milestone
without expanding into networking, config parsing, temporary resources,
directory mutation, or other future stdlib areas.

The central requirement remains VM/Bash parity. Every supported standard-library
program must behave the same when run directly by `ds` and when emitted to
standalone Bash.

The plan is broad because stdlib helpers touch parsing, semantic checks, HIR
lowering, runtime values, command execution, file side effects, environment
mutation, collection/loop behavior, Bash helper emission, diagnostics, and prior
VM/Bash parity guarantees.

## Scope under test

Covered:

- `file.exists(path)`;
- `file.is_file(path)`;
- `dir.exists(path)`;
- `file.read(path)`;
- `file.write(path, text)`;
- `file.append(path, text)`;
- `path.cwd()`;
- `path.join(...)`;
- `path.basename(path)`;
- `path.dirname(path)`;
- `path.ext(path)`;
- `cmd.exists(name)`;
- `cmd.require(name)`;
- `env.get(name)`;
- `env.get(name, default)`;
- `env.set(name, value)`;
- `env.unset(name)`;
- `glob(pattern)`;
- `glob!(pattern)`;
- `lines(path)`;
- stdlib calls inside functions;
- stdlib calls across imports;
- stdlib calls inside loops and conditions;
- Bash helper emission and helper-name collision avoidance;
- diagnostics for unknown helpers, wrong arity, invalid environment names,
  unsupported deferred forms, and runtime failures.

Not covered as supported behavior unless the spec is amended:

- networking helpers;
- JSON/TOML/YAML/dotenv parsing;
- temporary files/directories;
- binary file APIs;
- recursive delete/copy/move;
- directory creation/listing/removal;
- broad file metadata;
- recursive `**` globbing if deferred;
- direct `env.NAME` access if deferred;
- streaming file handles;
- command pipelines;
- stdlib mocks.

Unsupported items still need negative tests so they fail clearly.

## Required test targets

Add a dedicated suite:

```txt
tests/v0_11/run.sh
```

Update the top-level test runner so:

```sh
make test-v0-11
make test
```

run the new suite plus all prior suites.

Use existing shared helpers from `tests/lib/testlib.sh`, especially VM/Bash
parity helpers. If file-side-effect or environment parity helpers are missing,
add them to the shared test library rather than copying one-off logic into the
version suite.

## Test data layout

Prefer small inline fixtures created in temporary directories by
`tests/v0_11/run.sh`, because stdlib tests need controlled files, directories,
PATH, and environment.

Suggested checked-in layout if golden output or import graphs are easier to
review:

```txt
tests/v0_11/fixtures/files-basic.ds
tests/v0_11/fixtures/paths-basic.ds
tests/v0_11/fixtures/cmd-env.ds
tests/v0_11/fixtures/glob-lines.ds
tests/v0_11/fixtures/import-main.ds
tests/v0_11/fixtures/import-lib.ds
tests/v0_11/fixtures/bad-*.ds
```

All temporary files, generated Bash, fixture output, and fake PATH commands must
live under the test temp directory, not the repository root.

## Lexer tests

Validate that existing tokenization covers namespace calls and special helper
names.

Cases:

```ds
if file.exists("package.json") { echo "yes" }
if file.is_file("README.md") { echo "file" }
if dir.exists("src") { echo "dir" }
let text = file.read("README.md")
file.write("out.txt", text)
file.append("out.txt", "\n")
let cwd = path.cwd()
let joined = path.join("src", "main.ds")
if cmd.exists("git") { echo "git" }
cmd.require("git")
let home = env.get("HOME")
env.set("NODE_ENV", "test")
env.unset("DEBUG")
for f in glob("*.txt") { echo $f }
for f in glob!("*.ds") { echo $f }
for line in lines("input.txt") { echo $line }
```

Assertions:

- dots, bangs in `glob!`, parentheses, commas, and string arguments tokenize
  deterministically;
- stdlib namespace names do not need to be lexer keywords unless the
  implementation deliberately reserves them there;
- token debug output remains pointer-free and stable;
- comments and newlines around helper calls do not alter token order.

## Parser and AST tests

Run `ds ast` and `ds check` for valid stdlib usage.

### File and directory helpers

```ds
if file.exists("package.json") {
  echo "package exists"
}

if file.is_file("README.md") {
  echo "readme file"
}

if dir.exists("src") {
  echo "src dir"
}

let text = file.read("README.md")
file.write("out.txt", text)
file.append("out.txt", "\n")
```

Assertions:

- namespace member calls are parsed as call expressions/statements;
- statement-oriented calls parse as statements;
- calls inside `if` conditions parse correctly;
- AST output remains deterministic and pointer-free.

### Path helpers

```ds
let cwd = path.cwd()
let joined = path.join("src", "main.ds")
let base = path.basename(joined)
let parent = path.dirname(joined)
let ext = path.ext(joined)
echo "{cwd}:{joined}:{base}:{parent}:{ext}"
```

Assertions:

- zero-argument and variadic calls parse correctly;
- nested helper calls parse correctly;
- helper results can be interpolated through bindings.

### Command and environment helpers

```ds
if cmd.exists("git") {
  echo "git found"
}

cmd.require("git")
let target = env.get("TARGET", "staging")
env.set("NODE_ENV", "test")
env.unset("DEBUG")
echo "target={target}"
```

Assertions:

- helper calls parse in conditions, value expressions, and statement positions;
- optional/default argument forms parse correctly;
- environment helper names do not conflict with normal variables.

### Globs and lines

```ds
for file in glob("*.txt") {
  echo $file
}

for file in glob!("*.ds") {
  echo $file
}

for line in lines("input.txt") {
  echo $line
}
```

Assertions:

- `glob!` parses as the required-glob helper rather than as unary `!` applied to
  `glob` unless the implementation deliberately chooses an equivalent AST;
- stdlib iterable calls work in `for` loop iterable positions;
- loop bodies parse normally.

## Semantic and lowering tests

### Namespace and builtin resolution

Valid fixtures should confirm that ordinary bare names can still be used when
they do not form a stdlib call head:

```ds
let file = "README.md"
if file.exists(file) {
  echo "exists"
}

for file in glob("*.txt") {
  echo $file
}
```

Assertions:

- `file.exists(...)` resolves to the stdlib namespace member;
- bare `file` can still be a normal binding or loop variable;
- diagnostics remain clear if user-defined functions try to redefine builtin
  callable names such as `glob` or `lines`.

### Unknown helpers and wrong arity

Invalid fixtures:

```ds
file.missing("x")
file.exists()
file.exists("a", "b")
file.read()
file.write("out.txt")
file.append("out.txt")
dir.exists()
path.cwd("extra")
path.join()
path.basename()
path.dirname()
path.ext()
cmd.exists()
cmd.require()
env.get()
env.get("A", "B", "C")
env.set("A")
env.unset()
glob()
glob!("a", "b")
lines()
```

Assertions:

- errors happen during check/lowering where possible;
- diagnostics include expected arity and actual arity;
- unknown helpers are not treated as shell command statements.

### Type diagnostics

Invalid fixtures when types are statically known:

```ds
file.exists(1)
file.read(true)
file.write("out.txt", 3)
dir.exists(false)
path.join("src", 1)
path.basename(1)
cmd.exists(42)
env.get(1)
env.set("A", true)
glob(1)
lines(false)
```

Assertions:

- statically known wrong argument types are rejected before VM/Bash execution;
- dynamic wrong types produce equivalent VM/Bash runtime failures when static
  rejection is not possible.

### Statement-only helper misuse

Invalid fixtures unless the spec is amended to return `null` deliberately:

```ds
let x = file.write("out.txt", "x")
let x = file.append("out.txt", "x")
let x = cmd.require("git")
let x = env.set("A", "B")
let x = env.unset("A")
```

Assertions:

- diagnostics explain that the helper is statement-only;
- emitted Bash is not generated for invalid programs.

## VM tests

Run direct VM execution for each successful helper area in a temp directory with
controlled files and environment.

### File predicates and directory predicates

Setup:

```txt
work/
  README.md
  src/
```

Program:

```ds
if file.exists("README.md") { echo "exists" }
if file.is_file("README.md") { echo "is-file" }
if !file.exists("missing.txt") { echo "missing" }
if dir.exists("src") { echo "is-dir" }
if !dir.exists("README.md") { echo "not-dir" }
```

Expected stdout:

```txt
exists
is-file
missing
is-dir
not-dir
```

Edge cases:

- path exists as directory but checked with `file.is_file` -> `false`;
- path exists as file but checked with `dir.exists` -> `false`;
- path with spaces;
- relative paths under current working directory.

### File read/write/append

Program:

```ds
let text = file.read("input.txt")
file.write("out.txt", text)
file.append("out.txt", "tail")
let after = file.read("out.txt")
echo "{after}"
```

Assertions:

- output and file contents match expected bytes/text;
- write overwrites existing content;
- append preserves existing content;
- missing parent directory is an error;
- reading a missing file is an error;
- reading a directory is an error;
- file with spaces in the name works;
- empty file reads as empty string;
- multiline file preserves newlines.

### Path helpers

Program should print a deterministic set of path operations:

```ds
echo path.join("src", "main.ds")
echo path.join("src/", "main.ds")
echo path.join("/tmp", "ds")
echo path.basename("/tmp/ds/file.txt")
echo path.dirname("file.txt")
echo path.dirname("/tmp/ds/file.txt")
echo path.ext("archive.tar.gz")
echo path.ext("README")
echo path.ext(".env")
```

Assertions:

- outputs follow the spec;
- `path.cwd()` returns the temp working directory when tests run the script from
  there;
- path helpers do not touch the filesystem except `cwd`.

### Command helpers

Setup a fake PATH directory containing an executable `fake-tool` and a
non-executable `not-exec`.

Program:

```ds
if cmd.exists("fake-tool") { echo "fake yes" }
if !cmd.exists("missing-tool") { echo "missing no" }
cmd.require("fake-tool")
echo "after require"
```

Assertions:

- executable command is found;
- missing command returns false;
- non-executable command is not considered available;
- `cmd.require("missing-tool")` exits non-zero and includes the command name;
- behavior is based on controlled PATH, not the developer machine.

### Environment helpers

Program:

```ds
let before = env.get("DS_V0_11_TARGET", "unset")
echo "before={before}"
env.set("DS_V0_11_TARGET", "production")
let after = env.get("DS_V0_11_TARGET")
echo "after={after}"
sh -c "printf 'child=%s\n' \"$DS_V0_11_TARGET\""
env.unset("DS_V0_11_TARGET")
let final = env.get("DS_V0_11_TARGET", "unset")
echo "final={final}"
```

Expected stdout contains:

```txt
before=unset
after=production
child=production
final=unset
```

Edge cases:

- invalid names such as `1BAD`, `BAD-NAME`, and empty string fail clearly;
- empty string values are preserved;
- values with spaces are preserved;
- parent shell environment is not changed by the test.

### Glob helpers

Setup:

```txt
a.txt
b.txt
c.ds
space name.txt
sub/nested.txt
```

Program:

```ds
for file in glob("*.txt") {
  echo $file
}

echo "--required--"
for file in glob!("*.ds") {
  echo $file
}
```

Assertions:

- matches are sorted lexicographically;
- unmatched `glob("nope-*.txt")` produces zero iterations;
- unmatched `glob!("nope-*.txt")` exits non-zero with a useful message;
- file names with spaces are preserved as one item;
- bracket and question-mark patterns work if implemented;
- recursive `**` is either tested as supported or rejected as deferred.

### Lines helper

Setup files:

- `empty.txt` empty;
- `lines.txt` with multiple newline-terminated lines;
- `unterminated.txt` with a final line and no trailing newline;
- `spaces.txt` with leading/trailing spaces and blank lines.

Program:

```ds
for line in lines("lines.txt") {
  echo "line={line}"
}

for line in lines("unterminated.txt") {
  echo "tail={line}"
}
```

Assertions:

- empty file produces zero iterations;
- final unterminated line is emitted;
- leading/trailing spaces are preserved in line values;
- blank lines produce empty string iterations;
- missing files, directories, and unreadable files fail clearly;
- line iteration has the same output in VM and Bash.

## Bash emitter tests

For every successful VM fixture, also run:

```sh
ds emit bash fixture.ds -o fixture.sh
bash -n fixture.sh
bash fixture.sh
```

Assertions:

- generated Bash is standalone;
- helper functions are emitted only when needed;
- helper names use internal prefixes and do not collide with user functions or
  variables;
- paths, env values, command names, glob results, and line values are quoted
  safely;
- failure helpers produce readable messages;
- Bash scripts do not call `ds`;
- Bash scripts honor controlled working directory, PATH, and environment.

Specific Bash checks:

- `file.exists` lowers to a Bash existence test or helper with equivalent
  behavior;
- `file.write` and `file.append` preserve exact text used in tests;
- `cmd.exists` uses controlled PATH;
- `env.set` uses exported values visible to child commands;
- `glob` unmatched patterns do not produce literal pattern strings;
- `lines` handles the final unterminated line.

## VM/Bash parity tests

Use a shared helper that runs the same fixture in VM mode and emitted Bash mode,
then compares:

- stdout;
- stderr where stable;
- exit status;
- resulting file contents for side-effect tests;
- child-command environment output;
- generated Bash syntax validity.

Parity fixture groups:

1. file and directory predicates;
2. file read/write/append side effects;
3. path helpers;
4. command helpers with fake PATH;
5. environment helpers;
6. glob helpers;
7. lines helper;
8. stdlib calls inside functions;
9. stdlib calls across imports;
10. stdlib calls inside loops and conditionals;
11. failure cases where both backends must exit non-zero.

## Functions, imports, and loops integration

### Functions

```ds
fn ensure_tool(name) {
  cmd.require(name)
}

ensure_tool("fake-tool")
```

```ds
fn read_name(path_name) {
  let text = file.read(path_name)
  echo "{text}"
}

read_name("name.txt")
```

Assertions:

- stdlib calls work inside function bodies;
- function-local bindings can hold stdlib return values;
- statement-only helpers inside functions preserve function/local scope.

### Imports

`import-lib.ds`:

```ds
fn print_first_line(path_name) {
  for line in lines(path_name) {
    echo "{line}"
  }
}
```

`import-main.ds`:

```ds
import "./import-lib.ds"
print_first_line("input.txt")
```

Assertions:

- imported functions can call stdlib helpers;
- emitted Bash bundles imported code and required helpers once;
- import-relative paths still resolve according to import rules, while runtime
  file paths are evaluated relative to the process working directory unless the
  language already defines otherwise.

### Loops

```ds
for f in glob("*.txt") {
  let text = file.read(f)
  echo "{f}:{text}"
}
```

Assertions:

- glob arrays/iterables interact with `for` loops;
- file names with spaces remain single loop values;
- command statements inside loops still use existing fail-fast behavior.

## Diagnostics tests

Each invalid or failing fixture should assert non-zero exit and useful output.
Avoid brittle full-output matching when source-highlighting is still evolving;
match key substrings.

### Static diagnostics

Invalid fixtures:

```txt
unknown stdlib namespace/member
wrong arity
wrong statically known type
invalid builtin redefinition if unsupported
statement-only helper used as value
unsupported direct env.NAME access if deferred
unsupported recursive glob if deferred
unsupported path-like command name if deferred
```

Expected diagnostic substrings:

- filename;
- line/column when available;
- helper or namespace name;
- expected arity/type or deferred feature note.

### Runtime diagnostics

Failing fixtures:

```txt
file.read("missing.txt")
file.write("missing-parent/out.txt", "x")
lines("missing.txt")
lines("directory")
cmd.require("missing-tool")
glob!("no-matches-*.txt")
env.get("1BAD")
env.set("BAD-NAME", "x")
```

Assertions:

- VM mode exits non-zero;
- emitted Bash exits non-zero;
- error output includes the failing helper and offending path/name/pattern where
  appropriate;
- successful output before the failure is preserved consistently in both modes
  where fail-fast behavior allows it.

## CLI smoke tests

For representative fixtures, run:

```sh
ds tokens fixture.ds
ds ast fixture.ds
ds check fixture.ds
ds bytecode fixture.ds
ds run fixture.ds
ds fixture.ds
ds emit bash fixture.ds -o fixture.sh
bash -n fixture.sh
bash fixture.sh
```

Assertions:

- debug commands do not crash on stdlib calls;
- `check` catches static stdlib errors without executing side effects;
- `bytecode` output is deterministic enough for smoke checks;
- direct execution and `run` behave the same for stdlib fixtures.

## Edge cases

File/path edge cases:

- paths with spaces;
- empty files;
- multiline files;
- final line without newline;
- blank lines and whitespace-preserving lines;
- hidden files such as `.env`;
- basename/dirname/ext with relative and absolute paths;
- write overwrite vs append;
- missing parent directories;
- directory passed to file read;
- file passed to `dir.exists`;
- permission-denied cases when reliable in the test environment.

Command/env edge cases:

- controlled PATH with fake executable;
- non-executable file on PATH;
- missing command;
- env var absent/present;
- env var empty string;
- env value with spaces and shell-sensitive characters;
- invalid env names;
- env mutation visible to later child command but not parent test process.

Glob/lines edge cases:

- zero matches for `glob`;
- zero matches for `glob!`;
- sorted multiple matches;
- matches with spaces;
- patterns with `?` and bracket classes if implemented;
- recursive `**` supported or rejected clearly;
- `lines` on empty, multiline, and unterminated files;
- `lines` on missing file/directory.

Bash emission edge cases:

- generated helpers not emitted when unused;
- generated helpers emitted once when imported files use the same helper;
- generated internal names do not collide with user functions/variables;
- generated Bash remains valid under `bash -n`;
- no generated Bash path calls back into `ds`.

After automated tests pass, run a small script manually from a temp project:

```ds
cmd.require("git")

let here = path.cwd()
echo "cwd={here}"

file.write("input.txt", "one\ntwo\n")
file.append("input.txt", "three")

for line in lines("input.txt") {
  echo "line={line}"
}

for candidate in glob("*.txt") {
  if file.is_file(candidate) {
    echo "file={candidate}"
  }
}
```

Run both:

```sh
ds run smoke.ds
ds emit bash smoke.ds -o smoke.sh
bash -n smoke.sh
bash smoke.sh
```

Confirm output, side effects, and exit status match.
