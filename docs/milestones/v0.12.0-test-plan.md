# v0.12.0 Test Plan — Cleanup: Standard Library and Type Consistency

## Purpose

This plan verifies the `v0.12.0` cleanup milestone. The version should improve
maintainability, consistency, and diagnostics for the standard-library/type path
without adding new syntax or new helpers.

The central requirement remains regression safety:

```txt
all supported v0.1.0-v0.11.0 behavior still works
VM and emitted Bash remain equivalent
unsupported/deferred features still fail clearly
internal refactors do not leak into user behavior accidentally
```

## Scope under test

Covered:

- centralized standard-library helper metadata;
- helper lookup, arity, return-kind, statement-only, iterable, and string-arg
  rules;
- builtin-name collision diagnostics;
- namespace-member resolution and ordinary bare variable coexistence;
- type/value-kind consistency for stdlib calls, script args, collections,
  command results, interpolation, and if conditions;
- VM stdlib behavior after refactor;
- Bash helper emission after refactor;
- staged hashmap absorption into the project-owned runtime/core boundary while
  preserving the `DsMap` abstraction and current map behavior;
- VM/Bash parity for existing stdlib, collection, function, import, command, and
  script-arg interactions;
- diagnostics consistency across `check`, `bytecode`, `run`, direct execution,
  and `emit bash` where applicable;
- test helper/Makefile behavior after cleanup.

Not covered as supported behavior:

- new stdlib helpers;
- direct `env.NAME` access/assignment;
- recursive `**` globbing;
- binary file APIs;
- directory mutation/listing;
- pipelines/background jobs;
- function return values;
- collection function arguments;
- map iteration, `while`, ranges, slices, and index assignment;
- tracing/debug commands from `v0.13.0`;
- the future test runner or formatter.

Unsupported items still need negative regression tests when they touch cleaned
code paths.

## Static cleanup tests

Static checks should be limited and meaningful. They should catch known drift
risks without overfitting to harmless formatting.

### Shared stdlib metadata

Assertions:

- there is a single shared metadata table or lookup source for stdlib helper
  names;
- `file.exists`, `file.is_file`, `file.read`, `file.write`, `file.append`,
  `dir.exists`, `path.cwd`, `path.join`, `path.basename`, `path.dirname`,
  `path.ext`, `cmd.exists`, `cmd.require`, `env.get`, `env.set`, `env.unset`,
  `glob`, `glob!`, and `lines` appear in the shared metadata source;
- lowering no longer maintains a separate hand-written arity/return-kind list if
  the metadata table is introduced;
- VM/Bash stdlib dispatch uses helper lookup/name mapping instead of unrelated
  duplicate lists where practical.

Do not require an exact file name unless the implementation chooses one. If the
cleanup introduces `src/builtin.c` / `include/ds_builtin.h`, static checks may
assert those names. Otherwise, assert the actual chosen centralization point.

### Makefile/test target consistency

Assertions:

- `TEST_VERSIONS` includes `0-12` once;
- `make test-v0-12` works through the pattern target;
- older suites do not expect literal hand-written `test-v0-x:` Makefile blocks;
- `asan` and `ubsan` still call the normalized `test` target.

### Module-boundary sanity

If files are split:

- Makefile `SRC` includes every new `.c` file;
- `make clean && make` succeeds;
- no old source file includes a stale private prototype that should now live in a
  header;
- docs mention the new boundary where useful.

If files are not split:

- the completion review documents why the split was deferred;
- static tests should not fail merely because the project kept one file.

### Hashmap absorption boundary

Assertions:

- production builds no longer depend on `libs/hashmap/hashmap.c` or
  `-Ilibs/hashmap` once the implementation is absorbed;
- the old `libs/hashmap/` subtree is absent, empty of production code, or called
  out in the completion review as intentionally deferred debt;
- the absorbed hashmap source/header lives under a project-owned internal path
  such as `src/core/`, `src/runtime/`, or another clearly documented internal
  area;
- license and attribution text from the owned hashmap remain present in the
  moved source/header or an adjacent notice;
- `DsMap` is still the only production abstraction used by parser, AST, lowerer,
  VM, Bash emitter, and public headers;
- no production file outside the absorbed map implementation includes the raw
  hashmap header or calls `hm_*` functions;
- `src/runtime.c` or the new runtime map module contains the only bridge between
  `DsMap` and the raw hashmap implementation;
- direct unit-test compile commands and sanitizer helper compile commands use the
  new source/header paths, not `libs/hashmap`.

Suggested static check shape:

```sh
grep -R -nE 'libs/hashmap|-Ilibs/hashmap' Makefile compile_flags.txt docs tests src include
grep -R -nE '#include[[:space:]]+[<"].*hashmap|\bhm_[a-z_]+\b' src include \
  | grep -v '<chosen internal hashmap implementation file>'
```

The second check should allow the actual absorbed implementation file and its
private header, but should fail for frontend/lowering/VM/emitter leakage.

## Public behavior regression matrix

Run representative VM/Bash parity fixtures that exercise all helpers after the
cleanup.

### Stdlib happy path matrix

Fixture should cover at least:

```ds
file.write("tmp/input.txt", "one\ntwo\n")
file.append("tmp/input.txt", "three\n")

if file.exists("tmp/input.txt") {
  echo "exists"
}

if file.is_file("tmp/input.txt") {
  echo "file"
}

if dir.exists("tmp") {
  echo "dir"
}

let text = file.read("tmp/input.txt")
echo "text={text}"

echo "cwd={path.cwd()}"
echo "join={path.join("tmp/", "input.txt")}"
echo "base={path.basename("tmp/input.txt")}"
echo "dir={path.dirname("tmp/input.txt")}"
echo "ext={path.ext("archive.tar.gz")}"

let target = env.get("DS_V012_TARGET", "staging")
env.set("DS_V012_TARGET", "prod")
echo "target={env.get("DS_V012_TARGET")}"
env.unset("DS_V012_TARGET")
echo "fallback={env.get("DS_V012_TARGET", target)}"

for f in glob("tmp/*.txt") {
  echo "glob={f}"
}

for f in glob!("tmp/*.txt") {
  echo "required={f}"
}

for line in lines("tmp/input.txt") {
  echo "line={line}"
}
```

Assertions:

- VM and Bash stdout/stderr/exit status match;
- side-effect files match;
- emitted Bash is standalone and passes `bash -n`;
- helper bodies are emitted only when needed for the fixture.

### Cross-feature matrix

Cover stdlib calls inside:

- functions;
- imported files;
- array loops;
- `if` conditions;
- command arguments through scalar bindings;
- captured command-result control flow.

Example shape:

```ds
import "./lib.ds"

fn print_file(path) {
  let base = path.basename(path)
  echo "base={base}"
  for line in lines(path) {
    echo "line={line}"
  }
}

file.write("tmp/a.txt", "alpha\n")
print_file("tmp/a.txt")
lib_check("tmp/a.txt")
```

Assertions:

- VM/Bash parity;
- imported stdlib calls are bundled into emitted Bash;
- helper dependencies from imported functions are detected;
- local variables named like namespaces do not break namespace helper calls.

## Helper metadata and type consistency tests

### Arity matrix

For each supported helper, check one valid arity and relevant invalid arities:

- zero args for one-arg helpers;
- extra args for fixed-arity helpers;
- zero args for variadic `path.join`;
- one and two args for `env.get`;
- three args for `env.get`;
- statement-only helpers used as expressions;
- value-returning helpers used as statements.

Assertions:

- diagnostics name the helper;
- diagnostics include expected/actual arity when relevant;
- `check`, `bytecode`, `run`, direct execution, and `emit bash` reject before
  executing side effects where possible;
- failed `emit bash` removes stale output artifacts.

### Argument kind matrix

Fixtures:

```ds
file.exists(123)
file.read(true)
file.write("out.txt", 123)
path.join("a", 1)
cmd.exists(false)
env.get(123)
glob(123)
lines(123)
```

Assertions:

- static non-string arguments are rejected consistently;
- diagnostics name the helper and mention string arguments;
- no backend emits or executes a helper after static rejection.

### Statement/value position matrix

Fixtures:

```ds
let x = file.write("out.txt", "x")
let y = cmd.require("git")
file.exists("README.md")
glob("*.ds")
lines("input.txt")
```

Assertions:

- statement-only helpers cannot be assigned/interpolated/used in conditions;
- value-returning helpers must be assigned/used in expressions or iterable
  positions as documented;
- diagnostics point to the call.

### Value-kind interaction matrix

Fixtures should check:

- stdlib booleans in `if` conditions;
- stdlib strings in interpolation;
- stdlib arrays in `for` loops;
- stdlib arrays cannot be passed whole to functions or commands if still
  deferred;
- command-result fields are unaffected by stdlib cleanup;
- collection literals still reject non-Bash-assignable expressions.

## Map/hashmap runtime absorption regression tests

The hashmap move must be behavior-preserving. Re-run and, where useful, extend
the existing map checks from `v0.10.0` under the `v0.12.0` suite so the boundary
cleanup cannot accidentally weaken language maps.

### Map behavior parity

Fixtures should cover:

- map literal with identifier keys;
- map literal with quoted string keys;
- mixed field access and bracket access;
- dynamic key lookup from a string variable;
- missing-key failure in VM and emitted Bash;
- duplicate static key diagnostics;
- maps inside functions;
- maps across imports;
- maps used in scripts that also use stdlib helpers;
- array-only scripts still avoiding the Bash 4 map guard;
- map-using scripts still emitting the Bash 4 associative-array guard.

Assertions:

- VM and Bash stdout/stderr/exit status match;
- no test assumes map iteration or map insertion order;
- missing-key diagnostics remain explicit and source-located where currently
  available;
- emitted Bash remains standalone and passes `bash -n`.

### `DsMap` implementation contract

If unit-style runtime tests remain, they should verify through `DsMap` APIs only:

- create/free on empty maps;
- set/get existing key;
- overwrite existing key;
- miss returns the documented miss result without mutating output values;
- keys are copied or retained according to the documented ownership rule;
- values are stored/released according to existing `DsValue` ownership rules;
- stress with many inserts still works after the move;
- collision-heavy inputs do not lose values;
- freeing after partial allocation failure remains safe where the project already
  has failure-injection coverage.

Do not expose raw `hm_*` calls from the language/runtime tests unless they live
inside a deliberately private hashmap implementation test.

### Build and tooling after absorption

Assertions:

- `make clean && make` succeeds from a fresh tree;
- `compile_flags.txt` no longer points editors at the old staged include path;
- docs/editor instructions no longer mention `libs/hashmap` as a live include
  path;
- old standalone `libs/hashmap/test.sh`, fuzz, or benchmark scripts are either
  moved to a project-owned developer-test location and still work, or their
  removal is documented in the completion review;
- generated delivery archives do not contain both an old staged hashmap and a
  duplicated absorbed copy unless the duplication is explicitly justified.

## Name-resolution and collision tests

### Namespace variables remain legal

```ds
let file = "README.md"
if file.exists(file) {
  echo "exists"
}

for path in glob("*.ds") {
  echo $path
}
```

Assertions:

- bare variables named `file`, `dir`, `path`, `cmd`, or `env` are allowed where
  already supported;
- namespace member calls still resolve to stdlib helpers;
- diagnostics do not falsely report duplicate namespace names.

### Builtin callable redefinitions are rejected

Invalid fixtures:

```ds
fn glob(pattern) { echo pattern }
fn lines(path) { echo path }
fn file.exists(path) { echo path }
fn cmd.require(name) { echo name }
```

Assertions:

- declaration-site diagnostics clearly say the name conflicts with a standard
  library helper;
- later call sites do not produce misleading secondary errors;
- imported duplicate/collision cases report once.

### Duplicate user names still work as before

Fixtures:

- duplicate functions;
- function and top-level `let` with the same name;
- script arg and local variable conflict where currently rejected;
- duplicate loop variable in the same scope where currently rejected.

Assertions:

- diagnostics remain clear and non-duplicated;
- cleanup does not turn ordinary duplicate variables into builtin-collision
  diagnostics.

## Runtime edge-case regressions

### File and lines errors

Cover VM and Bash parity for:

- `file.read` missing file;
- `file.read` directory;
- `file.read` embedded NUL;
- `file.write` missing parent;
- `file.write` overwrite behavior;
- `file.append` create and append behavior;
- `file.append` missing parent;
- `lines` missing file;
- `lines` directory;
- `lines` embedded NUL;
- `lines` preserves final unterminated line behavior;
- `lines` strips `\r` before `\n` if that remains documented.

Assertions:

- exit status matches;
- diagnostics mention the failing helper/path;
- no later statements run after fail-fast runtime errors;
- side-effect files are left in documented states.

### Glob errors and patterns

Cover:

- normal `glob` unmatched returns an empty iterable;
- `glob!` unmatched fails;
- sorted output for multiple matches;
- `?` pattern;
- bracket pattern;
- literal recursive `**` rejection during check/lower;
- dynamic recursive `**` rejection in VM and emitted Bash.

### Command helper errors

Cover:

- `cmd.exists` true for an executable file on PATH;
- false for a non-executable file on PATH;
- false for an executable/searchable directory;
- path-like executable file works if still supported;
- path-like directory returns false;
- `cmd.require` failure exits non-zero before following statements;
- `cmd.require` diagnostics mention the missing command.

### Environment helper errors

Cover:

- valid env get/set/unset;
- fallback value for missing env;
- empty string values;
- invalid static names;
- invalid dynamic names;
- unset after set;
- child command observes env mutation.

## Bash-emission regression tests

For fixtures that use specific helper families, assert helper emission behavior:

- no stdlib helpers in scripts that do not use stdlib;
- only file/path helpers where those are the only helpers used, if dependency
  tracking is granular enough;
- map/associative-array Bash 4 guard still appears only for map usage, not for
  array-only or stdlib-only scripts unless a helper truly requires it;
- all helper names use `__ds_` prefix;
- user variables/functions cannot collide with helper names;
- stale output artifacts are removed after failed `emit bash`;
- emitted Bash passes `bash -n`.

Avoid brittle full-script goldens unless a helper body is intentionally stable.
Prefer targeted contains/not-contains assertions plus VM/Bash parity.

## Diagnostics consistency tests

For representative invalid fixtures, run all relevant public entrypoints:

```sh
ds check bad.ds
ds bytecode bad.ds
ds run bad.ds
ds bad.ds
ds emit bash bad.ds -o bad.sh
```

Invalid cases:

- unknown namespace helper: `file.missing("x")`;
- unknown bare helper: `globall("*.ds")` if parsed as function call;
- wrong arity;
- non-string static argument;
- statement-only helper as value;
- value-returning helper as statement;
- builtin callable redefinition;
- direct `env.NAME` access;
- recursive literal `**` glob;
- direct collection access in command args;
- collection value passed to function.

Assertions:

- diagnostics use `path:line:column: error:` shape for static failures;
- messages are consistent enough across entrypoints;
- runtime-only failures still include the source location where available;
- failed emission does not leave stale scripts.

## Acceptance checklist for the test pass

- the dedicated suite exists and is wired into Makefile;
- all public behavior from `v0.1.0` through `v0.11.0` remains supported;
- hashmap absorption is complete or the exact remaining staged-debt exception is
  documented honestly;
- no new unsupported syntax starts passing silently;
- VM/Bash parity fixtures pass;
- side-effect file/env/path/command helper cases pass;
- diagnostics are source-located and non-duplicated for covered cases;
- ASAN/UBSAN are clean where the environment allows;
- docs and completion review are updated.
