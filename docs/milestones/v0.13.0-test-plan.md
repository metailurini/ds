# v0.13.0 Test Plan — Debugging and Tracing

## Status

Planned. Implement this plan after implementing the `v0.13.0` spec.

## Scope under test

This test plan covers only the `v0.13.0` debugging and tracing milestone:

- `ds hir <file.ds>`;
- improved `ds bytecode <file.ds>` output;
- `ds run --trace-cmd <file.ds> [args...]`;
- `ds run --trace-vm <file.ds> [args...]`;
- combined trace flags;
- emitted Bash source markers, command failure helpers, and optional
  `DS_TRACE_CMD=1` command tracing;
- runtime diagnostics with source spans;
- diagnostic consistency for touched paths;
- regression coverage proving normal execution and Bash emission remain
  behavior-preserving.

Not covered as supported behavior:

- interactive debugger;
- breakpoints;
- step-through UI;
- REPL;
- profiler/timing output;
- coverage reporting;
- `v0.14.0` `test`/`assert` blocks;
- `v0.15.0` formatter/checker behavior;
- new source-language syntax;
- new standard-library helpers.

Unsupported future items should still have negative tests if parser/CLI changes
could accidentally accept them.

## Required test target

Add a dedicated suite:

```txt
tests/v0_13/run.sh
```

Update the normalized Makefile version list so these work:

```sh
make test-v0-13
make test
make asan
make ubsan
```

The suite should use public CLI behavior as the primary signal. Static source
checks are allowed only for debug-surface wiring that cannot be verified through
CLI output.

## Test conventions

- Keep all temporary source files, emitted Bash files, fake commands, logs, and
  side-effect files under the suite temp directory.
- Normalize absolute temp paths in golden output before comparing when paths are
  inherently environment-specific.
- Compare stdout, stderr, and exit status separately.
- Trace output must be asserted on stderr, not stdout.
- Golden debug output should avoid depending on raw pointer addresses, temporary
  absolute paths, or allocation order.
- When a test compares VM and Bash tracing, normalize file paths if generated
  Bash embeds absolute source paths.
- Existing tests may continue to use helper shell functions from the shared test
  library; add small v0.13-specific helpers for trace normalization if useful.

## HIR debug output tests

### Minimal HIR fixture

Source:

```ds
let name = "world"
echo "hello {name}"
```

Command:

```sh
./ds hir minimal.ds
```

Assertions:

- exit status `0`;
- stdout contains a top-level program marker;
- stdout contains a `let` representation for `name`;
- stdout contains a command representation for `echo`;
- stderr is empty;
- repeated runs produce byte-for-byte identical normalized output.

### Full current-language HIR fixture

Create a fixture that uses the supported surface from v0.1 through v0.12:

```ds
script {
  arg app: string
  option target: string = "staging"
  option retries: int = 3
  flag force: bool = false
}

import "./lib.ds"

fn deploy(name = "api") {
  let files = ["a.txt", "b.txt"]
  for file in files {
    echo "file={file}"
  }
  let ports = { api: 3000, web: 5173 }
  echo "port={ports.api}"
  let result = run echo "deploy {name}"
  if result.ok {
    echo result.stdout
  }
  cmd.require("echo")
}

deploy(app)
```

Imported `lib.ds`:

```ds
fn helper() {
  echo "from lib"
}
```

Assertions:

- `ds hir main.ds` succeeds;
- output contains script declarations with their types/defaults;
- output contains both imported and root functions in deterministic order;
- output contains function parameters/defaults;
- output contains array and map literals;
- output contains `for` loop structure;
- output contains command-result/run expression structure;
- output contains stdlib call names such as `cmd.require`;
- output does not contain raw pointer-looking values such as `0x...`;
- source markers or span labels appear if implemented by the spec.

## VM command tracing tests

### Plain command trace

Create a fake command under temp `PATH`:

```sh
fake-ok() { printf 'ok:%s\n' "$1"; }
```

Source:

```ds
let target = "prod"
fake-ok $target
```

Command:

```sh
PATH="$fakebin:$PATH" ./ds run --trace-cmd script.ds
```

Assertions:

- stdout is exactly normal program output, e.g. `ok:prod`;
- stderr contains one `trace: cmd` line before any runtime failure or command
  stderr;
- trace line includes the source file path or basename;
- trace line includes line/column information where implemented;
- trace line includes expanded command words (`fake-ok prod`), not the literal
  `$target` only;
- exit status equals normal execution.

### Captured run trace does not change semantics

Fake command exits non-zero after printing stdout/stderr.

Source:

```ds
let result = run fake-fail "abc"
echo "ok={result.ok}"
echo "code={result.code}"
echo "out={result.stdout}"
echo "err={result.stderr}"
```

Assertions:

- normal VM and traced VM both exit `0`;
- stdout is identical between normal and traced VM;
- traced stderr contains command trace plus no accidental fail-fast diagnostic;
- captured stderr remains in `result.stderr` and does not leak to process stderr
  except through intentional trace output.

### Plain command failure trace

Source:

```ds
fake-fail-now
```

Assertions:

- normal VM exits non-zero;
- traced VM exits the same non-zero status;
- traced stderr contains command trace before the failure diagnostic;
- failure diagnostic still includes source context;
- stdout remains identical to normal VM.

### Tracing commands in control flow

Source:

```ds
fn run_one(name) {
  fake-ok $name
}

let xs = ["a", "b"]
for x in xs {
  run_one(x)
}

if true {
  fake-ok "then"
} else {
  fake-ok "else"
}
```

Assertions:

- trace contains exactly commands that execute;
- trace includes two loop iterations and the `then` command;
- trace does not include the non-executed `else` command;
- trace order matches execution order.

### Tracing commands from imports

Root imports a file whose function runs a command.

Assertions:

- trace identifies the imported file source for the imported command if span
  source tracking supports it;
- otherwise completion review documents limitation and test asserts the chosen
  fallback marker.

### Trace with redirection

Source:

```ds
fake-ok "one" |> "out.txt"
fake-err "two" !> "err.txt"
fake-mixed "three" &> "all.txt"
```

Assertions:

- trace shows the commands and useful redirection target information;
- redirected program output still goes to files, not stdout/stderr;
- side-effect files match normal untraced behavior;
- exit status matches normal execution.

## Edge cases

### CLI argument edge cases

- script arg named `--trace-cmd` after file path should be passed to the script;
- `ds run -- --trace-cmd script.ds` should fail or behave according to the
  existing CLI conventions, but must be documented by the test expectation;
- duplicate trace flags should either be accepted idempotently or rejected with a
  clear CLI error;
- combined trace flags in either order;
- trace flags with `--help` script arg after file path.

### Trace rendering edge cases

- command args containing spaces, quotes, dollars, backslashes, glob characters,
  and empty strings;
- interpolated command words;
- command variables from script args/options/flags;
- command words generated from map/index reads via scalar binding;
- redirection paths with spaces;
- command stderr output interleaved with trace output;
- commands that print no output;
- commands that produce large output.

### Source-location edge cases

- first line and last line failures;
- commands inside imported files;
- commands inside nested blocks;
- command generated from a function default argument path if applicable;
- diagnostics for files without trailing newline;
- caret placement for multibyte UTF-8 text should not crash, even if column width
  remains byte-oriented for now.

### HIR/bytecode determinism edge cases

- repeated runs of the same file;
- same program loaded through relative path and normalized path, with path output
  normalized by test helpers;
- import load-once behavior does not duplicate HIR/bytecode functions;
- map literal order in debug output follows source order where the lowered form
  preserves it, not hashmap iteration order.

### Bash standalone edge cases

- run emitted Bash from a different current working directory when paths are
  intentionally relative to script execution;
- run emitted Bash with `DS_TRACE_CMD` unset, empty, `0`, and `1`;
- user variables/functions should not collide with `__ds_` trace/failure helpers;
- emitted Bash trace/failure helpers work when strict mode is enabled;
- emitted Bash trace/failure helpers do not require GNU-only tools beyond the
  project's existing Bash assumptions.
