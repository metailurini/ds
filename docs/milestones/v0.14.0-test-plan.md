# v0.14.0 Test Plan — Test Runner

## Status

Planned. Implement this plan after implementing the `v0.14.0` spec.

## Scope under test

This plan covers only the `v0.14.0` test-runner milestone:

- top-level `test "name" { ... }` declarations;
- `assert expr` inside test blocks;
- `ds test [path]` behavior;
- parser, AST/HIR, semantic, VM, and Bash-emission behavior required by test
  blocks;
- imports and functions used by tests;
- failure reporting and diagnostics;
- normal execution and normal Bash emission ignoring tests;
- regressions for all previously supported production behavior.

Out of scope as supported behavior:

- mocks/stubs;
- snapshots;
- coverage;
- parallel runner;
- watch mode;
- test filtering unless the spec is amended;
- setup/teardown hooks;
- nested suites;
- formatter behavior from `v0.15.0`.

Unsupported future items should still receive negative tests when the parser or
CLI could accidentally accept them.

## Required test target

Add a dedicated suite:

```txt
tests/v0_14/run.sh
```

Update Makefile wiring so these work:

```sh
make test-v0-14
make test
make asan
make ubsan
```

The suite should primarily test public CLI behavior. Static source checks are
allowed for build wiring and for confirming normal Bash emission does not include
test-runner helpers when no optional Bash backend is implemented.

## Test conventions

- Create all temporary `.ds` files, emitted Bash files, fake commands, and side
  effects under the suite temp directory.
- Compare stdout, stderr, and exit status separately.
- Normalize absolute temp paths when comparing diagnostics or summaries.
- Avoid golden assertions on timings.
- Test names should be unique unless the fixture intentionally checks duplicate
  diagnostics.
- Each test fixture should be small and focused, with one reason to fail.
- Existing shared shell helpers may be reused; add v0.14-specific helpers for
  running `ds test` and normalizing test output if useful.

Assertions:

- `ds check` succeeds;
- `ds ast` includes a test declaration with the test name;
- `ds hir` includes the test block if `v0.13.0` HIR output is available;
- source spans are preserved in AST/HIR output where the implementation exposes
  them;
- normal unrelated AST nodes still print as before.

### Test name string handling

Fixtures:


```ds

  assert true
```

Assertions:

### Invalid test declarations

### Invalid nesting

Assertions:

- no tests execute.

### Assert placement and syntax


Assertions:

- diagnostics point at the assertion statement or malformed expression;
- `assert` is not accidentally treated as a command statement.

### Test-local scope isolation

### Production top-level statements do not run during tests

Fixture:

Assertions:

- `ds test` passes;
- `should-not-exist.txt` is not created;

### Script block interaction

Fixture:


Assertions:

- if accepted, `ds test file.ds` does not require the `app` positional arg;

## CLI edge cases

Commands and assertions:

- `./ds test missing.ds` fails with existing file-load diagnostic.
- `./ds test dir/` follows final directory-discovery policy.
- `./ds test --unknown file.ds` fails usage and does not run tests.
- `./ds test file.ds --extra` fails unless extra args are explicitly supported.
- `./ds test file.ds` with a file that has invalid production syntax fails before
  running any tests.
- `./ds test file.ds` with imports that have only production statements does not
  execute those production statements.

- `ds test` reports one passing test;
- normal run does not execute the test;
- emitted Bash is syntactically valid and does not execute the test;
