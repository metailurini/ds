# v0.16.0 Test Plan — Cleanup: Pre-Beta Hardening

## Purpose

This plan verifies the `v0.16.0` cleanup milestone. The version should harden
current behavior through `v0.15.0` without adding major language features.

The main signal is regression safety:

```txt
supported production features still run in the VM
supported production features still emit standalone Bash
VM and emitted Bash behavior remain equivalent
supported test-only features remain test-only
formatter/checker behavior is deterministic and does not execute user code
unsupported/deferred features still fail clearly
```

## Scope under test

Covered:

- docs/status accuracy for supported, test-only, experimental, and deferred
  areas;
- example validity and VM/Bash parity;
- formatter behavior after the final comment/trivia decision;
- checker warning behavior and warning flags;
- CLI/import composition boundaries;
- root-file debug command behavior versus composed command behavior;
- VM/Bash parity for features through `v0.15.0`;
- test-runner isolation from normal execution and Bash emission;
- runtime ownership under normal and sanitizer-backed test runs;
- internal static boundary checks for hashmap, generated Bash, formatter/checker,
  test-only nodes, headers, and temporary files;
- diagnostics for malformed, missing, unsupported, and runtime-failing inputs.

Not covered as supported behavior:

- `while`, `break`, `continue`, or `case`;
- function return values;
- string methods;
- regex/membership operators;
- map iteration and index assignment;
- nested collections;
- collection values passed directly to functions or commands;
- recursive `**` glob support;
- direct `env.NAME` access/assignment;
- formatter style configuration;
- warning suppression comments;
- editor/LSP integration;
- alternative shell backends;
- native compilation.

Unsupported future syntax should still be covered by negative tests when a
cleanup could accidentally accept it.

## Required test target

Add a dedicated cleanup suite:

```txt
tests/v0_16/run.sh
```

Update Makefile wiring so these work:

```sh
make test-v0-16
make test
make asan
make ubsan
```

The dedicated suite should mostly test public CLI behavior. Static checks are
allowed for boundary contracts that cannot be observed through public behavior.

## Test conventions

- Create temporary `.ds` files, generated Bash files, fake commands, side-effect
  files, formatted files, and diagnostics captures under the suite temp
  directory.
- Compare stdout, stderr, and exit status separately.
- Normalize temp paths in diagnostics before comparison.
- Use focused fixtures for individual diagnostics and one or two mixed fixtures
  for full parity.
- Avoid wall-clock timing assertions.
- Do not require exact sanitizer output unless a sanitizer failure is expected;
  tests should simply fail if sanitizer builds report errors.
- Behavior-preservation tests should run original and formatted programs in
  separate temp directories so file side effects cannot contaminate comparisons.
- When testing emitted Bash, run `bash -n` before executing the script.
- Generated Bash must be executed without relying on the `ds` binary in `PATH`
  unless the fixture intentionally invokes a user command named `ds`.

## Static and build wiring tests

### Makefile target wiring

Assertions:

- `TEST_VERSIONS` contains `0-16` exactly once and after `0-15`;
- `make test-v0-16` invokes `tests/v0_16/run.sh`;
- aggregate `make test` includes the new suite;
- `make asan` and `make ubsan` include the new suite or the aggregate target
  that includes it;
- any new cleanup source files are included in normal, ASAN, and UBSAN builds;
- `make clean all` succeeds.

### Status document existence and content

Assertions for `docs/status.md` or equivalent:

- document exists;
- names current supported public commands: `tokens`, `ast`, `check`, `fmt`,
  `hir`, `bytecode`, `run`, `test`, direct script execution, and `emit bash`;
- distinguishes production syntax from test-only syntax;
- states emitted Bash is standalone and must not call `ds`;
- documents formatter comment/trivia behavior as implemented in `v0.16.0`;
- lists key deferred items: `while`, `break`, `continue`, `case`, function return
  values, string methods, regex/membership operators, direct `env.NAME`,
  recursive `**`, map iteration, and nested collections;
- includes a next-wave note for `v0.17.0` control-flow work.

Avoid overfitting exact prose. Check stable headings or key phrases.

### Internal boundary checks

Hashmap boundary:

- no production file outside `src/runtime/hashmap.c`, `src/runtime/hashmap.h`,
  and the `DsMap` bridge includes the raw hashmap header;
- no production file outside the raw hashmap implementation/bridge calls `hm_*`;
- `include/ds.h` does not expose raw hashmap types;
- build files do not reference a stale `libs/hashmap` path.

Generated Bash boundary:

- emitted Bash for representative fixtures contains no invocation of the project
  binary as an implementation dependency;
- emitted Bash has a normal shebang/header and passes `bash -n`;
- test-only blocks are absent from normal emitted Bash behavior.

Formatter/checker non-execution boundary:

- `ds fmt`, `ds fmt --check`, `ds fmt --write`, `ds check`,
  `ds check --warnings-as-errors`, and `ds check --no-warnings` must not execute
  command statements from the checked/formatted source;
- static test can use a fixture containing `touch SHOULD_NOT_EXIST` and assert no
  side-effect file is created by formatting/checking.

Header/include boundary:

- new internal `.c` files should include focused headers where practical;
- no new source file should include `include/ds.h` merely to access private
  internals;
- `include/ds.h` may remain as the compatibility umbrella.

## CLI/import composition tests

### Root-file debug views

Fixture:

```ds
import "./lib.ds"

```

`lib.ds`:

```ds
echo "lib"
```

Assertions:

- `./ds tokens main.ds` shows tokens for the root file and does not inline `lib`;
- `./ds ast main.ds` shows the root file import statement and does not inline
  executable imported statements;
- diagnostics for malformed root syntax still point to the root file.

### Composed command views

Using the same fixture, assertions:

- `./ds check main.ds` succeeds;
- `./ds hir main.ds` includes composed executable order;
- `./ds bytecode main.ds` carries source spans from imported and root files;
- `./ds run main.ds` prints imported output before root output;
- direct `./ds main.ds` matches `./ds run main.ds`;
- `./ds emit bash main.ds -o out.sh` produces standalone Bash that prints the
  same output without loading `.ds` files at runtime;
- `./ds fmt main.ds`, if comments/trivia permit, formats only the root source
  passed to it and does not rewrite imported files unless a future workspace mode
  is explicitly added.

### Import edge cases

Fixtures and assertions:

- missing import path reports the missing imported file and import location;
- import cycle reports a readable stack and exits non-zero;
- duplicate imports load and execute imported statements once;
- imported file declaring a `script {}` block remains rejected;
- import path with spaces works when quoted;
- malformed imported file reports the imported file path and line/column;
- formatted main file preserves import path string meaning.

## Formatter tests

Run this section according to the final `v0.16.0` comment/trivia decision.

### Common formatter invariants

For every supported formatter fixture:

1. Run `./ds fmt input.ds > once.ds`.
2. Run `./ds fmt once.ds > twice.ds`.
3. Assert `cmp once.ds twice.ds` succeeds.
4. Run `./ds check once.ds`.
5. When deterministic, compare VM/Bash/test behavior before and after formatting.

Common edge cases:

- empty file;
- file with no final newline;
- strings with spaces, escaped quotes, interpolation, backslash escapes, and
  braces that are not interpolation;
- imports with relative paths and spaces;
- command redirections;
- captured `run` commands;
- arrays/maps/indexing/field access;
- test blocks and assertions;
- malformed source under `fmt`, `fmt --check`, and `fmt --write`.

### If comment preservation is implemented

Fixtures:

```ds
# file header
# second header

import "./lib.ds"

# app contract
script {
# positional app
arg app: string
}

# helper comment
fn helper(name = "world") {
# body comment
echo "hello {name}"
}

# branch comment
if app == "prod" {
# then comment
echo "prod"
} else {
# else comment
echo "dev"
}
```

Assertions:

- all comments remain present exactly once;
- header comments remain before imports/code;
- comments inside blocks are indented to block depth;
- comments before `else` or inside `else` do not move into the `then` block;
- formatting is idempotent;
- formatted source parses, checks, runs, and emits equivalent Bash.

Inline trailing comment fixture:

```ds
let name = "Danh" # user name
echo "hello {name}" # greeting
```

Assertions:

- if inline trailing comments are supported, they remain attached to the same
  logical line and formatting is idempotent;
- if inline trailing comments are still unsupported, `fmt` exits non-zero with a
  clear diagnostic and does not output partial rewritten source;
- inline trailing comments are never silently dropped.

Edge comment placements:

- comments before closing braces;
- comments between `}` and `else`;
- comments before and inside `test` blocks;
- comments surrounding imports;
- comments in an otherwise empty file;
- comments adjacent to unsupported syntax.

### If comment preservation remains deferred

Assertions:

- any file containing a comment exits non-zero under `ds fmt` with the documented
  unsupported-comment diagnostic;
- `ds fmt --check` on a commented file exits non-zero for the diagnostic, not for
  a generic formatting-difference message;
- `ds fmt --write` refuses commented files and leaves them unchanged;
- `ds check`, `ds run`, `ds test`, and `ds emit bash` continue to accept comments
  according to normal language behavior;
- docs/status/language catalog clearly state comment-preserving formatting is
  deferred;
- no formatter test expects silent comment deletion.

## Checker warning tests

### Existing warnings remain conservative

Unused local variable positives:

```ds
let unused = "x"
echo "done"
```

```ds
fn f() {
  let inner = 1
  echo "f"
}
```

Unused function parameter positive:

```ds
fn greet(name, unused = "x") {
  echo "hello {name}"
}
```

Unreachable test statement positive:

```ds
test "stops" {
  fail "stop"
  assert true
}
```

Assertions:

- normal `ds check` exits `0` for warning-only input;
- warnings include filename, line, column, source line, and caret;
- warning order is deterministic;
- `--warnings-as-errors` exits non-zero;
- `--no-warnings` suppresses warnings but not hard errors;
- `--warnings-as-errors --no-warnings` is invalid.

### Warning false-positive guards

No warning when variables/parameters are used by:

```ds
echo "{name}"
echo $name
let b = a + 1
if ok { echo "yes" }
assert ok
let item = xs[0]
let value = ports.api
file.write(path, content)
helper(name)
for item in items { echo "{item}" }
```

Additional edge cases:

- use inside imported files;
- use inside function default arguments where supported;
- use inside nested blocks;
- script args/options/flags used in commands and interpolation;
- test-local variables used only inside tests;
- variables named like namespaces (`file`, `dir`, `path`, `cmd`, `env`) but not
  colliding with namespace-member calls.

## VM/Bash parity matrix

Create one mixed deterministic production fixture covering:

```ds
script {
  arg app: string
  option target: string = "staging"
  option retries: int = 2
  flag force: bool = false
}

import "./lib.ds"

let services = ["api", "web"]
services.push(app)
let ports = { api: 3000, web: 5173 }

fn greet(name = "world") {
  echo "hello {name}"
}

greet(app)

for service in services {
  echo "service={service}"
}

let api_port = ports.api
echo "api={api_port} target={target} retries={retries} force={force}"

file.write("tmp/input.txt", "one\ntwo\n")
file.append("tmp/input.txt", "three\n")
let text = file.read("tmp/input.txt")
echo "text={text}"
echo "base={path.basename("tmp/input.txt")}"
echo "ext={path.ext("archive.tar.gz")}"

let capture = run sh -c "printf cap; printf err >&2; exit 7"
echo "capture={capture.stdout}:{capture.stderr}:{capture.code}:{capture.failed}"
```

Assertions:

- `./ds check` succeeds without unexpected warnings;
- `./ds run fixture.ds api --target prod --retries 3 --force` has expected
  stdout/stderr/status;
- direct execution matches `run`;
- emitted Bash passes `bash -n`;
- emitted Bash output/status matches VM output/status after normalizing temp
  paths;
- emitted Bash does not call `ds`;
- formatting the fixture, if supported by the comment decision, preserves VM and
  Bash behavior.

- missing required arg;

Stdlib:

- `dir.exists`;
- `path.cwd`, `path.join`, `path.basename`, `path.dirname`, `path.ext`;
