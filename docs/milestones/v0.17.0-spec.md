# v0.17.0 Spec — Control Flow Completion

## Status

Implementation complete. Tests are intentionally deferred to the follow-up
test-plan pass.

`v0.17.0` starts the next feature wave after the pre-beta cleanup pass. Its job
is to finish the core imperative control-flow surface that real shell scripts
need: useful `while` loops, loop-local `break`/`continue`, and a small portable
`case` statement.

## Goal

Add control-flow constructs that work the same way in direct VM execution and in
emitted standalone Bash:

```ds
let i = 0
while i < 3 {
  echo "i={i}"
  i += 1
}

for item in items {
  if item == "skip" { continue }
  if item == "stop" { break }
  echo $item
}

case lang {
  "bash" | "sh" { echo "shell" }
  "python"      { echo "python" }
  _             { echo "other" }
}
```

This milestone deliberately keeps the feature boring. It should unblock common
script patterns without pulling in function return values, map iteration,
ranges, regex, process control, or a general pattern-matching language.

The product rules still apply:

```txt
every supported production control-flow construct runs in the VM
every supported production control-flow construct emits standalone Bash
VM and emitted Bash behavior match for stdout, stderr, exit status, and side effects
unsupported/deferred forms fail clearly before partial execution/emission
generated Bash must not call ds
```

## Motivation

By `v0.16.0`, `ds` has conditionals, functions, array loops, command capture,
redirection, script args, imports, a standard library, formatter/checker tooling,
and test blocks. The most visible missing basic scripting features are now:

- `while` loops for retries, polling, counters, and input-driven loops;
- `break` and `continue` for early loop exit and skipping work;
- `case` for readable multi-branch command-line and string/int dispatch.

`v0.10.0` deferred `while` because useful loops require reassignment/update
syntax. The syntax catalog already shows reassignment and `+=`/`-=` for scalar
variables, but the implementation does not yet support them. Therefore this
milestone includes the minimum scalar reassignment surface needed to make
`while` practical and to keep the documentation honest.

## Non-goals

This version does not include:

- `until`; use `while !condition` instead;
- labeled `break` or labeled `continue`;
- `break N` / `continue N` depth arguments;
- `else` on loops;
- infinite-loop detection or arbitrary VM iteration limits;
- `for` ranges such as `1..10`;
- map iteration;
- index assignment such as `xs[0] = "x"`;
- collection mutation beyond existing array `push` and the scalar reassignment
  added here;
- function return values;
- `return` statements;
- recursive-call semantics beyond whatever existing function behavior already
  supports;
- arithmetic operators beyond integer `+`/`-` expression support and the
  scalar integer `+=`/`-=` updates scoped below;
- `*=`, `/=`, `%=`, `**=`, or arithmetic `*`, `/`, `%`, `**` work reserved for
  `v0.21.0`;
- regex case arms, glob case arms, character classes, or Bash `case` pattern
  semantics;
- fallthrough between `case` arms;
- multiple statements after a `case` arm without braces;
- pipelines from `v0.18.0`;
- formatter trivia/comment preservation from the `v0.16.0` deferral;
- new standard-library helpers;
- backend expansion beyond Bash emission;
- native compilation.

If an implementation detail is attractive but not needed for the constructs
above, defer it. This milestone should not become a general language-semantics
expansion.

## Syntax decisions

### Normal expression syntax for `case`

The roadmap sketch used `case $lang { ... }`, but `$name` is currently reserved
for command arguments. Normal expressions do not use `$` in `ds`. `v0.17.0`
therefore defines `case` selectors as normal expressions:

```ds
case lang {
  "bash" { echo "shell" }
}
```

During implementation, update `docs/language.ds`, `docs/roadmap.md`, examples,
and status docs so the runnable syntax does not contradict the command-argument
rule. `case $lang { ... }` should be rejected with a diagnostic that points users
to `case lang { ... }`.

### Reassignment surface

Add scalar reassignment statements:

```ds
name = expr
count += expr
count -= expr
```

Supported targets:

- existing scalar variables only;
- variables in the nearest visible scope according to existing block/function
  scope rules;
- script args/options/flags only if existing runtime/Bash behavior can update
  them consistently; otherwise reject assigning to script declarations with a
  clear diagnostic and record the deferral.

Unsupported targets:

```ds
xs[0] = "x"        # index assignment deferred
ports.api = 3000   # field assignment deferred
env.PATH = "..."   # direct env assignment deferred
unknown = 1        # assignment cannot introduce a new variable
```

Supported `+=` / `-=` behavior:

- integer + integer updates for counters;
- string + string concatenation through `+=` only if VM and Bash can agree
  exactly; otherwise defer string compound assignment and require `name = name +
  expr` if that already behaves consistently;
- reject boolean, null, array, map, command-result, and unsupported helper
  compound updates with clear diagnostics or runtime errors in both backends;
- `-=` is integer-only.

Plain `=` reassignment should accept any scalar value kind already supported for
`let` assignment when the variable already exists and both backends can store it
consistently. Collection reassignment may be supported only if it preserves the
existing collection copy/ownership model in VM and Bash; otherwise reject it and
record the deferral.

### `while` loops

Syntax:

```ds
while condition {
  statements
}
```

Rules:

- condition uses the same truthiness/comparison semantics as `if`;
- body uses the existing block-scope model;
- reassignment inside the loop can update an outer variable so loops can make
  progress;
- `let` bindings declared inside the loop body do not leak outside;
- functions, imports, test blocks, stdlib calls, commands, captured `run`, and
  redirection inside the loop follow existing semantics;
- nested `while` and mixed `for`/`while` loops are supported unless a clear
  implementation blocker is found and recorded before coding;
- no arbitrary iteration cap is added by the VM.

### `break` and `continue`

Syntax:

```ds
break
continue
```

Rules:

- allowed only inside `for` or `while` loop bodies;
- work inside nested blocks and `if` statements nested inside loop bodies;
- affect the nearest enclosing loop only;
- invalid at top level, inside functions with no active loop, inside test blocks
  with no active loop, and inside `case` arms that are not nested in a loop;
- no expression, label, or depth argument is accepted.

In function bodies, `break`/`continue` are valid only when the statement is
lexically inside a loop in that same function body. A function call made from a
loop must not allow a `break` inside the called function to break the caller's
loop.

### `case` statements

Syntax:

```ds
case selector {
  pattern1 | pattern2 { statements }
  pattern3            { statements }
  _                   { statements }
}
```

Selector:

- normal scalar expression;
- supported scalar values: string, int, bool;
- arrays, maps, command-result values, and null selectors are rejected unless
  the implementation can define portable string conversion without ambiguity.

Patterns:

- string literals;
- integer literals;
- boolean literals;
- `_` default arm;
- `|` separates alternatives in a single arm.

Rules:

- first matching arm executes;
- no fallthrough;
- at most one `_` default arm;
- `_` must be the final arm;
- duplicate literal patterns in the same `case` are diagnostics when statically
  visible;
- an empty `case` body is rejected;
- an arm body must use braces;
- selector and pattern comparison must be kind-aware and exact for supported
  scalar literals. Integer `1` must not match string `"1"`, and boolean `true`
  must not match string `"true"`. VM and Bash must agree without relying on
  shell string coercion.
- selectors whose scalar kind is unknown during lowering are rejected for this
  milestone instead of becoming VM-only behavior. This keeps exact matching
  portable to standalone Bash until the HIR carries richer runtime type tags.

Pattern syntax deliberately does not use Bash globbing. For example, `"*.txt"`
means the literal string `*.txt`, not a wildcard pattern. Regex matching remains
a later milestone.

## Parser and AST requirements

Add AST statement nodes for:

- scalar reassignment;
- `while`;
- `break`;
- `continue`;
- `case` and case arms.

Parser requirements:

- `tokens` exposes the relevant tokens deterministically;
- `ast` prints the new nodes deterministically and without pointer addresses;
- malformed statements produce source-located diagnostics;
- unsupported old deferred forms now either parse as supported syntax or retain
  clear rejection diagnostics if still out of scope;
- `case` becomes a keyword/token rather than a special identifier hack;
- `|` is accepted only where the grammar supports it for `case` alternatives
  until `v0.18.0` pipelines claim command/expression pipe syntax;
- one-line forms such as `if item == "x" { break }` remain accepted if the
  existing parser supports single-line block statements.

Malformed examples that must be rejected:

```ds
while { echo "bad" }
while ok echo "bad"
break 1
continue label
break
continue
case {
  _ { echo "missing selector" }
}
case lang {
  "bash"
}
case lang {
  _ { echo "default" }
  "bash" { echo "late" }
}
case $lang {
  _ { echo "bad selector syntax" }
}
```

## Lowering and semantic requirements

Lowering must keep VM and Bash emission on one shared semantic path.

Requirements:

- new statements are represented in HIR rather than handled by one backend only;
- reassignment validates that the target exists and is assignable;
- loop depth is tracked for `break`/`continue` validation;
- function boundaries reset loop-control validation so functions cannot break
  caller loops;
- test blocks lower the new syntax only for `ds test`; normal run/emission still
  ignores tests;
- `case` duplicate/default-order diagnostics are emitted before backend work;
- `case` arms introduce block scopes like other blocks;
- `while` bodies introduce scopes consistently with existing blocks while still
  allowing outer-variable reassignment;
- diagnostics should prefer semantic clarity over accepting backend-specific
  behavior.

If the current checker warning layer needs control-flow awareness to avoid noisy
false positives, update it conservatively. Do not attempt full data-flow
analysis. Obvious cases such as statements after unconditional `break` or
`continue` in the same block may warn only if reliable; otherwise defer.

## VM requirements

The VM must execute:

- scalar `=` reassignment;
- scalar `+=` and `-=` updates according to the supported rules;
- `while` loops;
- nested loops;
- `break` and `continue` targeting the nearest loop;
- `case` selector dispatch;
- the same constructs inside functions and tests where lexically valid.

Implementation approach is flexible, but it should fit the current bytecode
model:

- `while` can use existing conditional and unconditional jumps;
- `break`/`continue` can be patched to loop end/start targets during compile;
- `case` can lower to comparisons plus jumps rather than a dedicated VM opcode;
- reassignment should reuse existing value ownership/copy rules and scope lookup.

Runtime failures must include source locations where existing VM diagnostics do.

## Bash emission requirements

Generated Bash remains standalone and must not call back into `ds`.

Requirements:

- emit valid Bash for `while`, `break`, `continue`, `case`, and scalar
  reassignment;
- generated Bash passes `bash -n` for every supported fixture;
- generated Bash uses safe quoting for selector values and pattern literals;
- `case` may emit as Bash `case` only if literal matching semantics remain exact;
  otherwise emit portable `if`/`elif` comparisons;
- literal `*.txt` case patterns must not accidentally become Bash glob patterns;
- Bash loop-control statements must target the nearest emitted loop and not leak
  across function boundaries;
- Bash function-local variables remain local where previous milestones require
  local scoping;
- array/map helpers and temporary variables avoid collisions with user variables;
- scripts that do not use maps should not newly require Bash 4 because of this
  milestone alone.

## Formatter/checker requirements

Formatter support should be added for the new syntax if it can be done without
changing the `v0.16.0` comment/trivia decision:

- deterministic formatting for reassignment, `while`, `break`, `continue`, and
  `case`;
- idempotence for formatted control-flow fixtures;
- no execution during `fmt`, `fmt --check`, `fmt --write`, or `check`;
- comment-bearing files remain rejected by formatter until trivia preservation is
  implemented in a later milestone.

Checker warnings should remain conservative. Update scope tracking so loop and
case bindings/statements do not create false unused/shadowing warnings.

## Imports, functions, script args, and tests

The new constructs must work through existing composition rules:

- imported files may define functions containing `while`, `case`, and loop
  control;
- imported top-level executable statements with the new constructs execute
  before root statements as usual;
- emitted Bash bundles imported control-flow code into one standalone script;
- functions may contain loops and cases;
- loop-control validity is lexical per function/test body;
- `script {}` args/options/flags can be used as loop/case selectors and
  conditions;
- `ds test` can run tests that contain loops and cases;
- normal `run`, direct execution, and normal `emit bash` still ignore test
  blocks.

## Docs and examples

Update docs/examples only when implementation reaches this version.

Required docs updates during implementation:

- `docs/language.ds` marks `while`, `break`, `continue`, and `case` implemented
  in `v0.17.0`;
- `docs/language.ds` and `docs/roadmap.md` use expression-style `case lang`, not
  command-style `case $lang`, or clearly explain the final syntax decision;
- `docs/status.md` moves these constructs from deferred to supported;
- README project status includes `v0.17.0` once implementation is complete and
  marks tests as pending until the test-plan pass;
- examples include at least one control-flow example if it adds clarity.

Recommended example:

```txt
examples/control-flow.ds
```

It should demonstrate a bounded `while`, `break`, `continue`, and `case` without
requiring external commands beyond portable shell basics.

## Acceptance criteria

- Parser accepts supported reassignment, `while`, `break`, `continue`, and
  `case` syntax.
- Parser rejects malformed control-flow syntax with source-located diagnostics.
- Lowering validates assignment targets, loop-control placement, duplicate/default
  case arms, and unsupported selectors/patterns.
- VM executes all supported constructs.
- Bash emitter emits standalone Bash for all supported constructs.
- VM and emitted Bash agree on stdout, stderr where relevant, exit status, and
  file side effects for deterministic fixtures.
- `tokens`, `ast`, `hir`, and `bytecode` debug commands expose deterministic
  output for the new constructs.
- Formatter handles the new syntax or rejects only according to the existing
  comment/trivia rule, not because the syntax is unknown.
- Checker remains non-executing and avoids obvious false positives introduced by
  loop/case scopes.
- Imports, functions, script args, tests, commands, captured `run`, redirection,
  arrays, maps, and stdlib helpers continue to work with the new constructs
  where the combination is in scope.
- Unsupported/deferred adjacent syntax still fails clearly.
- Docs/examples are updated to match implemented behavior.
- Completion review records implemented items, deferrals, validation, and any
  technical debt carried to `v0.18.0`.

## Deferred items

Expected deferrals unless explicitly pulled into this spec by amendment:

- `until`;
- labeled or depth-based loop control;
- loop `else`;
- `return` and function return values;
- map iteration;
- ranges;
- index/field/env assignment;
- collection compound assignment;
- regex/glob/destructuring case patterns;
- fallthrough case arms;
- case arm guards;
- pattern binding;
- string methods;
- pipelines;
- full type checker or full data-flow warning analysis;
- comment-preserving formatter trivia.

## Completion review

Implementation complete. Tests complete.

Implemented:

- parser support for scalar reassignment, `while`, `break`, `continue`, and
  expression-style `case`;
- lowering validation for assignment targets, integer compound updates,
  loop-control placement, scalar case selectors, duplicate case patterns, and
  default-arm placement;
- VM bytecode support for integer `+`/`-`, reassignment, loop jumps,
  scope-aware `break`/`continue`, and kind-aware exact case dispatch;
- standalone Bash emission for the same supported surface without calling `ds`;
- Bash sidecar type tags for scalar variables used by emitted `case` comparisons
  and scalar-variable `if`/`while` truthiness so shell string coercion does not
  make `1`, `"1"`, `true`, and `"true"` interchangeable;
- formatter/checker traversal for the new syntax;
- docs and examples updated for the implemented syntax and deferrals.

Validation performed during implementation and test-plan execution:

- `make clean all` passed;
- `make check` passed;
- `make test-v0-17` passed after adding the dedicated control-flow suite;
- `make test-v0-16` passed after the version/wiring changes;
- sanitizer builds were smoke-checked through the v0.17 suite;
- manual VM/Bash parity smoke checks passed for bounded `while`, integer
  updates, `continue`, `break`, case alternatives, kind-aware exact literal
  matching, copied scalar variables, and a default-only case;
- negative smoke checks verified duplicate case pattern and string binary `+`
  diagnostics.

Deferred to later milestones:

- `until`, loop `else`, labeled/depth-based `break`/`continue`, function
  `return`, map iteration, ranges, index/field/env assignment, collection
  compound assignment, regex/glob/destructuring/fallthrough case arms, pipelines,
  string methods, and comment-preserving formatter trivia remain out of scope;
- string binary `+` is rejected for now because the current HIR does not retain
  enough type information for the Bash emitter to choose arithmetic addition vs
  string concatenation without risking VM/Bash drift. Interpolation remains the
  supported string-composition path.
- unknown-kind `case` selectors, such as unconstrained function parameters, are
  rejected in this milestone rather than becoming VM-only behavior. This can be
  relaxed after richer value-kind metadata is propagated through function calls
  and collection iteration.

Technical debt carried into later milestones:

- string binary `+` needs richer lowered type information before it can be
  supported without Bash parity risk;
- unknown-kind `case` selectors can be relaxed once function calls and future
  collection iteration carry reliable scalar kind metadata to Bash emission;
- comment-preserving formatting still needs a retained trivia model.
