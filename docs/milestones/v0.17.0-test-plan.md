# v0.17.0 Test Plan — Control Flow Completion

## Status

Planned. This test plan must be implemented after the `v0.17.0` spec is coded.

## Purpose

Verify that `v0.17.0` adds useful imperative control flow without breaking the
VM/Bash parity contract or expanding beyond the scoped feature set.

The core signal:

```txt
while, break, continue, case, and scoped scalar reassignment parse and lower
VM execution and emitted Bash behavior match
loop control targets the nearest lexical loop
case matching is literal and first-match only
unsupported adjacent syntax stays rejected
```

## Scope under test

Covered:

- scalar reassignment with `=`, `+=`, and `-=` as implemented by the spec;
- `while condition { ... }` loops;
- `break` and `continue` in `for` and `while` loops;
- nested loop behavior and nearest-loop targeting;
- `case` over string, integer, and boolean selectors with literal alternatives
  and `_` default;
- parser, AST, HIR, bytecode, VM, Bash, formatter, checker, imports, functions,
  script args, and test-runner behavior for the new constructs;
- VM/Bash parity for deterministic control-flow fixtures;
- docs/status/example consistency;
- regression checks for unsupported future syntax.

Not covered as supported behavior:

- `until`;
- labeled/depth-based loop control;
- function `return` values;
- map iteration;
- range loops;
- index/field/env assignment;
- collection compound assignment;
- regex/glob/destructuring case patterns;
- fallthrough case arms;
- pipelines;
- full type checking or advanced warning data-flow;
- formatter comment preservation.

Unsupported adjacent syntax should still receive negative coverage so the new
parser branches do not accidentally accept future language surface.

## Required test target

Add a dedicated suite:

```txt
tests/v0_17/run.sh
```

Update Makefile wiring so these work:

```sh
make test-v0-17
make test
make asan
make ubsan
```

The suite should primarily test public CLI behavior. Static checks are allowed
for Makefile/docs/source-boundary contracts that are not directly observable
through CLI output.

## Test conventions

- Create temporary `.ds` files, generated Bash files, fake commands, side-effect
  files, stdout/stderr captures, and formatted files under the suite temp
  directory.
- Compare stdout, stderr, and exit status separately.
- Normalize temp paths in diagnostics before comparing.
- Run `bash -n` before executing emitted Bash.
- Execute emitted Bash without `ds` in `PATH` unless the fixture intentionally
  tests a user command named `ds`.
- Run VM and Bash parity fixtures in isolated temp directories when file side
  effects are involved.
- Avoid wall-clock timing assertions.
- Avoid infinite-loop tests. Use bounded loops and explicit counters.
- Prefer stable diagnostic fragments and caret/source-location shape over exact
  full diagnostic prose when the wording is not central to the feature.

## Parser, token, AST, HIR, and bytecode tests

### Token coverage

Fixtures:

```ds
let i = 0
while i < 2 {
  i += 1
  if i == 1 { continue }
  break
}

case i {
  1 | 2 { echo "small" }
  _ { echo "other" }
}
```

Assertions:

- `tokens` emits stable token names for `while`, `break`, `continue`, `case`,
  compound assignment tokens, and case alternative separators;
- `|` inside `case` alternatives does not imply pipeline support elsewhere;
- `case` no longer appears only as an ordinary identifier in token output.

### AST coverage

Assertions:

- `ast` prints deterministic `AssignStmt`/equivalent nodes for `=`, `+=`, `-=`;
- `ast` prints `WhileStmt` with condition and body;
- `ast` prints `BreakStmt` and `ContinueStmt`;
- `ast` prints `CaseStmt`, selector, arms, alternatives, and default;
- output contains no pointer addresses or nondeterministic temp IDs.

### HIR coverage

Assertions:

- `hir` contains lowered assignment, while, break, continue, and case forms;
- loop-control validation has already rejected illegal placements before HIR
  output succeeds;
- imported control-flow statements appear in composed order;
- test blocks are visible in test-aware paths but ignored by normal run/emission
  according to existing rules.

### Bytecode coverage

Assertions:

- `bytecode` for `while` shows conditional and back-edge jumps or equivalent;
- `break` jumps to loop end;
- `continue` jumps to the nearest loop continuation point;
- nested loops patch different targets correctly;
- `case` lowers to deterministic comparisons/jumps or equivalent dispatch;
- assignment/update bytecode mutates existing bindings, not new shadow bindings.

## Reassignment tests

### Plain scalar reassignment

Fixture:

```ds
let name = "api"
echo "before={name}"
name = "web"
echo "after={name}"
```

Assertions:

- `check`, `run`, direct execution, `emit bash`, and emitted Bash succeed;
- VM/Bash stdout is `before=api` then `after=web`;
- reassignment does not create a new inner variable that hides the old one.

### Integer compound updates

Fixture:

```ds
let i = 3
i += 2
echo "plus={i}"
i -= 4
echo "minus={i}"
```

Assertions:

- VM/Bash stdout matches `plus=5` and `minus=1`;
- negative values and zero are handled consistently;
- updates inside functions and blocks update the intended visible binding.

### Scope and shadowing edge cases

Fixtures/assertions:

- assigning to an outer variable from inside a block updates the outer variable;
- `let x = ...` inside a block still creates a block-local binding according to
  existing rules;
- assigning to a variable after a block observes the correct final value;
- assigning to an unknown variable fails with a clear diagnostic;
- assigning to a loop variable is either supported consistently or rejected with
  a documented diagnostic; lock the implemented choice;
- assigning to function parameters is either supported consistently or rejected
  with a documented diagnostic; lock the implemented choice;
- assigning to script args/options/flags is either supported consistently or
  rejected with a documented diagnostic; lock the implemented choice.

### Unsupported assignment targets

Negative fixtures:

```ds
xs[0] = "x"
ports.api = 3000
env.PATH = "bin"
unknown = 1
count *= 2
count /= 2
count %= 2
```

Assertions:

- `check`, `run`, and `emit bash` reject before partial execution/emission;
- diagnostics mention unsupported assignment target/operator or unknown variable;
- formatter/checker do not make the syntax appear supported.

## While-loop tests

### Basic bounded loop

Fixture:

```ds
let i = 0
while i < 3 {
  echo "i={i}"
  i += 1
}
echo "done={i}"
```

Assertions:

- VM/direct/Bash stdout matches exactly;
- final `i` value is `3`;
- generated Bash passes `bash -n` and has no `ds` dependency.

### Condition semantics

Fixtures/assertions:

- boolean variable condition toggled by reassignment;
- string/integer truthiness matches existing `if` behavior;
- unary `!` condition works (`while !done { ... }`);
- comparison operators work in loop conditions;
- captured command result fields can control a bounded loop where the command
  result changes through reassignment or controlled fixture state.

### Body semantics

Fixtures/assertions:

- command statements inside `while` remain fail-fast;
- captured `run` commands inside `while` do not auto-fail on non-zero status;
- redirection inside `while` writes/appends expected files in VM and Bash;
- stdlib helpers inside `while` behave consistently;
- `let` declarations inside body do not leak;
- functions called inside loops preserve function-local scope;
- imported functions containing `while` work in VM and Bash.

### Nested while/for loops

Fixtures/assertions:

- while inside while prints expected nested sequence;
- for inside while prints expected nested sequence;
- while inside for prints expected nested sequence;
- loop variables and counters do not collide;
- emitted Bash uses safe temp/user variable names.

### Malformed while syntax

Negative fixtures:

```ds
while { echo "bad" }
while i < 3 echo "bad"
while i < 3
while i < 3 {
```

Assertions:

- diagnostics include filename, line, column, source line, and caret;
- no backend executes partial code;
- `emit bash` fails without leaving a successful output script.

## Break and continue tests

### Basic for-loop control

Fixture:

```ds
let items = ["a", "skip", "b", "stop", "c"]
for item in items {
  if item == "skip" { continue }
  if item == "stop" { break }
  echo $item
}
```

Assertions:

- VM/Bash stdout is `a` then `b`;
- `continue` skips only the current iteration;
- `break` stops only the nearest loop.

### Basic while-loop control

Fixture:

```ds
let i = 0
while i < 5 {
  i += 1
  if i == 2 { continue }
  if i == 4 { break }
  echo "i={i}"
}
echo "done={i}"
```

Assertions:

- VM/Bash stdout is `i=1`, `i=3`, `done=4`;
- continue target runs the next condition check, not the statement after loop;
- break target skips the rest of the loop.

### Nested loop targeting

Fixtures/assertions:

- `break` inside inner loop leaves only the inner loop;
- outer loop continues after inner `break`;
- `continue` inside inner loop continues only the inner loop;
- `continue` inside outer loop skips the inner loop when placed before it;
- behavior matches VM/Bash exactly.

### Loop control in nested blocks and case arms

Fixtures/assertions:

- `break` and `continue` inside `if` inside a loop are valid;
- `break` and `continue` inside a bare block inside a loop are valid;
- `break` inside a `case` arm nested in a loop breaks the loop;
- `continue` inside a `case` arm nested in a loop continues the loop;
- `break`/`continue` inside a case not nested in a loop are rejected.

### Invalid loop control

Negative fixtures:

```ds
break
continue
fn bad() { break }
fn bad() { continue }
test "bad" { break }
test "bad" { continue }
for item in items { break 1 }
for item in items { continue label }
```

Assertions:

- invalid loop control fails at check/lower time before execution;
- diagnostics say the statement must be inside a loop or takes no argument;
- function-boundary cases do not inherit caller loop depth.

## Case tests

### String selector with alternatives and default

Fixture:

```ds
let lang = "sh"
case lang {
  "bash" | "sh" { echo "shell" }
  "python"      { echo "python" }
  _             { echo "other" }
}
```

Assertions:

- VM/Bash stdout is `shell`;
- first matching arm wins;
- default does not run when a literal arm matches;
- literal pattern alternatives are ORed only within the arm.

### Integer and boolean selectors

Fixtures/assertions:

- integer selector matches integer literal pattern;
- integer selector does not accidentally match unrelated string literal unless
  the spec explicitly chooses string-coercion semantics; lock the chosen behavior;
- boolean selector matches `true`/`false` patterns;
- no-match without default executes no arm and exits successfully.

### Exact literal semantics

Fixtures/assertions:

- pattern `"*.txt"` matches only literal `*.txt`, not `readme.txt`;
- spaces, quotes, backslashes, and interpolation in selector values are quoted
  safely in emitted Bash;
- duplicate patterns are rejected when statically visible;
- `_` default may appear once and must be final;
- empty `case` body is rejected;
- empty arm body `{}` is allowed only if empty blocks are already allowed; lock
  the implemented choice.

### Case with commands, functions, stdlib, loops

Fixtures/assertions:

- arm body can contain command statements;
- arm body can call functions;
- arm body can assign variables visible after the `case` according to existing
  block/scoping rules; lock the intended behavior;
- `case` inside `while` works;
- `while` inside a case arm works;
- imported function with `case` works in VM and Bash;
- `case` inside `test` works under `ds test`.

### Malformed and unsupported case syntax

Negative fixtures:

```ds
case $lang { _ { echo "bad" } }
case { _ { echo "bad" } }
case lang { "bash" }
case lang { _ { echo "default" } "bash" { echo "late" } }
case lang { _ { echo "one" } _ { echo "two" } }
case lang { "a" | { echo "bad" } }
case lang { /a/ { echo "regex deferred" } }
case lang { *.txt { echo "glob deferred" } }
```

Assertions:

- diagnostics clearly identify selector, arm, default, duplicate, or unsupported
  pattern problems;
- `$` selector diagnostic recommends expression-style `case lang` if practical;
- unsupported regex/glob patterns do not fall through to Bash semantics.

## Formatter and checker tests

### Formatter support for new syntax

For fixtures containing reassignment, while, break, continue, and case:

1. Run `./ds fmt input.ds > once.ds`.
2. Run `./ds fmt once.ds > twice.ds`.
3. Assert `cmp once.ds twice.ds` succeeds.
4. Run `./ds check once.ds`.
5. Compare VM/Bash behavior before and after formatting for deterministic
   fixtures.

Style assertions:

- `while condition {` uses same-line opening brace;
- case arm bodies use braces and two-space indentation;
- `|` alternatives have stable spacing;
- `break` and `continue` are one-line statements;
- assignment operators have spaces around them;
- formatter still rejects comment-bearing files with the existing v0.16
  diagnostic rather than dropping comments.

### Checker non-execution

Fixture contains commands that would create side-effect files inside while/case
bodies.

Assertions:

- `ds check`, `ds check --warnings-as-errors`, `ds check --no-warnings`,
  `ds fmt`, `ds fmt --check`, and `ds fmt --write` do not execute those commands;
- warning flags preserve their existing behavior;
- new loop/case scopes do not produce obvious false unused/shadowing warnings.
