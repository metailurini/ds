# v0.19.0 Test Plan — String Library and Formatted Output

## Status

Implemented in `tests/v0_19/run.sh` and wired into `make test-v0-19`,
aggregate `make test`, `make asan`, and `make ubsan`.

Amendment from implementation review: because function parameters remain
untyped in this wave, direct string methods or formatted interpolation on an
unknown-kind parameter are rejected by `ds check` to preserve VM/Bash parity.
The suite tests imported top-level string values and script string args as the
supported integration paths, and it tests untyped function parameter string
methods as an intentional diagnostic until typed parameters or hidden type tags
are added.

## Purpose

Verify that `v0.19.0` adds practical string methods, interpolation formatting,
and triple-quoted strings without weakening VM/Bash parity, checker safety,
formatter determinism, or the standalone Bash requirement.

The core signal:

```txt
string methods parse/lower/run/emit consistently
format specifiers are small, validated, and portable
triple-quoted strings preserve content
split results compose with existing arrays and loops
unsupported string/format forms fail clearly before partial execution/emission
```

## Scope under test

Covered:

- `trim`, `upper`, `lower`, `replace`, `contains`, `split`, `starts_with`, and
  `ends_with`;
- method calls on literals, variables, command-result fields, parenthesized
  expressions, and valid method chains;
- method arity/type diagnostics;
- split edge cases and array-loop integration;
- interpolation named transforms and numeric/string width specifiers;
- triple-quoted strings with newlines and interpolation;
- VM behavior and emitted Bash behavior for all supported forms;
- checker and formatter behavior;
- imports, functions, script args, control flow, pipelines, and tests;
- generated Bash helper emission and standalone execution.

Not covered as supported behavior:

- regex methods;
- raw strings;
- heredocs/here-strings;
- locale-aware or Unicode case conversion;
- decimal numeric literals or floating-point arithmetic;
- full printf/Python/Rust format grammar;
- arbitrary expression interpolation beyond the scoped existing interpolation
  model;
- methods on arrays/maps/booleans/null/integers unless explicitly allowed by
  the implementation spec;
- formatter comment preservation.

## Test entrypoint

Add a new executable suite:

```sh
tests/v0_19/run.sh
```

and wire it into the Makefile:

```sh
make test-v0-19
make test
make asan
make ubsan
```

The suite should primarily test public CLI behavior. Static checks are allowed
for Makefile/docs/source-boundary contracts that are not directly observable
through CLI output.

## Test conventions

- Create every `.ds` fixture, input file, emitted Bash file, fake command,
  stdout/stderr capture, and side-effect file under the suite temp directory.
- Use fake commands for command-output fixtures so host command differences do
  not change results.
- Compare stdout, stderr, and exit status separately.
- Normalize temp paths in diagnostics before comparing.
- Run `bash -n` before executing emitted Bash.
- Execute emitted Bash without `ds` in `PATH` unless a fixture intentionally
  tests a user command named `ds`.
- For VM/Bash parity, run VM and emitted Bash from isolated temp directories so
  side effects cannot leak between backends.
- Avoid locale-sensitive assertions. Force `LC_ALL=C` for emitted Bash parity
  fixtures if implementation depends on ASCII transformations.
- Prefer stable diagnostic fragments over exact full diagnostic prose unless the
  exact wording is central to the feature.
- Do not use wall-clock timing or large input data.

## Lexer/parser/token tests

### Token coverage

Fixtures:

```ds
let s = "  Hello  ".trim().lower()
echo "{s:upper}"
let body = """
line one
line two
"""
```

Assertions:

- `tokens` identifies string literals and triple-quoted strings without losing
  line/column information;
- `.` still tokenizes as field/method access and does not conflict with decimal
  literal syntax unless decimal literals are deliberately implemented;
- `:` inside interpolation does not confuse normal type annotation parsing;
- unterminated triple-quoted strings produce a lexer/parser diagnostic pointing
  at the opening delimiter;
- `"""` inside normal strings remains normal string content only if escaped in
  the way documented by the implementation.

### Parser acceptance

Fixtures that must parse/check:

```ds
let a = " x ".trim()
let b = a.upper()
let c = a.lower().replace("x", "y")
let ok = c.contains("y")
let parts = "a,b,c".split(",")
let starts = c.starts_with("y")
let ends = c.ends_with("y")
echo "{c:upper}"
echo "{c:<8}"
echo "{1:05d}" # only if literal interpolation is supported; otherwise use variable
```

If interpolation remains variable/field-only, use:

```ds
let n = 1
echo "{n:05d}"
```

Assertions:

- method call AST/HIR debug output distinguishes method calls from field access;
- method chains preserve call order;
- triple-quoted string spans include all lines;
- interpolation specifier parsing preserves the exact specifier for lowering.

### Parser rejection

Fixtures that must fail before execution/emission:

```ds
let x = "a".
let x = "a".trim(

let x = "a".unknown()
let x = "a".split("")
let x = "a".replace("", "b")
echo "{name:}"
echo "{name:?}"

let body = """

```

Assertions:

- diagnostics are non-zero and mention the relevant construct;
- unsupported syntax is not treated as a command statement;
- `emit bash` fails for invalid fixtures and does not create a partial output
  file when the CLI policy says invalid emission should fail atomically.

## String method behavior tests

### `trim`

Fixtures:

```ds
let a = "  hello  ".trim()
let b = "\t hello \n".trim()
let c = "".trim()
let d = "   ".trim()
echo "[{a}]"
echo "[{b}]"
echo "[{c}]"
echo "[{d}]"
```

Assertions:

- leading and trailing ASCII spaces, tabs, CR, and LF are removed;
- internal whitespace is preserved;
- empty and all-whitespace strings become empty;
- VM and Bash outputs match exactly.

### `upper` / `lower`

Fixtures:

```ds
let a = "abc XYZ 123".upper()
let b = "abc XYZ 123".lower()
echo "{a}"
echo "{b}"
```

Assertions:

- ASCII letters transform correctly;
- non-letters are preserved;
- behavior is stable under `LC_ALL=C`;
- non-ASCII bytes are preserved byte-for-byte or documented/rejected
  consistently.

### `replace`

Fixtures:

```ds
let a = "hello hello".replace("hello", "hi")
let b = "aaaa".replace("aa", "b")
let c = "abc".replace("z", "x")
let d = "a-b-c".replace("-", "")
echo "{a}"
echo "{b}"
echo "{c}"
echo "{d}"
```

Assertions:

- replacement is literal and global;
- no-match replacement returns the original string;
- empty replacement target string deletes matches;
- empty `from` string is rejected;
- overlapping behavior is documented and VM/Bash match. Preferred behavior:
  left-to-right non-overlapping replacement, so `"aaaa".replace("aa", "b")`
  returns `"bb"`.

### Predicate methods

Fixtures:

```ds
let s = "release/api"
if s.contains("api") { echo "contains" }
if s.starts_with("release/") { echo "starts" }
if s.ends_with("api") { echo "ends" }
if !s.contains("web") { echo "missing" }
```

Assertions:

- predicates return booleans usable in `if` and `assert`;
- empty substring/prefix/suffix behavior is documented and tested. Preferred
  behavior: empty needle is true for all three predicate methods;
- VM and Bash match.

### `split`

Fixtures:

```ds
let a = "a,b".split(",")
let b = "a,".split(",")
let c = ",a".split(",")
let d = "a,,b".split(",")
let e = "abc".split(",")
let f = "".split(",")

for x in d {
  echo "[{x}]"
}

echo "a0={a[0]}"
echo "a1={a[1]}"
echo "b1={b[1]}"
echo "c0={c[0]}"
echo "e0={e[0]}"
echo "f0={f[0]}"
```

Assertions:

- result shape matches the spec edge-case table;
- split arrays work with indexing and `for` loops;
- empty separator is rejected;
- multi-character separators work literally;
- separators at boundaries preserve empty fields;
- VM and Bash match exactly.

### Method chains and receivers

Fixtures:

```ds
let raw = "  Hello World  "
let a = raw.trim().lower().replace(" ", "-")
let b = ("xx" + "yy").replace("x", "z")
let r = run printf " branch\n"
let branch = r.stdout.trim()
echo "{a}"
echo "{b}"
echo "{branch}"
```

Assertions:

- chains execute left-to-right;
- command-result fields may be method receivers;
- unsupported receiver types fail clearly;
- if `+` string concatenation is supported, parenthesized string expressions work;
  otherwise amend fixture to use supported receivers only.

## Interpolation formatting tests

### Named transforms

Fixtures:

```ds
let name = "  api  "
echo "{name:upper}"
echo "{name:lower}"
echo "{name:trim}"
```

Assertions:

- transforms match method behavior;
- transforms do not mutate the variable;
- VM and Bash match.

### Width and alignment

Fixtures:

```ds
let label = "api"
echo "[{label:<6}]"
echo "[{label:>6}]"
echo "[{label:^7}]"
echo "[{label:<2}]"
```

Assertions:

- left/right/center alignment work;
- width smaller than value length does not truncate;
- odd center padding chooses the documented side for the extra space;
- VM and Bash match.

### Integer padding

Fixtures:

```ds
let a = 7
let b = -7
let c = 12345
echo "{a:03d}"
echo "{b:04d}"
echo "{c:03d}"
echo "{a:5d}"
```

Assertions:

- zero and space padding work;
- negative signs are handled consistently;
- width smaller than value length does not truncate;
- non-integer values with `d` fail clearly;
- VM and Bash match.

### Fixed decimal formatting

Fixtures:

```ds
let n = 7
echo "{n:.2f}"
echo "{n:6.2f}"
```

Assertions:

- integer-to-fixed rendering follows the spec (`7.00` for `.2f`);
- width applies to the full rendered fixed value;
- precision `0` behavior is documented and tested if supported;
- decimal literals are rejected unless deliberately implemented;
- VM and Bash match.

### Bad specifiers

Fixtures that must fail:

```ds
echo "{name:unknown}"
echo "{name:05d}"
echo "{n:upper}"
echo "{name:99999}"
echo "{name:<0}"
echo "{name:.9999f}"
echo "{name:%s}"
```

Assertions:

- diagnostics mention unsupported specifier or incompatible type;
- invalid format strings are rejected by `check`, `run`, and `emit bash`;
- emitted Bash is not written for invalid fixtures.

## VM/Bash parity tests

Create a parity helper that:

1. writes a fixture;
2. runs `./ds <fixture>` in VM mode;
3. emits Bash to a file;
4. verifies `bash -n`;
5. runs emitted Bash with `ds` removed from `PATH`;
6. compares status, stdout, stderr, and side effects.

Run this helper for fixtures covering:

- each string method individually;
- method chains;
- predicate methods in `if`, `while`, and `case` conditions where applicable;
- split plus for-loop;
- interpolation transforms;
- width/alignment/integer/fixed formatting;
- triple-quoted strings;
- command-result stdout trimming;
- imported string helpers;
- string features inside functions;
- string features inside `script` argument handling;
- string features after a captured pipeline from `v0.18.0`;
- generated Bash with multiple helper dependencies.

Assertions:

- emitted Bash contains no invocation of `ds`;
- helper functions appear once when used from multiple imports/functions;
- stdout/stderr/status match exactly;
- side-effect files match exactly for fixtures that write files.
