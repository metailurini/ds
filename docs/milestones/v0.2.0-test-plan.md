# v0.2.0 Test Plan — Basic Bash Emitter

## Purpose

This test plan verifies the first Bash emission backend.

`v0.2.0` should convert valid `v0.1.0` scripts into standalone Bash and reject unsupported or invalid input clearly.

There is still no bytecode VM in this version.

## Test categories

`v0.2.0` should include tests for:

- Bash emitter output;
- generated Bash syntax validity;
- generated Bash behavior;
- safety and quoting;
- diagnostics;
- CLI behavior;
- edge cases.

`docs/language.ds` is not used as a full Bash emission fixture in this version because it contains future syntax. Use focused fixtures for the `v0.1.0` supported subset instead.

Golden tests are strongly recommended.

## Emitter golden tests

Each fixture should include:

```txt
input.ds
expected.sh
```

Recommended fixtures:

- empty file;
- comments-only file;
- simple string variable;
- integer variable;
- boolean variable;
- simple command;
- command with string argument;
- string interpolation;
- `if` without `else`;
- `if` with `else`;
- nested `if`;
- mixed variables, commands, and conditionals.

Golden output should be stable. Avoid including timestamps or absolute paths in generated output.

## Header tests

Generated Bash should:

- start with:

```bash
#!/usr/bin/env bash
```

- include:

```bash
set -euo pipefail
```

- include a blank line after the header if that is the chosen style.

## Variable emission tests

### String variables

Input:

```ds
let name = "Danh"
```

Expected output shape:

```bash
__ds_name="Danh"
```

Test cases:

- simple string;
- empty string;
- string with spaces;
- string with quotes;
- string with backslash;
- string with dollar sign;
- string with command-looking content such as `$(echo bad)` should not execute during emission or runtime assignment.

### Integer variables

Input:

```ds
let count = 3
```

Expected output shape:

```bash
__ds_count=3
```

Test cases:

- zero;
- positive integer;
- large integer.

Negative integers may be deferred if unary numeric parsing is not complete.

### Boolean variables

Input:

```ds
let ok = true
let bad = false
```

Expected output shape:

```bash
__ds_ok=true
__ds_bad=false
```

Boolean representation should be consistent.

## String interpolation tests

Input:

```ds
let name = "Danh"
echo "Hello {name}"
```

Expected output shape:

```bash
echo "Hello ${__ds_name}"
```

Test cases:

- interpolation at beginning of string;
- interpolation in middle of string;
- interpolation at end of string;
- multiple interpolations;
- adjacent interpolation and text;
- unknown interpolation name should fail clearly;
- literal braces behavior should be defined or rejected clearly.

Deferred cases:

- expression interpolation;
- function calls inside interpolation;
- format specifiers.

## If emission tests

### Basic `if`

Input:

```ds
if ok {
  echo "ok"
}
```

Generated Bash should contain a valid Bash `if` statement.

### `if` / `else`

Input:

```ds
if ok {
  echo "ok"
} else {
  echo "no"
}
```

Generated Bash should contain:

```bash
if ...; then
  ...
else
  ...
fi
```

### Comparison operators

Test emission for:

- `==`
- `!=`
- `>`
- `>=`
- `<`
- `<=`

If numeric comparisons and string comparisons have different emission rules, test both or document the limitation.

### Nested conditionals

Input:

```ds
if ok {
  if ready {
    echo "ready"
  }
}
```

Generated Bash should be valid and properly nested.

## Command statement emission tests

Test that command statements emit in order.

Input:

```ds
echo "one"
echo "two"
```

Expected runtime output:

```txt
one
two
```

Test cases:

- simple command;
- command with multiple words;
- command with string argument;
- command inside `if`;
- command after `if` block.

## Generated Bash validity tests

For each generated fixture:

```sh
bash -n generated.sh
```

Expected:

- exit `0` for valid generated Bash;
- no syntax errors.

## Generated Bash behavior tests

Run generated Bash for simple scripts and verify output.

Recommended behavior tests:

### Interpolation

Input:

```ds
let name = "Danh"
echo "Hello {name}"
```

Expected output:

```txt
Hello Danh
```

### True branch

Input:

```ds
let ok = true
if ok {
  echo "yes"
} else {
  echo "no"
}
```

Expected output:

```txt
yes
```

### False branch

Input:

```ds
let ok = false
if ok {
  echo "yes"
} else {
  echo "no"
}
```

Expected output:

```txt
no
```

### Command failure

Input:

```ds
false
echo "after"
```

Expected:

- generated Bash exits non-zero;
- `after` is not printed because of strict mode.

## Safety and quoting tests

Generated Bash should not accidentally change meaning because of unsafe quoting.

Test cases:

- string contains spaces;
- string contains double quote;
- string contains single quote;
- string contains `$HOME`;
- string contains `$(echo bad)`;
- string contains backticks;
- string contains backslash;
- string contains newline if multi-line strings are supported;
- variable name cannot collide with generated helper names.

Expected behavior:

- string content is preserved;
- command substitutions inside string literals are not executed unexpectedly;
- generated Bash remains valid.

## Diagnostics tests

- Invalid source file fails before emission.
- Missing output path fails clearly.
- Unsupported syntax fails clearly.
- Unknown interpolation variable fails clearly.
- Unsafe or invalid identifier mapping fails clearly if applicable.
- Output file write failure reports useful error.

Diagnostics should include file/line/column when tied to source syntax.

## CLI tests

### Successful emission

```sh
ds emit bash examples/basic.ds -o /tmp/basic.sh
```

Expected:

- exits `0`;
- output file exists;
- output file is not empty;
- `bash -n /tmp/basic.sh` succeeds.

### Missing input

```sh
ds emit bash
```

Expected:

- exits non-zero;
- prints usage or clear error.

### Missing output path

```sh
ds emit bash examples/basic.ds
```

Expected:

- exits non-zero;
- prints clear error explaining `-o` is required, unless stdout output is intentionally supported.

### Missing input file

```sh
ds emit bash missing.ds -o /tmp/out.sh
```

Expected:

- exits non-zero;
- reports missing file.

## Edge cases

- Empty source emits valid minimal Bash.
- Comments-only source emits valid minimal Bash.
- File without trailing newline emits valid Bash.
- Deeply nested `if` emits valid Bash.
- Long string emits valid Bash.
- Many variables emit valid Bash.
- Command after block emits in correct order.
- Interpolation next to punctuation preserves text.

## Syntax catalog checks

- Confirms `docs/language.ds` still exists after Bash emitter work.
- Confirms any syntax changed due to Bash emission constraints is updated in `docs/language.ds`.
- Confirms future syntax in `docs/language.ds` is not accidentally treated as supported by the v0.2.0 Bash emitter.
- Confirms Bash emission fixtures are focused on the supported subset, not the full syntax catalog.

## Manual smoke tests

Run:

```sh
ds emit bash examples/basic.ds -o /tmp/basic.sh
bash -n /tmp/basic.sh
bash /tmp/basic.sh
```

For conditionals:

```sh
ds emit bash examples/if.ds -o /tmp/if.sh
bash -n /tmp/if.sh
bash /tmp/if.sh
```

For failure behavior:

```sh
ds emit bash examples/fail.ds -o /tmp/fail.sh
bash /tmp/fail.sh
```

Expected:

- success examples exit `0`;
- failure example exits non-zero.
