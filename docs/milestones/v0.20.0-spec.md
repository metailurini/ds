# v0.20.0 Spec — Cleanup: Wave 2 Stabilization

## Status

Implementation complete for the scoped code/docs pass. The dedicated v0.20 test
suite is intentionally pending because this implementation pass was requested
without adding tests yet.

`v0.20.0` is the cleanup/debt-repayment milestone that closes the second feature
wave. It must not add new production syntax. Its job is to stabilize the
features added in `v0.17.0`, `v0.18.0`, and `v0.19.0` before `v0.21.0` adds
function return values and a larger arithmetic/value-result model.

## Goal

Make the implemented Wave 2 language surface boring, consistent, documented, and
safe across both execution backends:

```txt
v0.17.0 control flow: reassignment, while, break, continue, case
v0.18.0 linear pipelines: plain command pipelines and captured run pipelines
v0.19.0 strings: methods, formatted interpolation, triple-quoted literals
```

The cleanup should verify that these features compose with older language areas
rather than only passing their original isolated milestone suites.

The core product rules remain unchanged:

```txt
every supported production feature runs in the VM
every supported production feature emits standalone Bash
generated Bash is standalone and must not call ds
VM and emitted Bash behavior match for stdout, stderr, exit status, and side effects
unsupported or deferred forms fail clearly before partial execution/emission
cleanup work fixes inconsistency without expanding the language surface
```

## Motivation

Wave 2 added several cross-cutting features that stress the existing compiler and
backend boundaries:

1. **Control flow now changes execution shape.** `while`, `break`, `continue`,
   scalar reassignment, and `case` interact with block scopes, function bodies,
   tests, imported declarations, command failures, and array loops.
2. **Pipelines bridge shell-native syntax and typed command results.** Plain
   command pipelines are fail-fast while captured `run` pipelines produce a
   command-result object. This difference must remain documented, tested, and
   equivalent between VM and emitted Bash.
3. **Strings now have receiver-style calls and formatting.** String helpers,
   formatting specifiers, command-word interpolation, triple-quoted literals,
   arrays from `split`, and bool-returning predicates all need consistent kind
   tracking and helper dependency emission.
4. **Generated Bash helper selection is more important.** Wave 2 relies on Bash
   helpers for loops, command capture, pipelines, string operations, formatting,
   and tests. Helpers must remain deterministic, deduplicated, guarded when they
   require Bash 4+ features, and absent when unsupported by the source program.
5. **Docs and examples are now the contract.** Users should be able to read the
   status docs, language catalog, examples, milestone specs, and generated Bash
   notes without finding contradictions about what is supported today.
6. **The next milestone needs a clean value model.** `v0.21.0` will introduce
   `return expr`, captured function results, and arithmetic operators. Any Wave 2
   ambiguity about value kinds, unknown function parameters, helper return kinds,
   or VM/Bash coercion should be resolved or explicitly deferred first.

## Non-goals

This version does not include:

- new production syntax;
- `return`, value-returning functions, function-call expressions, or recursion
  changes from `v0.21.0`;
- arithmetic operators `*`, `/`, `%`, `**` or compound `*=`, `/=`, `%=`;
- typed function parameters or runtime type-tag propagation for untyped
  parameters;
- `until`, loop `else`, labeled/depth-based `break`/`continue`, or loop labels;
- regex/glob/destructuring/fallthrough `case` arms;
- logical shell operators such as `&&` / `||` command chaining beyond expression
  operators that already exist;
- background jobs, coprocesses, process substitution, command substitution, or
  advanced pipeline forms;
- heredocs, here-strings, raw strings, or a redesigned escaping model;
- string concatenation with `+`, regex string methods, locale-aware case
  conversion, or Unicode grapheme semantics;
- map iteration, ranges, slices, index assignment, nested collections, or direct
  collection passing to functions/commands;
- new standard-library helper namespaces;
- direct `env.NAME` assignment/access;
- formatter comment/trivia preservation unless fixing a narrow regression in the
  existing explicit rejection path;
- warning suppression comments or configurable lint rules;
- editor/LSP work;
- backend expansion to zsh/fish/POSIX sh;
- native compilation.

Small behavior changes are allowed only when they fix an existing bug, remove a
VM/Bash parity gap, improve a misleading diagnostic, make helper emission safer,
or update docs/examples to match implemented behavior. Every such change must be
recorded in the completion review.

## Required cleanup work

### 1. Wave 2 behavior audit

Audit the supported Wave 2 surface as one language:

- `while` conditions and bodies;
- scalar reassignment inside blocks, loops, functions, tests, and imported code;
- lexical `break` / `continue` in nested `for` and `while` loops;
- `case` selector and arm expression evaluation for strings, integers, booleans,
  string predicates, and formatted/string-derived values;
- plain command pipelines;
- captured `run` pipelines and command-result fields;
- readable redirections attached to plain pipelines;
- string methods and method chains;
- formatted interpolation in normal strings, triple-quoted strings, command
  words, function bodies, imports, tests, script args, and loop/case contexts;
- `split` results used by array indexing and `for` loops;
- triple-quoted string preservation in VM output, emitted Bash, formatter, and
  diagnostics.

For each area, verify:

- VM behavior;
- emitted Bash behavior;
- `ds check` behavior;
- `ds fmt` behavior where formatting is supported;
- clear rejection for unsupported/deferred forms;
- useful source spans in diagnostics.

### 2. VM/Bash parity hardening

Add or improve integration tests so scripts using multiple Wave 2 features are
run in both VM mode and emitted Bash mode with the same:

- stdout;
- stderr when deterministic;
- exit status;
- generated Bash syntax validity through `bash -n`;
- fail-fast behavior for plain commands;
- non-fail-fast capture behavior for `run` command results.

Parity tests should avoid relying on machine-specific command output. Prefer
small shell commands such as `printf`, `cat`, `grep`, `sort`, `wc`, and temporary
files created inside the fixture when those commands are available in the
existing test environment.

### 3. Helper dependency and generated Bash audit

Review generated Bash for Wave 2 scripts.

Requirements:

- generated Bash remains standalone and never invokes `ds`;
- helper functions use the reserved `__ds_` prefix;
- helper bodies are emitted only when needed at the dependency-class level the
  implementation currently supports;
- helper output is deterministic across repeated emissions;
- helper emission is deduplicated across imports, functions, tests, command
  words, string interpolation, and pipelines;
- Bash 4+ guards are emitted whenever emitted syntax or helpers require Bash 4+
  behavior;
- scripts that do not require Wave 2 helpers do not gain unrelated helper bodies;
- `bash -n` succeeds for generated scripts that combine loops, pipelines, case,
  string helpers, and triple-quoted literals;
- unsupported source features fail during check/lowering/emission rather than
  producing partially-invalid Bash.

It is acceptable for `v0.20.0` to keep coarse helper bundles if the bundle is
already documented and deterministic. If the implementation does not move to
per-helper emission, record that as technical debt in the completion review.

### 4. Diagnostics and checker cleanup

Review error messages introduced or stressed by Wave 2.

Diagnostics should be clear for:

- `break` / `continue` outside loops;
- invalid reassignment targets;
- reassignment kind mismatches;
- invalid `case` arm kinds;
- missing or duplicate `case` defaults if those are rejected by current rules;
- unsupported pipeline forms;
- invalid redirection placement around pipelines;
- command-result field misuse;
- string method receiver/type/arity failures;
- empty `split` separators and empty `replace` sources;
- unknown or incompatible interpolation format specifiers;
- malformed triple-quoted strings;
- formatter rejection of comments/trivia if that remains deferred;
- unknown-kind string operations on untyped function parameters.

Where possible, diagnostics should include the unsupported construct name and a
short hint toward the supported alternative.

### 5. Formatter and examples cleanup

Review `ds fmt` and examples for the implemented Wave 2 surface.

Requirements:

- examples for control flow, pipelines, and strings remain valid;
- examples pass `ds check`;
- examples run in VM mode when they are not intentionally invalid;
- examples emit standalone Bash and that Bash runs where deterministic;
- formatter output for Wave 2 syntax is deterministic and idempotent;
- formatter preserves triple-quoted literal contents exactly;
- formatter still rejects comments with a clear diagnostic unless comment
  preservation is explicitly implemented in this cleanup;
- docs do not imply formatter comments are supported if they remain deferred.

### 6. Runtime safety and sanitizer pass

Run sanitizer-backed checks focused on Wave 2 behavior.

At minimum, cover:

- nested loops with `break` / `continue`;
- `case` arms with strings, ints, bools, and string predicate calls;
- command pipelines that succeed, fail left, fail right, and produce large-ish
  captured output;
- string method chains that allocate intermediate values;
- `replace` with no match, repeated matches, boundary matches, and longer/shorter
  replacements;
- `split` with repeated separators and empty fields;
- formatted interpolation width/precision edges;
- triple-quoted strings with empty bodies, leading/trailing newlines, embedded
  braces, quotes, backslashes, and command-looking text;
- imports/functions/tests that combine the above.

Fix memory-safety issues that appear inside current scope. Broader ownership
redesigns may be deferred only if the failure is not exposed by supported user
behavior and the completion review records the reason.

### 7. Documentation reconciliation

Update docs only where they are wrong or incomplete after the cleanup.

Required review targets:

- `README.md` status and important-file list;
- `docs/status.md` support/deferred matrix;
- `docs/language.ds` status markers and comments around Wave 2 syntax;
- `docs/architecture.md` compiler/backend notes if boundaries change;
- `docs/runtime.md` value-kind/helper-boundary notes if they change;
- `docs/roadmap.md` only if `v0.20.0` scope changes deliberately;
- examples that double as public documentation.

Docs must continue to state that emitted Bash is standalone and does not call the
C runtime or `ds` binary.

## Implementation guidance

Prefer small, low-risk cleanup patches:

- add cross-feature tests before broad refactors;
- fix exposed parity bugs with localized changes;
- keep parser/lowerer/VM/Bash responsibilities split by the current file
  boundaries;
- avoid introducing new syntax while writing tests;
- preserve existing source spans and diagnostics where they are already clear;
- add helper metadata or dependency scanning cases rather than string-search hacks
  where a structured path is available;
- use `apply_patch` for edits;
- keep `src/runtime/hashmap.*` private behind `DsMap`.

If a cleanup requires a larger design than fits this milestone, document the
exact blocker and defer it to the next relevant feature or cleanup milestone
instead of landing risky partial behavior.

## Acceptance criteria

`v0.20.0` is complete when:

- a dedicated `tests/v0_20/run.sh` suite exists and is wired into the Makefile;
- all existing version suites through `v0.19.0` still pass;
- the new `v0.20.0` suite verifies cross-feature Wave 2 behavior, not just smoke
  tests;
- VM/Bash parity tests cover representative combinations of control flow,
  pipelines, strings, imports, functions, script args, and tests;
- generated Bash for Wave 2 combinations passes `bash -n` and runs standalone;
- sanitizer targets cover the new v0.20 fixtures or an equivalent subset;
- docs/examples are updated only where the review finds drift;
- the completion review below is filled in with actual work, deferred items, and
  known technical debt.

Suggested commands before completion:

```sh
make -j2 all
make test-v0-17
make test-v0-18
make test-v0-19
make test-v0-20
make check
make test
make test-asan
make test-ubsan
git diff --check
```

If full aggregate tests are too output-heavy for the local tool environment, run
the scoped Wave 2 suites, sanitizer v0.20 coverage, `make check`, and document
exactly which aggregate command could not finish and why.

## Completion review

- Implementation summary: tightened Wave 2 composition without adding new
  production syntax. The lowerer now tracks known array element kinds for array
  literals and for string-array helpers (`string.split`, `lines`, `glob`, and
  `glob!`). Indexed values from those arrays keep their known scalar kind when
  the lowerer validates later expressions, so supported string methods compose
  with indexed split/line/glob values instead of being rejected as unknown.
- VM/Bash parity notes: manual parity fixtures covering indexed `split` values,
  chained string methods, known indexed array `case` selectors, int/bool array
  loop variables inside `case`, `while`, plain pipeline redirection, and
  `lines()` matched between VM execution and emitted standalone Bash. Existing
  v0.17/v0.18/v0.19 suites also continued to pass.
- Helper/dependency notes: fixed Bash dependency scanning so call arguments are
  traversed for run, captured-pipeline, stdlib/string, collection-index, and map
  helper needs. This prevents generated Bash from omitting helpers such as
  `__ds_array_get` when an indexed collection access is nested inside a string
  helper receiver argument. Helper emission remains dependency-class based, not
  per-helper.
- Diagnostics/checker notes: unknown-kind receivers are still rejected for string
  methods. The cleanup only upgrades statically known array element kinds; it
  does not add runtime coercion or typed function parameters.
- Formatter/examples notes: no formatter behavior or public example script had
  to change. Manual formatter checks confirmed triple-quoted literal body
  preservation and idempotence for the reviewed fixture.
- Docs updates: updated `README.md`, `docs/status.md`, `docs/runtime.md`,
  `docs/architecture.md`, and `CHANGELOG.md` to describe the v0.20 cleanup and
  the known-array-element-kind lowering rule.
- Test plan execution summary: no dedicated `tests/v0_20/run.sh` was added in
  this pass by request. Verification used `make -j2 all`, `make check`,
  `make test-v0-17`, `make test-v0-18`, `make test-v0-19`, manual VM/Bash
  parity fixtures, focused ASAN/UBSAN runs, and `git diff --check`. Full
  `make test` was attempted but exceeded the tool timeout while older suites
  were still printing passing assertions, so scoped Wave 2 suites were treated
  as the reliable completion signal for this implementation-only pass.
- Deferred items: the dedicated v0.20 test suite, aggregate test wiring, and
  v0.20 sanitizer wrappers are deferred to the requested follow-up test pass.
  Typed function parameters/runtime type tags are deferred because they are out
  of scope for this cleanup and belong with the upcoming function-value work.
- Known technical debt carried into `v0.21.0`: generated Bash helper emission is
  still dependency-class based rather than per-helper; collection element-kind
  tracking is deliberately simple and does not model nested collections, map
  value kinds, function parameter kinds, or arbitrary dataflow through future
  value-returning functions.
