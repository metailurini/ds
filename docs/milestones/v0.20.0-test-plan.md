# v0.20.0 Test Plan — Cleanup: Wave 2 Stabilization

## Status

Implemented. The dedicated suite is `tests/v0_20/run.sh` and is wired into `make test-v0-20`, aggregate `make test`, ASAN, and UBSAN paths.

The suite must prove that the features added in `v0.17.0`, `v0.18.0`, and
`v0.19.0` behave as one coherent language surface:

```txt
control flow + pipelines + strings + existing imports/functions/scripts/tests
```

No test should require new user-facing syntax beyond what is already supported
through `v0.19.0`.

## Purpose

The `v0.17.0`, `v0.18.0`, and `v0.19.0` suites already cover their own feature
slices. `v0.20.0` should add regression and composition coverage that those
milestone suites are likely to miss:

- Wave 2 features nested inside one another;
- VM/Bash parity under realistic shell-script patterns;
- generated Bash helper dependency behavior;
- diagnostics for unsupported combinations;
- formatter/checker behavior for mixed syntax;
- sanitizer safety for allocation-heavy strings and control-flow paths.

## Test entrypoint

Add:

```sh
tests/v0_20/run.sh
```

Wire it into the Makefile consistently with prior version suites:

```sh
make test-v0-20
make test
make test-asan
make test-ubsan
```

The test script should build `./ds` if needed, create temporary fixtures under a
private temp directory, and clean up after itself.

## Test conventions

Use the same shell conventions as existing version suites:

- `set -euo pipefail`;
- deterministic temp directories;
- helper functions for writing fixtures, running VM mode, emitting Bash, running
  emitted Bash, comparing stdout/stderr/status, and asserting diagnostics;
- no dependency on network access;
- no dependence on host-specific command output;
- quote temp paths because import and emit paths may contain spaces;
- avoid `sleep` and timing-sensitive checks;
- use small shell commands available in the existing test environment, such as
  `printf`, `cat`, `grep`, `sort`, `wc`, and `false`;
- normalize stderr only when source paths or shell paths make exact comparison
  intentionally unstable.

For parity tests, use this pattern:

1. Write `input.ds`.
2. Run `./ds input.ds` and capture stdout, stderr, and status.
3. Run `./ds emit bash input.ds -o out.sh`.
4. Run `bash -n out.sh`.
5. Run `bash out.sh` and capture stdout, stderr, and status.
6. Assert VM and Bash results match.
7. Assert generated Bash does not contain a call to `ds`.

## Cross-feature VM/Bash parity tests

### Control flow with string predicates

Fixture:

```ds
let raw = " api,web,,worker "
let parts = raw.trim().split(",")
let i = 0
while i < 4 {
  let part = parts[i].trim()
  if part == "" {
    i += 1
    continue
  }
  if part.starts_with("w") {
    echo "web-ish={part:upper}"
  } else {
    echo "svc={part:<6}done"
  }
  i += 1
}
```

Expected stdout:

```txt
svc=api   done
web-ish=WEB
web-ish=WORKER
```

Assertions:

- VM and emitted Bash match;
- `split` empty field is preserved;
- `continue` does not skip the increment path in the test fixture;
- formatted interpolation works inside loop bodies.

### Nested loops with lexical break/continue

Fixture:

```ds
let outer = ["a", "b"]
let inner = ["1", "skip", "2", "stop", "3"]
for o in outer {
  for i in inner {
    if i == "skip" {
      continue
    }
    if i == "stop" {
      break
    }
    echo "{o}:{i}"
  }
}
```

Expected stdout:

```txt
a:1
a:2
b:1
b:2
```

Assertions:

- `break` exits only the inner loop;
- `continue` advances only the inner loop;
- emitted Bash and VM match.

## Formatter tests

### Idempotence for Wave 2 syntax

For fixtures containing control flow, pipelines, strings, and triple-quoted
literals without comments:

1. Run `./ds fmt input.ds > once.ds`.
2. Run `./ds fmt once.ds > twice.ds`.
3. Assert `cmp once.ds twice.ds`.
4. Run `./ds check once.ds`.
5. For deterministic scripts, compare VM/Bash behavior before and after
   formatting.

Fixtures should include:

- nested `while` / `for` loops with `break` and `continue`;
- `case` with string/int/bool arms;
- plain and captured pipelines;
- string method chains;
- formatted interpolation specifiers;
- triple-quoted literals;
- imports and function bodies.

### Comment rejection remains clear

Unless v0.20 intentionally implements comment-preserving formatting, fixtures
with file header comments, block comments, and trailing inline comments should:

- parse/check/run normally where otherwise valid;
- fail `ds fmt` with a diagnostic that says comments/trivia are unsupported;
- not produce silently comment-stripped output;
- keep docs/status aligned with this limitation.

### Formatter does not execute commands

Assertions:

- `ds fmt input.ds` does not create `created-by-command.txt`;
- `ds check input.ds` does not create it either;

## Sanitizer tests

## Regression tests from previous reviews

Carry forward focused regressions that should not reappear:

- short colon fragments in strings/command words do not read past the string end;
- center alignment `:^N` emits and runs as center alignment, not right alignment;
- command-word interpolation requiring string helpers emits those helpers;
- `:upper` and `:lower` formatting emit any required Bash guard/helper path;
- bool-returning string predicates in `case` retain bool kind in Bash emission;
- empty format specifier `{name:}` is rejected;
- defaulted string/int/bool function parameters used directly as `case`
  selectors emit Bash type tags and match VM behavior when defaults are used;
- unknown-kind function parameters cannot call string methods or formatted string
  transforms, and explicit function argument runtime kind propagation remains
  deferred until typed parameters/runtime tags are deliberately implemented.
