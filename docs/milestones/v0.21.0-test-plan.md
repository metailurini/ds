# v0.21.0 Test Plan — Function Values and Arithmetic

## Status

Not started. This plan should be implemented after the `v0.21.0` feature work is
complete enough to run focused fixtures. The dedicated suite should be
`tests/v0_21/run.sh` and should be wired into the normal aggregate targets.

## Purpose

Prove that value-returning functions and integer arithmetic form one coherent
language surface across parser, checker, formatter, VM execution, standalone Bash
emission, imports, tests, examples, and diagnostics.

The suite must preserve the main product rules:

```txt
VM mode and emitted Bash agree for supported features
generated Bash is standalone and never calls ds
unsupported/deferred forms fail clearly before partial execution/emission
older procedure-style functions and arithmetic-free scripts keep working
```

## Test entrypoint

Add:

```sh
tests/v0_21/run.sh
```

Wire it consistently with previous suites:

```sh
make test-v0-21
make test
make test-asan
make test-ubsan
```

If ASAN/UBSAN aggregate runtime is too long, provide dedicated focused sanitizer
subruns and document that choice in the completion review.

## Test conventions

Follow existing version-suite conventions:

- `set -euo pipefail`;
- deterministic private temp directories;
- helper functions for writing fixtures, running VM mode, emitting Bash, running
  emitted Bash, comparing stdout/stderr/status, and asserting diagnostics;
- no network access;
- no timing-sensitive tests;
- quote all temp paths;
- use only stable shell commands when command output is needed;
- normalize path-specific stderr only where exact paths are intentionally
  unstable;
- assert `bash -n` for every emitted Bash fixture;
- assert generated Bash does not contain a call to `ds`.

For VM/Bash parity tests:

1. Write `input.ds`.
2. Run `./ds input.ds`; capture stdout, stderr, and status.
3. Run `./ds emit bash input.ds -o out.sh`.
4. Run `bash -n out.sh`.
5. Run `bash out.sh`; capture stdout, stderr, and status.
6. Compare stdout and status, and compare stderr when deterministic.
7. Assert emitted Bash is standalone.

Expected stdout:

```txt

```

Assertions:

- VM and Bash match;
- generated Bash contains no `ds` call;
- `bash -n` succeeds.

### Early return from nested blocks

Fixture:

```ds
fn choose(name = "api") {
  if name == "api" {
    return "backend"
  }

  return "other"
}

echo "{choose()}"
```

Expected stdout:

```txt
backend
```

Assertions:

- statements after the taken return are skipped;
- no leaked stdout from skipped statements.

### Return from loops and case arms

Fixture:

```ds
fn first_web(items = "api,web,worker") {
  let parts = items.split(",")
  let i = 0
  while i < 3 {
    let part = parts[i]
    case part {
      "web" { return part.upper() }
      _ { i += 1 }
    }
  }
  return "NONE"
}

echo "{first_web()}"
```

Expected stdout:

```txt
WEB
```

Assertions:

- return exits the function, not just the loop/case block;
- loop state does not leak to later code.

### Statement-style call ignores return value

## Arithmetic parser and precedence tests

### Basic precedence

Fixture:

```ds
echo "{1 + 2 * 3}"
echo "{(1 + 2) * 3}"
echo "{2 ** 3 ** 2}"
echo "{10 - 6 / 2}"
echo "{10 % 4 + 1}"
```

Expected stdout:

```txt
7
9
512
7
3
```

Assertions:

- `**` is right-associative;
- `*`, `/`, `%` bind tighter than `+` and `-`;
- parentheses override precedence.

### Arithmetic in function returns and calls

Fixture:

```ds
fn scale(n = 3) {
  return n * 10 + 2
}

fn add(a = 1, b = 2) {
  return a + b
}

echo "{scale()}"
echo "{scale(add(2, 3))}"
```

Expected stdout:

```txt
32
52
```

Assertions:

- function-call expressions can be arithmetic operands;
- nested calls evaluate once and in order.

### Arithmetic in conditions and case selectors

Fixture:

```ds
let n = 3
if n * 2 == 6 {
  echo yes
}

case n + 1 {
  4 { echo four }
  _ { echo other }
}
```

Expected stdout:

```txt
yes
four
```

### Negative numbers and exponent edge

Fixture:

```ds
echo "{-2 * 3}"
echo "{(-2) ** 3}"
echo "{2 ** 0}"
```

Expected stdout:

```txt
-6
-8
1
```

Assertions:

- unary minus and exponent precedence are documented and implemented;
- parenthesized negative bases behave consistently.
