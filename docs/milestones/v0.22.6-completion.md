# v0.22.6 Completion Note — Handler Context and Final v0.22 Documentation

`v0.22.6` closes the staged `v0.22` cleanup/signal milestone by documenting
which parts of the original process-control goal are supported, rejected,
deferred, and out of scope. It does not add new source-language syntax.

## Landed across v0.22.0 through v0.22.6

- Process-scope `defer { ... }` cleanup handlers for `EXIT`.
- Signal-specific `defer on: "EXIT"`, `defer on: "INT"`, and
  `defer on: "TERM"` handlers.
- Replacement-style `trap "EXIT"`, `trap "INT"`, and `trap "TERM"` handlers.
- Deterministic ordering: matching trap first, matching defers in LIFO order,
  then `EXIT` trap and `EXIT` defers for `INT`/`TERM` shutdown.
- VM and emitted-Bash parity for normal completion, explicit `exit`, explicit
  `fail`, direct command failure, captured command failure, foreground
  direct-command signals, and simple foreground-pipeline signals.
- A deterministic process-session signal harness for focused `INT`/`TERM`
  runtime coverage.
- Diagnostics for unsupported signals, malformed signal syntax, direct handler
  `return`, and function-local handler captures.

## Rejected in v0.22

- Function-local handler captures. Cleanup registration is process-scope and may
  run after the function that registered the handler has returned.
- Direct `return` from cleanup handlers. Use `exit N` when a handler needs to
  choose a process-level final status.
- Unsupported signal names, numeric signal syntax, multi-signal declarations,
  and handler removal APIs.

## Deferred after v0.22

- Handler context values such as a `$LINENO`-equivalent. This is deferred
  because VM execution and emitted Bash need a shared, portable source-location
  model before handlers can expose reliable line/context metadata.
- Function-local RAII-style cleanup.
- Broad signal metadata or structured cleanup/error objects.

## Out of scope

- Background jobs and background pipelines.
- Async/wait primitives.
- Public job-control/process-group APIs.
- Shell-grade process-tree management beyond the supported foreground direct
  command and simple foreground pipeline subset.
