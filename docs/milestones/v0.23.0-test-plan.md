# v0.23.0 Test Plan — Regex, Ranges, and Membership

## Status

Implemented. The dedicated suite lives at `tests/v0_23/run.sh`, is wired into the
normal aggregate targets, and covers the scoped feature surface plus VM/Bash
parity for membership, regex matching, and integer range loop sources.

## Purpose

Prove that membership checks, integer ranges, and regex matching form one
coherent language surface across parser, checker, formatter, VM execution,
standalone Bash emission, imports, functions, test blocks, diagnostics, and
generated-script behavior.

The suite must preserve the main product rules:

```txt
VM mode and emitted Bash agree for supported features
generated Bash is standalone and never calls ds
unsupported/deferred forms fail clearly before partial execution/emission
older scripts without v0.23 syntax keep working
```

## Test entrypoint

Add:

```sh
tests/v0_23/run.sh
```

Wire it consistently with previous suites:

```sh
make test-v0-23
make test
make test-asan
make test-ubsan
```

`make test-asan` and `make test-ubsan` are aliases for the repository's
sanitizer test targets.

If regex engine behavior differs by host in a way that cannot be made portable,
remove the construct from the supported subset rather than making host-specific
expected output.

## Test conventions

Follow existing version-suite conventions:

- `set -euo pipefail`;
- deterministic private temp directories;
- helper functions for writing fixtures, running VM mode, emitting Bash, running
  emitted Bash, comparing stdout/stderr/status, and asserting diagnostics;
- no network access;
- no timing-sensitive tests;
- quote all temp paths;
- use only stable shell commands;
- normalize path-specific stderr only where exact paths are intentionally
  unstable;
- assert `bash -n` for every emitted Bash fixture;
- assert generated Bash does not contain a call to `ds`;
- avoid tests whose regex behavior is known to differ across common libc/Bash
  environments unless the implementation normalizes it.

For VM/Bash parity tests:

1. Write `input.ds`.
2. Run `./ds input.ds`; capture stdout, stderr, and status.
3. Run `./ds emit bash input.ds -o out.sh`; assert success.
4. Run `bash -n out.sh`.
5. Assert `out.sh` does not call `ds`.
6. Run `bash out.sh`; capture stdout, stderr, and status.
7. Compare stdout, stderr, status, and declared side-effect files.

### Membership: positive VM/Bash parity

String arrays:

```ds
let app = "api"
let allowed = ["api", "web"]
if app in allowed {
  echo yes
} else {
  echo no
}
```

Integer arrays:

```ds
let n = 2
if n in [1, 2, 3] {
  echo yes
}
```

Boolean arrays:

```ds
let flag = false
if flag in [true, false] {
  echo yes
}
```

Empty array:

```ds
let xs = []
if "x" in xs {
  echo bad
} else {
  echo empty
}
```

Exact/kind-aware matching:

```ds
let mixed = ["2"]
if 2 in mixed {
  echo bad
} else {
  echo good
}
```

String safety:

```ds
let needle = "a*b"
let xs = ["axb", "a*b"]
if needle in xs {
  echo literal
}
```

Helper-derived arrays:

```ds
let parts = "api,web".split(",")
if "web" in parts {
  echo found
}
```

Lines/glob integration where deterministic:

```ds
file.write("items.txt", "a\nb\n")
if "b" in lines("items.txt") {
  echo found
}
```

Expression contexts:

- `let ok = app in allowed`;
- `assert app in allowed`;
- `echo "known={app in allowed}"`;
- `if (app in allowed) && true { ... }`;
- `while item in allowed { ... }` with mutation to terminate;
- `case app in allowed { true { ... } false { ... } }`;
- function return: `return app in allowed`;
- function argument: `show(app in allowed)`.

### Ranges: positive VM/Bash parity

Literal inclusive range:

```ds
for n in 1..3 {
  echo "{n}"
}
```

Variable bounds:

```ds
let start = 2
let end = 4
for n in start..end {
  echo "{n}"
}
```

Arithmetic bounds:

```ds
for n in 1 + 1..2 * 3 {
  echo "{n}"
}
```

Function-return bounds after v0.21:

```ds
fn first() { return 1 }
fn last() { return 2 }
for n in first()..last() {
  echo "{n}"
}
```

Single-value range:

```ds
for n in 3..3 {
  echo "{n}"
}
```

Empty high-to-low range:

```ds
for n in 5..3 {
  echo none
}
echo done
```

Negative bounds:

```ds
for n in -2..1 {
  echo "{n}"
}
```

Loop variable kind:

```ds
for n in 1..3 {
  case n {
    2 { echo two }
    _ { echo other }
  }
}
```

Break/continue:

```ds
for n in 1..5 {
  if n == 2 { continue }
  if n == 4 { break }
  echo "{n}"
}
```

Nested ranges:

```ds
for i in 1..2 {
  for j in 1..2 {
    echo "{i},{j}"
  }
}
```

Bounds evaluated once:

```ds
let end = 3
for n in 1..end {
  echo "{n}"
  end = 1
}
```

Expected output still includes `1`, `2`, and `3`.

### Regex: positive VM/Bash parity

Basic search:

```ds
if "deploy failed" matches /failed/ {
  echo yes
}
```

Anchors and escaped slash:

```ds
let branch = "release/123"
if branch matches /^release\/[0-9]+$/ {
  echo release
}
```

Alternation and groups:

```ds
let svc = "api"
if svc matches /^(api|web)$/ {
  echo service
}
```

Character classes and negation:

```ds
if "x9" matches /^[^0-9][0-9]$/ {
  echo ok
}
```

Quantifiers:

```ds
if "aaa" matches /^a{2,3}$/ {
  echo ok
}
```

Case-sensitive miss:

```ds
if "API" matches /api/ {
  echo bad
} else {
  echo good
}
```

Case-insensitive `/i`:

```ds
if "API" matches /api/i {
  echo good
}
```

No shell-option leakage after `/i`:

```ds
if "API" matches /api/i {
  echo first
}
if "API" matches /api/ {
  echo bad
} else {
  echo restored
}
```

Regex in expression contexts:

- `let ok = value matches /^x/`;
- `assert value matches /x/`;
- `echo "ok={value matches /x/}"`;
- `if (value matches /x/) || false { ... }`;
- `case value matches /x/ { true { ... } false { ... } }`;
- function return: `return value matches /x/`;
- function argument: `show(value matches /x/)`.

Regex escapes:

```ds
if "a/b" matches /a\/b/ {
  echo slash
}

if "a\\b" matches /a\\b/ {
  echo backslash
}
```

### Combined v0.23 interactions

Membership plus regex:

```ds
let names = ["api", "web", "db"]
for name in names {
  if (name in ["api", "web"]) && (name matches /^[a-z]+$/) {
    echo "ok={name}"
  }
}
```

Range plus membership:

```ds
let odds = [1, 3, 5]
for n in 1..5 {
  if n in odds {
    echo "odd={n}"
  }
}
```

Range plus regex formatting:

```ds
for n in 1..3 {
  let s = "item-{n:02d}"
  if s matches /^item-[0-9][0-9]$/ {
    echo $s
  }
}
```

Function return plus all three:

```ds
fn valid(name) {
  return (name in ["api", "web"]) && (name matches /^[a-z]+$/)
}

for i in 1..2 {
  if valid("api") {
    echo "{i}:ok"
  }
}
```

Imports:

- imported function returns regex/membership bool;
- imported variable supplies allowed array;
- root script uses imported helper inside a range loop;
- emitted Bash bundles everything and remains standalone.

Script args:

```ds
script {
  arg app: string
  option retries: int = 2
}

if !(app in ["api", "web"]) {
  fail "unknown app"
}

for n in 1..retries {
  echo "try={n}"
}
```

Test blocks:

```ds
test "regex and membership" {
  assert "api" in ["api"]
  assert "release/1" matches /^release\/[0-9]+$/
}
```

### Bash emission checks

For every positive parity fixture that emits Bash:

- `bash -n out.sh` succeeds;
- generated Bash contains no `ds` invocation;
- generated Bash quotes regex and string elements safely;
- scripts using `/i` preserve and restore `nocasematch` or use an equivalent
  local helper;
- scripts without `/i` do not alter `nocasematch` unnecessarily;
- range loops do not use brace expansion with runtime variables;
- range loop variables carry int type tags where type tags are needed;
- membership over arrays preserves bool/int/string type tags;
- generated helpers are not duplicated across imports.

### Checker diagnostics

Run `ds check` for every rejected fixture and assert:

- non-zero exit status where the issue is fatal;
- source filename, line, and column are present;
- message mentions the rejected feature or type mismatch;
- no generated Bash artifact is left behind after failed emission.

Warnings, if any, must stay non-fatal unless `--warnings-as-errors` is used.
