# v0.24.0 Test Plan — Cleanup: Pre-1.0 Hardening

## Status

Implemented. The dedicated suite lives at `tests/v0_24/run.sh` and is wired
into both `make test-v0-24` and the aggregate `make test` version list.

The dedicated suite should live at:

```sh
tests/v0_24/run.sh
```

It should be wired into the normal aggregate targets:

```sh
make test-v0-24
make test
make test-asan
make test-ubsan
```

`v0.24.0` is a cleanup milestone. Tests must harden the current supported
surface and rejection behavior. They must not require new production language
features.

## Purpose

Prove that the whole implemented language through `v0.23.0` is coherent enough
for a `1.0.0` release checklist:

```txt
VM mode and emitted Bash agree for supported features
generated Bash is standalone and never calls ds
examples are accurate and executable
docs describe the real supported/deferred/rejected surface
unsupported forms fail before partial execution/emission
sanitizer-backed runs do not expose supported-surface ownership bugs
```

The suite should complement existing version suites rather than duplicate every
old isolated fixture. Prefer cross-feature integration tests, docs/status audits,
generated-Bash audits, sanitizer-compatible fixtures, and diagnostic regression
checks.

## Test conventions

Follow existing version-suite conventions:

- `set -euo pipefail`;
- private deterministic temp directories;
- helper functions for writing fixtures, running VM mode, emitting Bash, running
  emitted Bash, comparing stdout/stderr/status, asserting diagnostics, and
  checking generated Bash content;
- no network access;
- no timing-sensitive tests except the existing deterministic signal harness
  utilities already used by v0.22;
- quote all temp paths;
- normalize absolute temp paths in stderr only where exact paths are inherently
  unstable;
- use stable shell commands already relied on by the project test suites;
- run `bash -n` for every emitted Bash fixture;
- assert generated Bash does not contain a call to `ds`;
- assert helper names stay under the reserved `__ds_` prefix;
- keep fixtures small enough that failures are diagnosable;
- do not rely on locale-specific regex/string behavior unless the implementation
  normalizes it.

For VM/Bash parity tests:

1. Write `input.ds`.
2. Run `./ds input.ds`; capture stdout, stderr, and status.
3. Run `./ds emit bash input.ds -o out.sh`; assert success.
4. Run `bash -n out.sh`; assert success.
5. Assert `out.sh` does not call `ds`.
6. Run `bash out.sh`; capture stdout, stderr, and status.
7. Compare stdout, stderr, status, and deterministic side-effect files.

### 3. Broad VM/Bash parity smoke script

Fixture:

```ds
script {
  arg app: string
  option target: string = "staging"
  flag force: bool = false
}

let allowed = ["api", "web", "worker"]
if !(app in allowed) {
  fail "unknown app"
}

let labels = "api,web,worker".split(",")
let seen = false
for idx in 0..2 {
  if labels[idx] == app {
    seen = true
  }
}

if !seen {
  fail "missing label"
}

fn suffix(name = "api") {
  if name matches /^a/ {
    return "alpha"
  }
  return "other"
}

let result = run printf "deploy:%s:%s:%s\n" $app $target $force
if result.failed {
  fail "printf failed"
}

let kind = suffix(app)
echo "{result.stdout:trim}:{kind}"
```

Run with:

```sh
./ds input.ds api --target production --force
bash out.sh api --target production --force
```

Expected stdout:

```txt
deploy:api:production:true:alpha
```

Assertions:

- VM and emitted Bash stdout/stderr/status match;
- script args, string split, membership, range loop, regex, function return,
  captured command result, bool interpolation, and formatting compose;
- command-word interpolation keeps the current v0.21 rule that function-call
  results must be bound to a scalar value before interpolation;
- generated Bash is standalone and passes `bash -n`.

### 4. Imports, functions, ranges, membership, and regex

Use two files.

`lib.ds`:

```ds
fn valid_app(name = "api") {
  return name in ["api", "web"]
}

fn release_branch(branch = "release/1") {
  return branch matches /^release\/[0-9]+$/
}
```

`main.ds`:

```ds
import "./lib.ds"

let count = 0
for n in 1..3 {
  count += n
}

if valid_app("web") && release_branch("release/24") && count == 6 {
  echo ok
} else {
  echo bad
}
```

Assertions:

- `check`, `hir`, `bytecode`, VM, Bash emission, and emitted Bash all succeed;
- imported value-returning functions compose with v0.23 operators;
- generated Bash bundles imports and never calls `ds`;
- stdout is `ok` in both VM and emitted Bash.

- generated Bash traps remain syntax-valid.
