# v0.26.0 Spec — Flat Collection and Command-Result Function Returns

## Status

Planned. This milestone follows `v0.25.0 — Portable Function Value Return ABI`
and implements the first structured values on top of that ABI. It must not be
started until the scalar value-return contract is implemented, tested, and
understood in both VM mode and emitted Bash.

`v0.26.0` is intentionally narrow: functions may return flat arrays, flat maps
/ objects, and command-result objects. Nested collections, map iteration, index
assignment, direct command-word function interpolation, and binary/streaming
command capture remain deferred to later roadmap milestones.

## Goal

Make functions able to return the structured data that scripts commonly need
while preserving the core DS requirements:

```txt
every supported production feature runs in the VM
every supported production feature emits standalone Bash
generated Bash is standalone and must not call ds
VM and emitted Bash behavior match for stdout, stderr, exit status, and side effects
unsupported or deferred forms fail clearly before partial execution/emission
```

By the end of this milestone:

- a value-returning function can return a flat array of scalar values;
- a value-returning function can return a flat map/object with string keys and
  scalar values;
- a value-returning function can return the current command-result value shape;
- emitted Bash encodes, transports, and decodes those values through the private
  `v0.25.0` return ABI;
- the VM continues to pass real typed runtime values directly;
- arrays/maps/command results returned from functions behave the same as
  equivalent values created outside functions;
- ordinary stdout remains reserved for the encoded return payload in
  value-returning Bash functions;
- deferred structured-value features are rejected with clear diagnostics.

## Motivation

`v0.25.0` makes scalar function returns portable by reserving function stdout for
a private typed return payload in emitted Bash. That foundation is useful only if
DS can then return real script data, especially arrays, maps, and command
results.

Useful scripts need functions like:

```ds
fn apps() {
  return ["api", "web", "worker"]
}

let names = apps()
echo names[0]
```

and:

```ds
fn package_info() {
  return { name: "api", port: 8080, enabled: true }
}

let info = package_info()
echo "{info.name}:{info.port}"
```

and:

```ds
fn grep_errors(path = "app.log") {
  return run grep "ERROR" path
}

let result = grep_errors("app.log")
if result.failed {
  echo result.stderr
}
```

Bash cannot return these values directly. This milestone makes the DS-owned
return ABI carry the first structured values without leaking the encoding to
users or weakening standalone Bash emission.

## Non-goals

This version does not include:

- nested arrays;
- nested maps/objects;
- arrays containing maps or maps containing arrays;
- arrays/maps containing command-result objects;
- returning ranges, regex objects, processes, jobs, functions, or cleanup
  handler values;
- map iteration syntax;
- index assignment or mutation of returned collection elements;
- direct function-call interpolation in command words;
- collection values passed directly as command arguments;
- command substitution syntax beyond the existing `run` command-result surface;
- streaming command results;
- binary-safe command stdout/stderr storage;
- public access to the internal value serialization format;
- typed return annotations;
- typed required parameters;
- recursive functions unless already supported by earlier milestones;
- broad redesign of command execution, cleanup/signal handling, imports, or
  collection literals outside what is necessary for returned values.

Small supporting changes are allowed only when they are required to make the
scoped returned values safe, deterministic, and portable.

## Required feature work

### 1. Flat array function returns

Allow a value-returning function to return an array literal or array variable
whose elements are scalar values.

Supported element kinds for this milestone:

- string;
- int;
- bool;
- null, only if null is already a supported array value in the current language;
- any other scalar kind already supported in arrays before this milestone.

Required behavior:

- returned arrays preserve element order;
- returned arrays preserve element kinds, not just rendered text;
- empty arrays can be returned if the current type/kind rules can infer their
  kind safely; otherwise they must be rejected with a clear diagnostic;
- returned arrays can be assigned to variables;
- returned arrays can be indexed using the existing supported indexing syntax;
- returned arrays can be used in existing array loops and membership checks
  where equivalent non-returned arrays are already legal;
- returned arrays from imported functions behave the same as local functions;
- return-kind validation remains same-kind across all return paths;
- emitted Bash decodes returned arrays without depending on `ds`, Python, Perl,
  `jq`, or non-standard tools.

Examples:

```ds
fn apps() {
  return ["api", "web", "worker"]
}

let names = apps()
echo names[0]
```

```ds
fn flags() {
  return [true, false, true]
}

let values = flags()
if values[0] {
  echo "enabled"
}
```

### 2. Flat map/object function returns

Allow a value-returning function to return a map/object literal or map variable
whose keys are strings and whose values are scalar values.

Supported key/value shape:

- keys must be strings or the existing object-field key syntax that lowers to a
  string key;
- values must be scalar values supported by the current map/object
  implementation;
- nested maps, arrays, and command-result objects as map values are deferred.

Required behavior:

- returned maps preserve the same lookup behavior as equivalent non-returned
  maps;
- returned maps preserve scalar value kinds;
- returned maps can be assigned to variables;
- returned maps can be accessed using existing supported member/index lookup
  syntax;
- duplicate-key behavior must match existing map literal rules;
- empty maps can be returned if the current kind rules can infer them safely;
  otherwise they must be rejected with a clear diagnostic;
- emitted Bash must not rely on host-specific associative-array iteration order
  for user-visible behavior;
- returned maps from imported functions behave the same as local functions.

Examples:

```ds
fn service() {
  return { name: "api", port: 8080, enabled: true }
}

let app = service()
echo "{app.name}:{app.port}:{app.enabled}"
```

```ds
fn labels() {
  let data = { role: "worker", tier: "batch" }
  return data
}

let value = labels()
echo value.role
```

### 3. Command-result function returns

Allow a value-returning function to return the current command-result value
shape produced by supported command capture syntax.

The returned command-result object must expose the same fields as command
results created outside functions. At minimum this milestone tracks the roadmap
shape:

- `stdout`;
- `stderr`;
- `status`.

If the current language already exposes compatibility fields such as `code`,
`ok`, `failed`, or other command-result properties, returned command-result
values must preserve those fields exactly as existing command results do.

Required behavior:

- non-zero captured command status remains data, not an automatic fatal script
  failure, when that is the existing `run` capture rule;
- fatal command execution failures must propagate consistently with existing
  command semantics;
- stdout and stderr text are preserved exactly according to the current
  text-oriented command-result contract;
- command-result values can be assigned to variables;
- command-result fields can be read after return;
- command-result values returned from imported functions behave the same as
  local functions;
- emitted Bash uses temporary files or equivalent safe helpers without leaking
  files on success or normal failure paths;
- emitted Bash does not corrupt the return payload with the command's user
  stdout/stderr.

Examples:

```ds
fn probe() {
  return run printf "hello"
}

let result = probe()
echo result.stdout
```

```ds
fn missing() {
  return run grep "needle" "missing-file.txt"
}

let result = missing()
echo result.status
if result.failed {
  echo result.stderr
}
```

### 4. Extend the private Bash value-return ABI

Extend the internal `v0.25.0` typed return payload so it can represent:

- flat arrays of scalar values;
- flat maps/objects with string keys and scalar values;
- command-result objects with text stdout/stderr and integer status plus any
  existing compatibility fields.

The exact format remains private implementation detail, but it must satisfy:

- preserve empty strings, whitespace, quotes, backslashes, tabs, and newlines;
- preserve array element order;
- preserve map key/value identity;
- preserve scalar value kinds inside collections;
- safely carry captured command stdout and stderr text;
- reject malformed internal payloads with generated-script diagnostics useful
  during DS development;
- avoid external runtime dependencies beyond documented baseline shell/core
  utilities already accepted by the project;
- remain deterministic under generated Bash strict mode;
- keep helper names under the reserved `__ds_` namespace;
- emit helpers only when needed and without duplicates.

Plain newline-separated payloads are not acceptable because strings and command
output may contain newlines.

### 5. Decode structured values at Bash call sites

When emitted Bash calls a structured-value-returning function from an expression
position, the generated caller must:

- capture the function payload;
- capture the function status;
- fail before using the value if the function status indicates failure;
- decode the payload into the expected DS kind;
- preserve or create the appropriate Bash-side representation/sidecar for arrays,
  maps, and command-result objects;
- avoid leaking helper temporaries into user-visible behavior;
- preserve strict-mode behavior;
- keep VM/Bash stdout, stderr, status, and side effects aligned.

Supported contexts should include existing value contexts where equivalent
non-returned arrays/maps/command results are already legal:

- `let value = f()`;
- `return f()` from another function of the same structured kind;
- indexing/member access after binding the returned value;
- existing array loops and membership checks where currently legal;
- conditionals over scalar fields/elements from returned values;
- import-aware function calls.

This milestone should not expand command-word interpolation. A structured value
must not be directly interpolated into command arguments unless an existing
explicit scalar field/element is selected first.

### 6. Return-kind validation and diagnostics

Extend existing same-kind/all-path return validation to structured values.

Required diagnostics:

- returning an array on one path and a scalar/map/command result on another path;
- returning maps with incompatible value-kind shapes if the implementation
  requires a uniform shape;
- returning arrays with unsupported nested or mixed values when those forms are
  not accepted by the current collection rules;
- returning a command result from a function whose other paths return a scalar,
  array, or map;
- using returned structured values in unsupported contexts, such as direct
  command-word interpolation;
- attempting to return nested collections before the roadmap milestone that
  supports them;
- ordinary stdout-producing statements inside value-returning functions, as
  already required by `v0.25.0`.

Diagnostics should suggest supported alternatives when practical:

- return a scalar field or element;
- split output-oriented and value-returning behavior;
- bind the returned value first, then access a scalar field/element;
- wait for later milestones for nested collections, map iteration, or index
  assignment.

### 7. Documentation updates

Update docs only where the implementation changes the support boundary:

- `docs/status.md` should mark flat array, flat map/object, and command-result
  function returns as supported when complete;
- `docs/runtime.md` should describe structured value returns at a high level and
  keep the Bash encoding private;
- `docs/language.ds` should show supported examples and clearly mark nested
  collection returns, map iteration, index assignment, and direct function-call
  interpolation as deferred;
- `README.md` examples may be adjusted only if they otherwise become stale or
  misleading;
- `docs/release-checklist.md` should remain honest about any unchecked
  pre-`1.0.0` sign-offs.

## Bash emission requirements

Generated Bash for this milestone must:

- remain standalone and never call the `ds` binary;
- preserve exact returned structured values;
- preserve scalar kinds inside arrays and maps;
- preserve command-result stdout/stderr/status fields;
- pass `bash -n` for emitted scripts;
- include helpers only when needed;
- avoid duplicate helper emission;
- keep all DS helper names under `__ds_`;
- avoid relying on nondeterministic map iteration order for user-visible output;
- keep command stdout/stderr separate from encoded value-return payload stdout;
- clean up temporary files created for command capture or payload decoding;
- preserve VM/Bash parity for stdout, stderr, exit status, and filesystem side
  effects.

## Examples

Valid flat array return:

```ds
fn apps() {
  return ["api", "web", "worker"]
}

let names = apps()
echo names[1]
```

Valid flat map/object return:

```ds
fn service() {
  return { name: "api", port: 8080, enabled: true }
}

let app = service()
if app.enabled {
  echo "{app.name}:{app.port}"
}
```

Valid command-result return:

```ds
fn render(name = "api") {
  return run printf "service=%s\n" name
}

let result = render("web")
echo result.stdout
```

Invalid nested collection return:

```ds
fn nested() {
  return [["api"], ["web"]]
}

let value = nested()
```

Invalid mixed return kinds:

```ds
fn bad(flag = true) {
  if flag {
    return ["api"]
  }
  return { name: "api" }
}

let value = bad(false)
```

Invalid direct command-word interpolation of a structured value:

```ds
fn apps() {
  return ["api", "web"]
}

echo "{apps()}"
```

## Acceptance criteria

`v0.26.0` is complete when:

- flat scalar arrays can be returned from functions in VM mode and emitted Bash;
- flat scalar maps/objects can be returned from functions in VM mode and emitted
  Bash;
- command-result objects can be returned from functions in VM mode and emitted
  Bash;
- returned structured values preserve their kinds, contents, and supported
  lookup behavior;
- returned command-result objects preserve stdout, stderr, and status/non-zero
  capture semantics;
- emitted Bash uses the `v0.25.0` private return ABI and remains standalone;
- generated Bash passes `bash -n` and does not call `ds`;
- ordinary stdout cannot corrupt value-return payloads;
- unsupported nested collections, map iteration, index assignment, and direct
  structured interpolation remain rejected or clearly deferred;
- the dedicated `v0.26.0` test plan is implemented;
- docs/examples are updated if the implementation changes the documented
  support boundary;
- the completion review below is filled in.

## Deferred items

Deferred to `v0.27.0`:

- direct `env.NAME` read/assignment syntax;
- direct scalar function-call interpolation in command words.

Deferred to `v0.29.0`:

- map iteration.

Deferred to `v0.30.0`:

- index assignment.

Deferred beyond this milestone:

- nested arrays and maps;
- arrays of maps;
- maps containing arrays or command-result objects;
- streaming command results;
- binary-safe command-output values;
- public serialization APIs;
- typed return annotations and typed required parameters;
- richer job/process values.

- Implementation summary: flat scalar arrays, flat scalar maps/objects, and
  command-result objects can be returned from functions, including forwarded
  structured returns. The lowerer no longer rejects those v0.26 return kinds,
  and emitted Bash materializes them through the private value-return ABI.
- Test summary: `tests/v0_26/run.sh` implements the dedicated v0.26 test plan
  and is wired into `make test-v0-26` / aggregate version test discovery. It
  covers direct and forwarded array returns, direct and forwarded map returns,
  empty array returns, command-result returns through both `status` and `code`,
  command-result pipeline returns, imports, diagnostics, malformed private
  structured payload guards, docs/status checks, generated Bash standalone
  checks, and Bash syntax validation. The suite passed with 398 assertions
  during the follow-up completion pass.
- VM/Bash parity notes: returned arrays/maps now preserve scalar kind metadata
  in emitted Bash sidecars, so membership, indexing, map field reads, and ds
  truthiness match VM behavior for flat scalar collections.
- Bash helper/ABI notes: `__ds_call_value_into` copies structured payloads by
  reference into caller-owned variables and copies per-element/per-key kind
  sidecars. Function capture clears stale structured payload globals before
  each call and validates that structured return payload variables and required
  sidecars exist. Command-result returns now expose `status` as the roadmap
  field while preserving `code` as a compatibility alias.
- Diagnostics added or changed: collection/command-result return diagnostics
  were relaxed for the v0.26 flat surface; nested/mixed structured values remain
  rejected or deferred.
- Docs/examples/tests updated: `docs/runtime.md`, `docs/status.md`, and
  `docs/language.ds` describe the v0.26 structured return support boundary and

- Deferred items confirmed: nested arrays/maps, arrays of maps, maps containing
  arrays/command results, collection-valued parameters, map iteration, index
