# v0.28.0 Spec — Cleanup: Value, Environment, and Interpolation Stabilization

## Status

Planned. This is the next unwritten roadmap milestone after the completed
`v0.27.0 — Environment Variables and Direct Function Interpolation` milestone.

`v0.28.0` is a cleanup milestone. It must not add production syntax or expand
the language surface. Its purpose is to stabilize the value-return,
environment, command-result, and interpolation work introduced across
`v0.25.0` through `v0.27.0` before the roadmap moves on to map iteration and
index assignment.

## Goal

Make the value/environment/interpolation surface boring, predictable, and easy
to maintain.

By the end of this milestone:

- scalar, flat collection, and command-result function returns should share one
  documented VM/Bash value-return contract;
- direct `env.NAME` reads, `env.NAME = scalar` assignment, `unset env.NAME`,
  environment helpers, command-result capture, and function-call interpolation
  should compose without backend drift;
- unsupported nested collections, illegal stdout in value-returning functions,
  invalid interpolation targets, and invalid environment assignments should fail
  at the correct ownership layer before partial execution or emission;
- generated Bash should remain standalone, deterministic, helper-hygienic, and
  free of duplicated value-return/interpolation helper logic;
- docs and examples should describe the exact supported flat-value boundary and
  the deferred nested/iteration/mutation boundary.

The core product rules remain unchanged:

```txt
every supported production feature runs in the VM
every supported production feature emits standalone Bash
generated Bash is standalone and must not call ds
VM and emitted Bash behavior match for stdout, stderr, exit status, and side effects
unsupported or deferred forms fail clearly before partial execution/emission
cleanup work fixes inconsistency without expanding the language surface
```

## Motivation

The preceding three milestones deliberately introduced a large amount of
cross-cutting machinery:

1. `v0.25.0` established the portable scalar value-return ABI.
2. `v0.26.0` extended function returns to flat arrays, flat maps, and captured
   command results.
3. `v0.27.0` added direct environment access and direct scalar function calls in
   interpolation, including command-word pre-materialization before command
   launch.

Those features are valuable, but they put pressure on several shared concepts:

- value-kind metadata and return-kind validation;
- VM/Bash return transport and Bash sidecar metadata;
- command-result field ownership;
- direct environment syntax versus environment helper calls;
- normal string interpolation versus command-word interpolation;
- lowerer-owned semantic/parity gates versus backend runtime invariants;
- helper dependency scanning and generated Bash helper emission.

The roadmap intentionally schedules `v0.28.0` as a cleanup checkpoint before
`v0.29.0` map iteration and `v0.30.0` index assignment. New collection traversal
and mutation would be harder to implement safely if the existing value and
interpolation contracts remain duplicated or ambiguous.

## Non-goals

This version does not include:

- new language syntax unless required to fix a correctness bug in already
  supported syntax;
- map iteration;
- index assignment;
- nested collection function returns;
- nested collection literals beyond already rejected/deferred forms;
- collection-valued function parameters;
- typed return annotations;
- typed required parameters;
- destructuring;
- collection spreading, slicing, or comprehensions;
- direct interpolation of arrays, maps, command results, jobs, handlers, regex
  captures, or other structured values;
- command substitution, process substitution, heredocs, here-strings, command
  `&&`/`||`, background jobs, or async/wait primitives;
- recursive glob behavior;
- regex captures, replacement, splitting, runtime regex strings, or regex/glob
  `case` patterns;
- scoped environment blocks, environment append/prepend shorthand, `.env` file
  loading, or environment iteration;
- formatter trivia preservation, formatter configuration, warning suppression,
  editor/LSP work, new shell backends, or native compilation.

Small behavior changes are allowed only when they remove VM/Bash drift, fix a
bug in the existing supported surface, move a diagnostic to its correct owner,
or clarify a documented ambiguity. Every such change must be recorded in the
completion review and covered by tests.

## Required cleanup work

### 1. Value-return protocol audit

Audit the implementation of function return values across the lowerer, VM, and
Bash emitter.

Required outcomes:

- one documented value-return model for scalar, flat array, flat map, and
  command-result returns;
- no backend-specific semantic acceptance rules for source-language return
  forms;
- return-kind discovery and all-path validation remain lowerer-owned;
- VM and Bash agree on stdout-clean value-returning functions;
- statement-style function calls may still stream stdout and ignore returned
  values according to the existing contract;
- expression-style function calls still reject stdout-producing bodies when the
  value-return protocol requires stdout cleanliness;
- returned arrays/maps keep the element/key/value kind metadata required for
  membership, indexing, field access, and truthiness parity;
- command-result returns preserve `stdout`, `stderr`, `status`, `code`, `ok`,
  and `failed` field behavior without becoming generic maps;
- overflow/error/status handling in expression-style value calls remains
  consistent with earlier scalar return rules;
- duplicated VM/Bash helper routines are consolidated where this can be done
  without broad redesign.

Do not add nested collection returns. If nested collection inputs are currently
parseable, they must be rejected with clear diagnostics at the lowerer/parity
gate layer.

### 2. Environment behavior audit

Audit direct environment syntax and environment helper calls as one coherent
surface.

Required outcomes:

- `env.NAME` reads, `env.NAME = scalar`, and `unset env.NAME` match the
  documented behavior for present, empty, and missing variables;
- direct environment operations and `env.get` / `env.set` / `env.unset` helpers
  either share implementation metadata or are documented as intentionally
  distinct compatibility surfaces;
- valid environment names are checked consistently;
- invalid direct names, invalid helper names, and invalid unset targets produce
  clear diagnostics;
- assigning arrays, maps, command results, or unknown/unsupported structured
  values to environment variables is rejected before execution/emission;
- string, int, and bool assignments stringify canonically and identically in VM
  and emitted Bash;
- environment mutations inside functions and before/after interpolated calls are
  ordered predictably;
- child commands launched after assignment/unset observe the updated
  environment in both VM and emitted Bash;
- generated Bash reads environment values at runtime, not at DS compile time.

Do not add scoped environment blocks, append/prepend shorthand, environment
iteration, or `.env` loading.

### 3. Interpolation contract audit

Review normal string interpolation and command-word interpolation together, but
keep their ownership boundaries explicit.

Required outcomes:

- parser preserves interpolation syntax without taking semantic ownership;
- `lower_interpolation.c` owns normal string interpolation acceptance;
- `lower_command.c` owns command-word interpolation acceptance and direct
  scalar function-call pre-materialization;
- shared format-spec parsing and supported-kind metadata remain in the shared
  interpolation contract;
- VM and Bash render only accepted interpolation payloads;
- direct scalar function calls in normal strings and quoted command words remain
  supported where the existing milestones support them;
- unsupported direct interpolation of arrays, maps, command results, stdoutful
  functions, unknown-return functions, and malformed calls is rejected before
  backend execution/emission;
- interpolated function calls are evaluated left-to-right before the outer
  command launches;
- failure in an interpolated function prevents the outer command from launching
  and preserves matching VM/Bash status/stderr behavior;
- returned shell metacharacters are passed as literal argument content, not
  reinterpreted by Bash;
- helper dependency scanning finds helpers required only by interpolated value
  calls, but emits each helper deterministically and at most once.

Do not expand command-word interpolation to structured values or arbitrary
command substitution.

### 4. Command-result composition audit

Audit command-result capture and command-result returns against environment and
interpolation behavior.

Required outcomes:

- captured command results and returned command results preserve the same field
  names and field semantics;
- `status` and `code` aliases remain consistent if both are supported;
- `ok` and `failed` remain boolean expressions and are not stringified until
  explicitly interpolated or exported;
- command-result fields can participate in supported interpolation and
  environment scalar assignment when a scalar field is selected;
- whole command-result values cannot be exported, interpolated, passed as scalar
  command words, or treated as maps;
- VM and Bash agree for stdout/stderr with trailing newlines, empty stdout,
  empty stderr, non-zero status, and captured pipelines.

### 5. Diagnostics ownership polish

Move or refine diagnostics so failures appear at the correct phase.

Required diagnostic ownership:

- lexer/parser own lexical and syntax-shape diagnostics only;
- lowerer owns semantic misuse, unsupported accepted syntax, value-kind checks,
  return-kind checks, invalid environment names/targets, unsupported
  interpolation forms, and VM/Bash parity gates;
- VM owns runtime data/OS/process failures and internal accepted-HIR invariant
  failures;
- Bash owns artifact/output failures and internal accepted-HIR invariant
  failures;
- checker owns warnings and presentation diagnostics, not hard language
  acceptance unless explicitly documented.

Specific diagnostics to verify:

- nested collection return rejected with a message naming the flat-return
  boundary;
- collection-valued environment assignment rejected;
- command-result-valued environment assignment rejected;
- invalid `env.NAME` target rejected;
- unsupported interpolation target rejected before backend work;
- stdout-producing value function rejected when used as an expression or direct
  interpolation value;
- unknown/mixed return-kind function rejected when used in value context;
- whole command-result interpolation rejected while scalar field interpolation
  remains supported;
- Bash/VM internal invariant messages are not the first user-facing error for
  ordinary unsupported source forms.

### 6. Generated Bash helper hygiene

Audit emitted Bash produced by the `v0.25` through `v0.27` behavior surface.

Required outcomes:

- generated Bash never invokes `ds`;
- helper names stay in the reserved `__ds_` namespace;
- value-return, structured-value, command-result, interpolation, environment,
  and quoting helpers are emitted deterministically;
- duplicate helper bodies are not emitted in one script;
- helper dependency scanning reaches into function bodies, return expressions,
  interpolation materialization, command-result storage, and environment
  assignments;
- scripts with no structured value-return/interpolation needs do not emit
  unnecessary helpers;
- Bash version guards appear only when needed by emitted Bash features;
- `bash -n` succeeds for every emitted supported fixture;
- generated Bash preserves literal shell metacharacters in returned/interpolated
  values and environment assignments.

### 7. Documentation and examples reconciliation

Update docs only where they are outdated or ambiguous.

Required docs to reconcile:

- `README.md`;
- `docs/status.md`;
- `docs/language.ds`;
- `docs/runtime.md`;
- `docs/parity-contracts.md`;
- `docs/diagnostics.md`;
- `docs/concept-map.md`;
- `docs/source-map.md`;
- `docs/technical-debt.md`, if cleanup reveals debt that should not be fixed in

- relevant examples.

Docs must clearly distinguish:

- supported scalar returns;
- supported flat collection returns;
- supported command-result returns;
- supported direct environment access/assignment/unset;
- supported scalar interpolation forms;
- rejected structured interpolation/export forms;
- deferred nested collections, map iteration, index assignment, recursive glob,
  and advanced regex behavior.

Examples should demonstrate real supported behavior and should not imply that
deferred nested collection or map-iteration syntax is available.

## Acceptance criteria

This milestone is complete when:

- `docs/milestones/v0.28.0-spec.md` and
  `docs/milestones/v0.28.0-test-plan.md` exist and match the roadmap scope;
- a dedicated `tests/v0_28/run.sh` suite exists and is wired into
  `make test-v0-28` and the aggregate `make test` target;
- the dedicated suite covers value-return protocol, direct environment behavior,
  direct scalar interpolation, command-result composition, diagnostics,
  generated-Bash helper hygiene, and docs/examples checks;
- full `v0.25`, `v0.26`, and `v0.27` regression suites still pass;
- VM and emitted Bash agree for all supported parity fixtures added in this
  milestone;
- unsupported/deferred nested collections, structured interpolation, invalid
  environment assignment, and invalid value-return forms fail before partial
  execution/emission;
- emitted Bash for supported fixtures passes `bash -n`, is standalone, and does
  not invoke `ds`;
- docs and examples no longer contradict the supported/deferred surface;
- any cleanup intentionally postponed is recorded in the deferred section or in
  `docs/technical-debt.md`.

## Completion review

Fill this section during implementation.

- Implementation summary: audited the v0.25.0 through v0.27.0 value-return,
  environment, command-result, and interpolation surface and fixed a Bash helper
  dependency gap for statement-style user function call arguments. The Bash
  dependency scanner now walks those argument expressions for formatted string
  interpolation helpers, integer helper use, collection index helper use, map
  literal helper use, and existing function-value helper use instead of treating
  statement calls as helper-free unless the call target itself was stdlib.
- Tests added: none in this implementation pass by request. Exploratory
  fixtures were run manually for statement-call arguments containing
  `{raw:trim}`, `{1 + 2}`, and `xs[0]`, and the existing v0.25.0, v0.26.0, and
  v0.27.0 focused suites were used as regression coverage.
- Docs updated: `docs/status.md`, `docs/runtime.md`, and `docs/source-map.md`
  now document the v0.28.0 cleanup pass and the HIR-walking responsibility of
  `src/bash_deps.c` for statement-call argument expressions.
- VM/Bash parity notes: the change affects emitted Bash helper availability
  only. VM behavior was already executing the lowered argument expressions
  directly. Emitted Bash now includes the same helper bodies for statement-call
  arguments that equivalent expressions already required in bindings,
  assignments, conditions, and returns.
- Generated Bash helper hygiene notes: helper emission remains deterministic and
  still emits each helper family through the existing centralized helper
  selection path. The fix prevents generated scripts from referencing helpers
  such as `__ds_string_trim`, `__ds_int_bin`, or `__ds_array_get` without also
  emitting their definitions.
- Diagnostics ownership notes: no source-language acceptance rules moved. The
  fix is backend helper discovery over already accepted HIR, so lowerer-owned
  diagnostics for invalid value kinds, invalid environment targets, invalid
  interpolation targets, and deferred structured forms remain unchanged.
- Behavior changes from earlier versions: supported statement-style user
  function calls with helper-needing argument expressions now emit standalone
  Bash that runs correctly instead of failing at shell runtime with missing
  helper definitions.
- Deferred items and rationale: the dedicated `tests/v0_28/run.sh` suite and
  `make test-v0-28` wiring are deferred only because this pass was explicitly
  requested without adding tests yet. Feature deferrals remain the roadmap
  deferrals listed above: map iteration, index assignment, recursive glob,
  advanced regex behavior, signal/job-control expansion, nested collections,
  collection-valued parameters, typed required parameters, typed return
  annotations, and broad iterator protocols.
- Technical debt recorded: no new technical-debt entry was added; this pass
  closed a localized helper dependency gap rather than exposing a broader source
  ownership problem that must be tracked separately.
