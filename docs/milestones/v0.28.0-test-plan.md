# v0.28.0 Test Plan — Cleanup: Value, Environment, and Interpolation Stabilization

## Purpose

Prove that the implementation surface introduced across `v0.25.0` through
`v0.27.0` behaves as one coherent, portable language contract before the roadmap
adds map iteration and index assignment.

This is a cleanup test plan. It must harden existing supported behavior and
clear rejection behavior. It must not require new production syntax.

The suite should prove:

```txt
value-returning functions preserve VM/Bash parity
flat structured returns remain flat and typed
command-result returns preserve field semantics
direct environment reads/assignments/unsets compose with function returns
direct scalar interpolation is ordered, quoted, and failure-safe
generated Bash is standalone and helper-hygienic
unsupported nested/structured forms fail before execution/emission
docs/examples describe the real supported/deferred surface
```

## Test suite location

The dedicated suite should live at:

```sh
tests/v0_28/run.sh
```

It should be wired into the normal targets:

```sh
make test-v0-28
make test
```

It should also be included in sanitizer runs when the project runs aggregate
sanitizer targets:

```sh
make test-asan
make test-ubsan
```

## Test conventions

Follow existing version-suite conventions:

- `set -euo pipefail`;
- private deterministic temp directories;
- no network access;
- no timing-sensitive tests;
- quote all temporary paths;
- normalize absolute temp paths only where unavoidable;
- use checked-in fixtures only when golden output or multi-file imports make
  that clearer than inline heredocs;
- keep each fixture small enough that failures identify one ownership boundary;
- run `bash -n` for every emitted Bash script;
- assert emitted Bash does not call `ds`;
- assert helper names stay under the reserved `__ds_` namespace;
- compare VM and Bash stdout, stderr, exit status, and deterministic side
  effects for every supported parity case;
- use lowerer/checker diagnostics for rejected source forms and verify failure
  happens before command side effects.

Recommended helper families:

- `write_fixture name source`;
- `run_vm file args...`;
- `emit_bash file out args...`;
- `run_bash out args...`;
- `assert_vm_bash_parity file args...`;
- `assert_check_fails file expected_stderr_substring`;
- `assert_emit_fails file expected_stderr_substring`;
- `assert_no_ds_call out.sh`;
- `assert_bash_helper_count out.sh helper_name expected_count`;
- `assert_no_side_effect path`;
- `assert_file_equals path expected`.

For VM/Bash parity cases:

1. Write the DS fixture.
2. Run `./ds fixture.ds`; capture stdout, stderr, and status.
3. Run `./ds emit bash fixture.ds -o out.sh`; assert success.
4. Run `bash -n out.sh`; assert success.
5. Assert `out.sh` does not contain an invocation of the `ds` binary.
6. Run `bash out.sh`; capture stdout, stderr, and status.
7. Compare stdout, stderr, status, and side-effect files.

For rejection cases:

1. Write the DS fixture.
2. Run `./ds check fixture.ds` or `./ds emit bash fixture.ds -o out.sh`, choosing
   the earliest public path that should expose the diagnostic.
3. Assert non-zero status.
4. Assert stderr contains the expected ownership-level message.
5. Assert side-effect marker files were not created.
6. Assert no partial emitted Bash artifact is treated as valid output.

### 2. Scalar value-return parity

#### 2.1 String return remains stdout-clean

Fixture:

```ds
fn artifact() {
  return "app.tar.gz"
}

let name = artifact()
echo "name={name}"
```

Expected stdout:

```txt
name=app.tar.gz
```

Assertions:

- VM/Bash stdout/stderr/status match;
- no extra stdout from the return transport appears;
- emitted Bash does not call `ds`.

#### 2.2 Integer return with arithmetic

Fixture:

```ds
fn base() {
  return 40
}

let total = base() + 2
echo total
```

Expected stdout:

```txt
42
```

Assertions:

- arithmetic uses integer kind, not string concatenation;
- VM and Bash overflow behavior remains checked by existing arithmetic helpers.

#### 2.3 Boolean return in condition and interpolation

Fixture:

```ds
fn enabled() {
  return true
}

if enabled() {
  echo "enabled={enabled()}"
}
```

Expected stdout:

```txt
enabled=true
```

Assertions:

- returned bool participates in conditions;
- interpolation stringifies bool canonically in both backends.

#### 2.4 Forward call return-kind discovery

Fixture:

```ds
fn outer() {
  return inner()
}

fn inner() {
  return "ok"
}

echo outer()
```

Expected stdout:

```txt
ok
```

Assertions:

- forward return-kind validation remains supported;
- VM/Bash parity holds.

#### 2.5 Mixed scalar return kinds rejected

Fixture:

```ds
fn bad(flag = true) {
  if flag {
    return "text"
  }
  return 7
}

echo bad()
```

Assertions:

- `ds check` fails;
- stderr mentions incompatible or mixed return kinds;
- no command side effects occur.

### 4. Command-result returns and composition

#### 4.1 Command-result return fields

Fixture:

```ds
fn captured() {
  let r = run sh "-c" "printf 'out'; printf 'err' >&2"
  return r
}

let r = captured()
echo "stdout={r.stdout}"
echo "stderr={r.stderr}"
echo "status={r.status}"
echo "ok={r.ok}"
echo "failed={r.failed}"
```

Expected stdout:

```txt
stdout=out
stderr=err
status=0
ok=true
failed=false
```

Assertions:

- stderr from the captured command is captured, not leaked;
- fields preserve documented names and kinds.

#### 4.2 Non-zero command-result return

Fixture:

```ds
fn captured() {
  let r = run sh "-c" "printf 'bad' >&2; exit 7"
  return r
}

let r = captured()
echo r.stdout
echo r.stderr
echo r.status
echo r.ok
echo r.failed
```

Expected stdout:

```txt

bad
7
false
true
```

Assertions:

- non-zero captured command does not fail the outer script merely because it is
  captured;
- VM/Bash status for the whole script remains successful unless explicitly
  failed later.

#### 4.3 Captured pipeline return

```txt

```

Assertions:

- emitted Bash uses standalone pipeline capture helpers.

#### 4.4 Whole command-result interpolation rejected

Assertions:

#### 4.5 Command-result scalar field interpolation accepted

#### 5.2 Assignment stringifies scalar returns

Expected stdout:

```txt

```

Assertions:

- string/int/bool environment assignment stringification matches interpolation;
- child command observes the updated environment.

#### 5.3 Assignment with shell metacharacters is literal

#### 5.4 Unset after assignment

### 6. Direct scalar interpolation ordering and quoting

#### 6.1 Scalar function call inside normal string

Fixture:

```ds
fn artifact() {
  return "api.tar.gz"
}

echo "artifact={artifact()}"
```

Expected stdout:

```txt
artifact=api.tar.gz
```

Assertions:

- normal string interpolation accepts scalar value calls;
- return transport stdout does not leak.

#### 6.2 Scalar function call inside quoted command word

Fixture:

```ds
fn artifact() {
  return "api.tar.gz"
}

run printf "%s\n" "file={artifact()}"
```

Expected stdout:

```txt
file=api.tar.gz
```

Assertions:

- command-word direct call is pre-materialized before command launch;
- VM/Bash stdout/stderr/status match.

#### 6.3 Multiple interpolated calls are left-to-right

Fixture:

```ds
env.DS_V028_ORDER = ""

fn first() {
  env.DS_V028_ORDER = "1"
  return "A"
}

fn second() {
  env.DS_V028_ORDER = "{env.DS_V028_ORDER}2"
  return "B"
}

run printf "%s\n" "{first()}-{second()}-{env.DS_V028_ORDER}"
```

Expected stdout:

```txt
A-B-12
```

Assertions:

- interpolation calls are evaluated left-to-right;
- environment side effects from earlier calls are visible to later calls.

#### 6.4 Failure prevents outer command launch

Fixture:

```ds
fn bad() {
  fail "boom"
  return "never"
}

run sh "-c" "touch should_not_exist; printf '%s\n' '{bad()}'"
```

Assertions:

- VM and emitted Bash both exit non-zero;
- stderr contains `boom` or the existing failure diagnostic;
- `should_not_exist` is not created;
- the outer command does not launch.

#### 6.5 Later interpolation not evaluated after earlier failure

Fixture:

```ds
fn bad() {
  fail "boom"
  return "never"
}

fn later() {
  env.DS_V028_LATER = "ran"
  return "later"
}

run printf "%s\n" "{bad()}-{later()}"
```

Assertions:

- VM and emitted Bash exit non-zero;
- `env.DS_V028_LATER` is not set by `later()`;
- failure ordering matches.

#### 6.6 Returned shell metacharacters are literal command argument content

Fixture:

```ds
fn meta() {
  return "a b; $(echo bad) *"
}

run printf "<%s>\n" "{meta()}"
```

Expected stdout:

```txt
<a b; $(echo bad) *>
```

Assertions:

- emitted Bash does not execute or glob the returned text;
- the result is one argument.

#### 6.7 Structured direct interpolation rejected

Fixtures:

```ds
fn names() {
  return ["api"]
}

echo "names={names()}"
```

```ds
fn config() {
  return {"name": "api"}
}

run printf "%s\n" "{config()}"
```

Assertions:

- `ds check` fails;
- stderr says only scalar value-returning calls are supported in interpolation;
- no backend internal invariant is shown first.

#### 6.8 Stdout-producing value function interpolation rejected

Fixture:

```ds

  echo "noise"
  return "value"
}

echo "x={noisy()}"
```

Assertions:

- `ds check` fails;

- no `noise` is printed.

### 9. Diagnostics ownership regression

Add focused negative tests for these cases:

- mixed return kinds;
- missing return on one value-function path;
- nested collection return;
- array/map/command-result environment assignment;
- invalid direct environment name;
- invalid unset target;
- whole command-result interpolation;
- direct array/map function-call interpolation;
- direct command-result function-call interpolation;
- stdout-producing value-call interpolation;
- unknown-return or mixed-return function used in interpolation;
- collection-valued command word without scalar field selection;
- map iteration attempted before `v0.29.0`;
- index assignment attempted before `v0.30.0`.

For each case:

- assert `ds check` or `ds emit bash` fails before execution;
- assert stderr contains a message naming the unsupported construct;
- assert stderr does not primarily expose a VM/Bash internal invariant for a
  normal user-facing unsupported form;
- assert marker side effects do not run.
