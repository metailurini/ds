# v0.29.0 Test Plan — Map Iteration

## Purpose

Prove that flat map iteration is deterministic, scoped, value-kind preserving,
and portable across VM execution and emitted standalone Bash.

This suite should verify:

```txt
for key, value in map iterates flat maps
iteration order is sorted by key and backend-independent
key variables are strings
value variables preserve scalar kinds
loop variables are body-scoped and collision-safe
break/continue/return interact with map loops correctly
unsupported iterable shapes fail before execution/emission
generated Bash is standalone and helper-hygienic
```

The suite must not require index assignment, nested collections, custom
iterators, recursive glob, regex captures/replacement, or signal/job-control
expansion.

## Test suite location

The dedicated suite should live at:

```sh
tests/v0_29/run.sh
```

It should be wired into the normal targets:

```sh
make test-v0-29
make test
```

It should also be included in sanitizer aggregate targets when the project runs
version suites under sanitizers:

```sh
make test-asan
make test-ubsan
```

## Test conventions

Follow existing version-suite conventions:

- `set -euo pipefail`;
- private deterministic temp directories;
- no network access;
- no timing-sensitive tests;
- no dependence on host locale ordering;
- quote every temporary path;
- keep fixtures small and single-purpose;
- prefer inline fixtures unless import/golden formatting makes checked-in files
  clearer;
- run `bash -n` for every emitted Bash script;
- assert emitted Bash does not call `ds`;
- assert generated helper names stay in the reserved `__ds_` namespace;
- compare VM and Bash stdout, stderr, exit status, and deterministic side
  effects for every accepted feature case;
- for rejections, assert the failure happens during `check` or `emit bash`
  before side effects;
- normalize absolute temp paths only where unavoidable.

Recommended helper families:

- `write_fixture name source`;
- `run_vm file args...`;
- `emit_bash file out args...`;
- `run_bash out args...`;
- `assert_vm_bash_parity file args...`;
- `assert_check_fails file expected_stderr_substring`;
- `assert_emit_fails file expected_stderr_substring`;
- `assert_no_ds_call out.sh`;
- `assert_contains file text`;
- `assert_not_contains file text`;
- `assert_bash_helper_present out.sh helper_name`;
- `assert_bash_helper_absent out.sh helper_name`;
- `assert_file_equals path expected`;
- `assert_no_side_effect path`.

For accepted parity cases:

1. Write the fixture.
2. Run `./ds fixture.ds`; capture stdout, stderr, and status.
3. Run `./ds emit bash fixture.ds -o out.sh`; assert success.
4. Run `bash -n out.sh`; assert success.
5. Assert `out.sh` does not contain an invocation of `ds`.
6. Run `bash out.sh`; capture stdout, stderr, and status.
7. Compare stdout, stderr, status, and side-effect files.

For rejected forms:

1. Write the fixture.
2. Run `./ds check fixture.ds` or `./ds emit bash fixture.ds -o out.sh`, choosing
   the earliest public path that should expose the diagnostic.
3. Assert non-zero status.
4. Assert stderr contains the expected ownership-level message.
5. Assert side-effect marker files were not created.
6. Assert no partial emitted Bash artifact is treated as valid output.

### 2. Basic map iteration parity

#### 2.1 Literal map bound to a name

Fixture:

```ds
let ports = {
  web: 5173,
  api: 3000,
  worker: 9000
}

for name, port in ports {
  echo "{name}:{port}"
}
```

Expected stdout:

```txt
api:3000
web:5173
worker:9000
```

Assertions:

- VM/Bash stdout/stderr/status match;
- keys are sorted, not insertion ordered;
- emitted Bash does not call `ds`;
- emitted Bash contains whatever map-loop sorting helper or inline sorting logic
  the implementation owns.

#### 2.2 String values preserve string kind

Fixture:

```ds
let labels = {
  b: "beta",
  a: "alpha"
}

for key, label in labels {
  echo "{key}={label.upper()}"
}
```

Expected stdout:

```txt
a=ALPHA
b=BETA
```

Assertions:

- string method inference works for the loop value;
- emitted Bash includes string helper dependencies only when needed.

#### 2.3 Boolean values preserve boolean kind

Fixture:

```ds
let flags = {
  slow: false,
  fast: true
}

for name, enabled in flags {
  if enabled {
    echo "{name}=on"
  } else {
    echo "{name}=off"
  }
}
```

Expected stdout:

```txt
fast=on
slow=off
```

Assertions:

- boolean truthiness is DS truthiness, not Bash non-empty-string truthiness;
- sorting still uses keys.

#### 2.4 Integer values preserve integer kind

Fixture:

```ds
let ports = {
  web: 5173,
  api: 3000
}

for name, port in ports {
  let next = port + 1
  echo "{name}:{next}"
}
```

Expected stdout:

```txt
api:3001
web:5174
```

Assertions:

- arithmetic accepts the loop value as an integer;
- overflow diagnostics remain unchanged if arithmetic overflows.

### 3. Ordering edge cases

#### 3.1 Numeric-looking keys sort lexically

Fixture:

```ds
let values = {
  "2": "two",
  "10": "ten",
  "1": "one"
}

for key, value in values {
  echo "{key}:{value}"
}
```

Expected stdout:

```txt
1:one
10:ten
2:two
```

Assertion: ordering is bytewise lexical, not numeric.

#### 3.2 Case-sensitive key sorting

Fixture:

```ds
let values = {
  b: "lower-b",
  A: "upper-a",
  a: "lower-a",
  B: "upper-b"
}

for key, value in values {
  echo "{key}:{value}"
}
```

Expected stdout for bytewise ASCII sorting:

```txt
A:upper-a
B:upper-b
a:lower-a
b:lower-b
```

Assertion: host locale does not change the order.

#### 3.3 Punctuation and underscore keys

Fixture:

```ds
let values = {
  "z": "zed",
  "a-b": "dash",
  "a_b": "underscore",
  "a.b": "dot"
}

for key, value in values {
  echo "{key}:{value}"
}
```

Expected stdout must match the documented bytewise order. The test should encode
that exact order after confirming the project's key spelling rules.

Assertions:

- quoted string keys bind exactly as stored;
- command/string interpolation prints the exact key.

#### 3.4 Duplicate key behavior remains existing behavior

Fixture:

```ds
let values = {
  api: 1,
  api: 2
}

for key, value in values {
  echo "{key}:{value}"
}
```

Expected behavior:

- if duplicate map keys are already rejected, assert the same diagnostic still
  occurs before iteration;
- if the current language keeps the final key, assert there is exactly one
  iteration for `api` and document that behavior.

Do not allow VM/Bash disagreement.

### 4. Function-returned maps

#### 4.1 Direct flat map return

Fixture:

```ds
fn ports() {
  return { web: 5173, api: 3000 }
}

for name, port in ports() {
  echo "{name}:{port}"
}
```

Expected stdout:

```txt
api:3000
web:5173
```

Assertions:

- the function call is evaluated once before the loop starts;
- value-return transport does not leak stdout;
- emitted Bash includes map-return and map-loop helper dependencies.

#### 4.2 Forwarded map return

Fixture:

```ds
fn base() {
  return { web: 5173, api: 3000 }
}

fn forwarded() {
  return base()
}

for name, port in forwarded() {
  echo "{name}:{port}"
}
```

Expected stdout:

```txt
api:3000
web:5173
```

Assertion: forwarding preserves map metadata needed by the loop.

#### 4.3 Function call iterable evaluates once

Fixture:

```ds
let calls = 0

fn data() {
  calls += 1
  return { b: 2, a: 1 }
}

for key, value in data() {
  echo "{key}:{value}"
}

echo "calls={calls}"
```

Expected stdout:

```txt
a:1
b:2
calls=1
```

Assertions:

- function call is not re-evaluated for every key;
- VM/Bash side effects match.

### 5. Scope and shadowing

#### 5.1 Loop variables do not leak

Fixture:

```ds
let ports = { api: 3000 }

for name, port in ports {
  echo "inside={name}:{port}"
}

echo name
```

Expected behavior:

- `ds check` fails if `name` is not defined after the loop;
- no command side effect after the invalid read occurs.

If the language has a specific undefined-variable diagnostic, assert that text.

#### 5.2 Loop variables shadow outer names only inside body

Fixture:

```ds
let name = "outer"
let port = 1
let ports = { api: 3000 }

for name, port in ports {
  echo "inside={name}:{port}"
}

echo "after={name}:{port}"
```

Expected stdout:

```txt
inside=api:3000
after=outer:1
```

Assertions:

- no outer variable mutation occurs;
- Bash temporary names do not collide with user variables.

#### 5.3 Reassigning loop variables does not mutate source map

Fixture:

```ds
let ports = { api: 3000, web: 5173 }

for name, port in ports {
  port += 1
  echo "loop={name}:{port}"
}

echo "after={ports.api}:{ports.web}"
```

Expected stdout:

```txt
loop=api:3001
loop=web:5174
after=3000:5173
```

Assertions:

- loop value binding is a scoped value, not a reference;
- source map is unchanged.

#### 5.4 Duplicate loop variable names are rejected

Fixture:

```ds
let ports = { api: 3000 }
for key, key in ports {
  echo key
}
```

Expected diagnostic: duplicate map loop variable names are not allowed.

### 6. Control flow inside map loops

#### 6.1 `continue` skips the current entry

Fixture:

```ds
let ports = { api: 3000, web: 5173, worker: 9000 }

for name, port in ports {
  if name == "web" { continue }
  echo "{name}:{port}"
}
```

Expected stdout:

```txt
api:3000
worker:9000
```

#### 6.2 `break` exits nearest map loop

Fixture:

```ds
let ports = { api: 3000, web: 5173, worker: 9000 }

for name, port in ports {
  if name == "web" { break }
  echo "{name}:{port}"
}

echo done
```

Expected stdout:

```txt
api:3000
done
```

#### 6.3 Nested map loops preserve nearest-loop behavior

Fixture:

```ds
let outer = { b: 2, a: 1 }
let inner = { y: 20, x: 10 }

for ok, ov in outer {
  for ik, iv in inner {
    if ik == "y" { break }
    echo "{ok}:{ik}:{ov}:{iv}"
  }
}
```

Expected stdout:

```txt
a:x:1:10
b:x:2:10
```

Assertions:

- inner `break` does not exit the outer loop;
- nested Bash temporaries are unique.

#### 6.4 Return from inside a map loop

Fixture:

```ds
fn find_port() {
  let ports = { api: 3000, web: 5173 }
  for name, port in ports {
    if name == "web" { return port }
  }
  return 0
}

echo "port={find_port()}"
```

Expected stdout:

```txt
port=5173
```

Assertions:

- value-return protocol survives loop control flow;
- emitted Bash returns through the existing function ABI.

### 8. Empty map behavior

```ds
let values = {}
```

```txt
done
```

### 10. Generated Bash helper hygiene

For representative accepted fixtures, assert:

- emitted Bash passes `bash -n`;
- emitted Bash does not invoke `ds`;
- emitted Bash includes a Bash 4+ guard when associative arrays are used;
- map-loop sorting helper is emitted exactly when map loops need it;
- map-loop sorting helper is not emitted for scripts with only array loops;
- string/int/collection helpers used inside loop bodies are emitted when needed;
- helper names use `__ds_`;
- no generated helper uses unquoted user-provided keys/values;
- `LC_ALL=C` or equivalent locale control is used for sorting if external sort
  is used;
- nested map loops do not reuse the same internal loop variable names in a way
  that breaks execution.

Suggested fixture for helper dependency recursion:

```ds
let values = { b: "beta", a: "alpha" }

for key, value in values {
  echo "{key}:{value.trim().upper()}"
}
```

Expected stdout:

```txt
a:ALPHA
b:BETA
```

### 12. Rejection tests: wrong iterable kind

#### 12.1 One-name loop over a map is rejected

Fixture:

```ds
let ports = { api: 3000 }
for item in ports {
  echo item
}
```

Expected diagnostic: map iteration requires `for key, value in map` or equivalent
specific wording.

#### 12.2 Two-name loop over an array is rejected

Fixture:

```ds
let items = ["api", "web"]
for index, item in items {
  echo item
}
```

Expected diagnostic: array loops use `for item in array`.

#### 12.3 Two-name loop over scalar values is rejected

Fixtures:

```ds
let value = "not-map"
for key, item in value { echo item }
```

```ds
let value = 42
for key, item in value { echo item }
```

```ds
let value = true
for key, item in value { echo item }
```

Expected diagnostic: map loop iterable must be a map.

#### 12.4 Command result is not a map

Fixture:

```ds
let result = run "printf" "hello"
for key, value in result {
  echo "{key}:{value}"
}
```

Expected diagnostic: command-result objects are not map iterables.

#### 12.5 Environment namespace/value is not a map

Fixtures:

```ds
for key, value in env {
  echo key
}
```

```ds
for key, value in env.PATH {
  echo value
}
```

Expected diagnostics: environment iteration is unsupported; `env.NAME` is a
string value, not a map.
