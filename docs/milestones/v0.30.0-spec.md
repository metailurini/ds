# v0.30.0 Spec — Index Assignment

## Status

Planned. This is the next unwritten roadmap milestone after
`v0.29.0 — Map Iteration`.

`v0.30.0` adds the first controlled collection mutation surface after flat
collection values and deterministic map traversal are specified. It must keep the
existing VM/Bash parity contract: every accepted mutation must execute in VM mode
and emit to standalone Bash with matching stdout, stderr, exit status, and side
effects.

## Goal

Add portable, explicit assignment to elements of named flat arrays and named flat
maps.

By the end of this milestone:

- named array elements can be replaced with scalar values by index;
- named map entries can be created or replaced with scalar values by string key;
- mutation updates the collection stored in that named variable for later reads,
  loops, interpolation, assertions, and function returns;
- array assignment validates integer indexes and bounds consistently across VM
  and emitted Bash;
- map assignment validates key/value portability consistently across VM and
  emitted Bash;
- unsupported temporaries, function-call results, command-result fields,
  environment values, nested collections, and alias/reference-like targets fail
  before execution or emission;
- generated Bash remains standalone, helper-hygienic, and sidecar-correct.

The core product rules remain unchanged:

```txt
every supported production feature runs in the VM
every supported production feature emits standalone Bash
generated Bash is standalone and must not call ds
VM and emitted Bash behavior match for stdout, stderr, exit status, and side effects
unsupported or deferred forms fail clearly before partial execution/emission
the lowerer owns language/parity gates; backends consume accepted HIR
```

## Motivation

Collections are currently useful for construction, indexing, array loops,
selected helper mutation such as `array.push`, flat structured returns, and the
planned `v0.29.0` map iteration surface. Scripts still cannot directly replace a
specific array element or write a map entry with ordinary assignment syntax.

This creates awkward workarounds:

```ds
let labels = ["old", "keep"]
# wanted: labels[0] = "new"

let ports = { api: 3000 }
# wanted: ports["web"] = 5173
```

`v0.30.0` introduces that mutation deliberately, but only for named flat
collections. It must not smuggle in reference semantics, nested mutation,
temporary collection mutation, sparse arrays, or general object updates. Those
choices have VM and Bash consequences and need their own later contracts.

## Non-goals

This version does not include:

- assignment into array or map literals;
- assignment into function-call results;
- assignment into command-result fields;
- assignment into environment values through collection syntax;
- assignment into nested arrays or nested maps;
- slice assignment;
- sparse array creation;
- aliasing or reference semantics;
- destructuring assignment;
- compound index assignment such as `items[0] += 1` unless already supported by
  the scalar assignment machinery without new semantics;
- map deletion or array deletion;
- custom iterator or collection protocol changes;
- recursive glob patterns, advanced regex features, or signal/job-control work.

Treat `v0.29.0` as the latest planned collection traversal surface. Do not
implement `v0.31.0` recursive glob patterns, `v0.32.0` regex
captures/replacement/runtime regex strings, or `v0.34.0+` signal/job-control
work while implementing this version.

## Required feature work

### 1. Assignment syntax

Add support for these assignment targets:

```ds
items[0] = "first"
items[i] = "chosen"
ports["api"] = 3000
ports[name] = port
```

Required behavior:

- the left side must be a bracket index expression whose base is a named
  collection variable;
- the base name must resolve to a mutable local/script variable containing a
  flat array or flat map;
- the right side uses the existing expression grammar;
- the statement uses the existing assignment statement position, not expression
  assignment;
- source spans for the base, index/key expression, right-hand expression, and
  full assignment are preserved for diagnostics, AST output, HIR output,
  bytecode output, and formatter behavior;
- whitespace around brackets and `=` follows existing formatter conventions;
- existing scalar assignment, environment assignment, read-only indexing, array
  loops, map loops, and `array.push` keep their current behavior.

The implementation may parse the left side as a general assignment target and
reject unsupported target shapes during lowering, or it may keep syntax-level
rejection for forms that have no useful AST representation. In either case,
accepted index assignment must lower to an explicit HIR mutation node rather than
being rediscovered by the VM or Bash emitter from raw AST text.

### 2. Array element assignment

Support replacing an existing element in a named flat array:

```ds
let items = ["old", "keep"]
items[0] = "new"
echo items[0]
```

Required behavior:

- array indexes are zero-based;
- the index may be an integer literal or a named integer variable if that is the
  current portable indexing surface;
- if read-only indexing still rejects computed indexes, index assignment should
  follow the same portability boundary unless this milestone explicitly expands
  both read and write support together;
- negative indexes are rejected or fail with the same public behavior in VM and
  Bash;
- indexes greater than or equal to the current array length fail consistently;
- assigning at exactly `len(array)` is rejected in this milestone and must not
  append; use `array.push` for append behavior;
- successful assignment updates the stored element for later reads and loops;
- assigning to a loop variable that contains a scalar copy does not mutate the
  original array;
- array element values must stay within the flat scalar collection boundary.

Runtime bounds failures are data failures for accepted dynamic indexes. Statically
impossible forms, unsupported index kinds, and invalid targets remain frontend or
lowerer-owned diagnostics.

### 3. Map entry assignment

Support setting string-keyed entries on a named flat map:

```ds
let ports = { api: 3000 }
ports["api"] = 3001
ports["web"] = 5173
```

Required behavior:

- string keys are supported;
- named string variables may be used as keys if read-only map indexing already
  supports that shape portably;
- writing an existing key replaces that key's value;
- writing a new key inserts that key;
- later reads, map iteration, interpolation, and function returns observe the
  updated value;
- map iteration order remains the `v0.29.0` deterministic sorted-key order after
  mutation;
- empty keys remain rejected if map literals and map indexing already reject
  them for portability;
- non-string keys are rejected unless the project has already normalized map keys
  to strings in a documented, portable way;
- nested collection values remain rejected;
- assigning to field syntax such as `ports.api = 3000` is deferred unless this
  milestone's implementation deliberately maps it to the same HIR mutation node
  with identical diagnostics and parity.

The default v0.30 contract is bracket map assignment. Field-style map assignment
is allowed only if the implementation can prove it is equivalent, unambiguous
with environment field assignment, and documented before release. Otherwise it
must remain rejected with a diagnostic that points users to bracket syntax.

### 4. Right-hand value rules

Accepted right-hand values are flat scalar values already supported inside
portable collections:

- strings;
- integers;
- booleans;
- scalar variables;
- scalar function calls;
- scalar stdlib calls;
- scalar field/index reads that are already accepted by the lowerer;
- scalar interpolation expressions that already have defined behavior.

Rejected right-hand values include:

- arrays;
- maps;
- command-result values;
- functions returning arrays, maps, or command results;
- unsupported captured command payloads;
- nested collection literals;
- values whose kind is unknown at lowering time and cannot be represented by the
  Bash sidecar protocol.

If the project already has a documented dynamic value-kind transport for flat
collection assignment, this milestone may reuse it. Otherwise, keep the accepted
surface conservative and require lowerer-known scalar kinds.

### 5. Mutation scope and ownership

Index assignment mutates the named collection variable in the current mutable
scope.

Required behavior:

- local variables inside a function or test block mutate that local collection;
- script-level variables mutate the script-level collection;
- loop-body assignments to outer named collections persist after the loop;
- assignment to a collection declared inside the loop body does not leak that
  collection outside the loop;
- assigning through a shadowing variable mutates the nearest visible binding;
- imported modules preserve their existing symbol visibility model;
- function parameters remain immutable or unsupported as collection mutation
  targets unless the language already has by-reference parameter semantics;
- mutation of captured or copied function-return values is rejected unless first
  assigned to a named mutable variable.

There are no aliases or references in this milestone. If two variables are made
from the same literal or return value, mutating one must not accidentally mutate
the other unless the language has already documented shared collection identity.

### 6. Interaction with loops

Index assignment must compose with existing and planned loop behavior:

- assigning array elements inside `for item in array` is allowed only when the
  target is a named array, not the scalar loop variable;
- assigning map entries inside `for key, value in map` is allowed only when the
  implementation defines mutation-during-iteration behavior consistently;
- the default v0.30 rule is: mutating the currently iterated map during a map
  loop is rejected, preserving the `v0.29.0` snapshot contract;
- mutating a different map inside a map loop is allowed if it preserves parity;
- mutating an array inside a map loop or while loop is allowed if the target is a
  named array and normal bounds rules pass;
- `break`, `continue`, `return`, `fail`, and `exit` keep their existing control
  behavior after successful mutations before the control transfer.

If the implementation chooses to support safe same-map mutation during iteration,
it must document whether iteration uses a snapshot or sees inserted keys. The
preferred contract is to keep same-map mutation rejected until a later milestone.

### 7. Invalid assignment targets

Reject unsupported targets clearly:

```ds
["a", "b"][0] = "x"
make_items()[0] = "x"
result.stdout[0] = "x"
env.PATH[0] = "x"
items[0][1] = "x"
ports.api = 3000       # deferred unless explicitly accepted
items[-1] = "x"
items[2] = "x"        # for a two-element array
items[0] += 1          # deferred unless explicitly accepted
```

Diagnostic expectations:

- malformed assignment syntax belongs to the parser;
- invalid target shape belongs to the parser or lowerer depending on whether an
  AST target can be represented;
- unknown names, immutable names, wrong collection kind, unsupported temporary
  targets, nested targets, and nonportable RHS kinds belong to the lowerer;
- dynamic bounds/key data failures for accepted operations belong to the VM or
  generated Bash runtime helper;
- Bash emitter diagnostics are limited to artifact failures and internal
  accepted-HIR invariant defenses.

Diagnostics should name the unsupported target and the supported form, for
example: `index assignment requires a named array or map target`.

### 8. HIR and value-kind model

Add or use explicit HIR for collection mutation.

The HIR must preserve:

- target collection name and symbol identity;
- collection kind: array or map;
- index/key expression;
- right-hand expression;
- expected right-hand value kind where known;
- source span for the full assignment and meaningful child spans;
- mutation result as statement-only behavior, not an expression value.

Backends must not infer mutation semantics from AST. The HIR is the contract that
states a target is mutable, portable, and accepted.

### 9. VM behavior

The VM must:

- evaluate the index/key expression before evaluating or committing the mutation,
  following the project's existing assignment evaluation order;
- evaluate the right-hand expression once;
- validate array bounds before replacing an element;
- validate map key strings before inserting/replacing an entry;
- preserve scalar value kinds inside collection storage;
- update subsequent reads and loops from the same named collection;
- avoid leaking partially written values when an index/key or RHS evaluation
  fails;
- report runtime data failures with source-aware diagnostics where available;
- keep unrelated collections unchanged on failure.

### 10. Bash emission behavior

Generated Bash must:

- remain standalone and never call `ds`;
- use Bash arrays for arrays and Bash associative arrays for maps consistently
  with existing collection emission;
- emit a Bash 4+ guard when associative arrays are required;
- quote indexes, keys, and values safely;
- check array bounds before mutation and report the same public failure contract
  as the VM;
- update collection value sidecars so later reads, interpolation, conditionals,
  map iteration, and function returns observe correct scalar kinds;
- avoid stale sidecar entries when map values are replaced;
- add helper definitions only when required by accepted HIR;
- reserve internal names under `__ds_`;
- avoid collisions in nested loops, functions, imports, and tests;
- pass `bash -n`.

If helper functions such as `__ds_array_set` or `__ds_map_set` are added, they
belong to the generated Bash helper layer. Dependency scanning must include them
only for programs that require index assignment or sidecar updates.

### 11. Formatter, AST, HIR, and bytecode/debug output

Public tooling must remain coherent:

- `ds tokens` should not require unnecessary new tokens;
- `ds ast` should show index-assignment targets distinctly from scalar
  assignment;
- `ds hir` should show collection mutation as an accepted HIR statement;
- `ds bytecode` should show stable mutation operations if bytecode has distinct
  instructions;
- `ds fmt` should preserve bracket assignment and normalize whitespace;
- formatter output must remain idempotent;
- `ds check` should report unsupported mutation forms before VM/Bash backend
  selection.

### 12. Documentation updates

Update docs only where they become outdated:

- `docs/status.md` should move index assignment from deferred to supported after
  implementation;
- `docs/language.ds` should show supported bracket assignment examples and keep
  field-style assignment/nested mutation deferred unless implemented;
- `docs/runtime.md` should describe array bounds behavior, map insert/replace
  behavior, sidecar updates, and Bash helper requirements;
- `docs/parity-contracts.md` should mention collection mutation as an accepted
  VM/Bash parity surface;
- `docs/diagnostics.md` should update assignment-target ownership if the current
  wording becomes stale;
- `docs/concept-map.md` and `docs/source-map.md` should move index assignment
  from rejected/deferred to its implemented concept home;
- examples may use index assignment only after implementation is complete.

Do not update docs to imply nested collections, sparse arrays, slice assignment,
aliasing, field-style map assignment, or mutation of temporaries are supported
unless those features are explicitly implemented and tested in this milestone.

## Acceptance criteria

`v0.30.0` is complete when:

- array element assignment parses, lowers, executes in VM mode, and emits
  standalone Bash;
- map entry assignment parses, lowers, executes in VM mode, and emits standalone
  Bash;
- VM/Bash parity holds for stdout, stderr, exit status, and side effects;
- array bounds, map keys, RHS value kinds, and unsupported targets produce clear
  diagnostics at the correct ownership layer;
- collection value-kind sidecars stay correct after replacement/insertion;
- mutation composes with reads, interpolation, loops, functions, imports, tests,
  and value returns within the scoped flat-collection boundary;
- emitted Bash passes `bash -n`, does not call `ds`, and includes only required
  helpers;
- docs accurately describe supported index assignment and still defer nested
  mutation, sparse arrays, recursive glob, advanced regex, and signal/job-control
  work;
- the dedicated v0.30 test suite passes and is wired into aggregate tests.

## Deferred to later milestones

- Recursive glob patterns: `v0.31.0`.
- Regex captures, replacement, and runtime regex strings: `v0.32.0`.
- Cleanup across collection/glob/regex behavior: `v0.33.0`.
- Richer signal/job-control behavior: `v0.34.0+`.
- Nested collection traversal/mutation: future milestone after flat collection
  mutation semantics are stable.
- Sparse arrays, slice assignment, deletion, references/aliases, destructuring,
  custom iterators, and field-style map assignment unless explicitly added to a
  future roadmap entry.
