# v0.30.0 Test Plan — Index Assignment

## Purpose

Prove that named flat array and map index assignment is portable, scoped,
sidecar-correct, and deterministic across VM execution and emitted standalone
Bash.

This suite should verify:

```txt
items[index] = scalar replaces existing array elements
maps[key] = scalar replaces existing map entries
maps[key] = scalar inserts new map entries
mutation updates later reads, loops, interpolation, assertions, and returns
array bounds behavior matches VM/Bash
map key behavior matches VM/Bash
unsupported mutation targets fail before execution/emission
nested collection mutation remains rejected
generated Bash is standalone and helper-hygienic
```

The suite must not require sparse arrays, slice assignment, deletion,
references/aliases, nested collections, recursive glob, advanced regex, or
signal/job-control expansion.

## Test suite location

The dedicated suite should live at:

```sh
tests/v0_30/run.sh
```

It should be wired into the normal targets:

```sh
make test-v0-30
make test
```

It should also be included in sanitizer aggregate targets when the project runs
version suites under sanitizers:

```sh
make test-asan
make test-ubsan
```

## Test conventions

Follow existing version-suite conventions:

- `set -euo pipefail`;
- private deterministic temp directories;
- no network access;
- no timing-sensitive tests;
- no dependence on host locale ordering;
- quote every temporary path;
- keep fixtures small and single-purpose;
- prefer inline fixtures unless import/golden formatting makes checked-in files
  clearer;
- run `bash -n` for every emitted Bash script;
- assert emitted Bash does not call `ds`;
- assert generated helper names stay in the reserved `__ds_` namespace;
- compare VM and Bash stdout, stderr, exit status, and deterministic side effects
  for every accepted feature case;
- for rejections, assert failure happens during `check` or `emit bash` before
  side effects;
- normalize absolute temp paths only where unavoidable.

Recommended helper families:

- `write_fixture name source`;
- `run_vm file args...`;
- `emit_bash file out args...`;
- `run_bash out args...`;
- `assert_vm_bash_parity file args...`;
- `assert_check_fails file expected_stderr_substring`;
- `assert_emit_fails file expected_stderr_substring`;
- `assert_no_ds_call out.sh`;
- `assert_contains file text`;
- `assert_not_contains file text`;
- `assert_bash_helper_present out.sh helper_name`;
- `assert_bash_helper_absent out.sh helper_name`;
- `assert_file_equals path expected`;
- `assert_no_side_effect path`.

For accepted parity cases:

1. Write the fixture.
2. Run `./ds fixture.ds`; capture stdout, stderr, and status.
3. Run `./ds emit bash fixture.ds -o out.sh`; assert success.
4. Run `bash -n out.sh`; assert success.
5. Assert `out.sh` does not contain an invocation of `ds`.
6. Run `bash out.sh`; capture stdout, stderr, and status.
7. Compare stdout, stderr, status, and side-effect files.

For rejected forms:

1. Write the fixture.
2. Run `./ds check fixture.ds` or `./ds emit bash fixture.ds -o out.sh`, choosing
   the earliest public path that should expose the diagnostic.
3. Assert non-zero status.
4. Assert stderr contains the expected ownership-level message.
5. Assert side-effect marker files were not created.
6. Assert no partial emitted Bash artifact is treated as valid output.

After implementation, assert docs contain the current contract:

- index assignment is supported in v0.30;
- array syntax is `items[index] = scalar`;
- map syntax is `map[key] = scalar`;
- array assignment replaces existing elements only and does not append;
- map assignment replaces existing keys and inserts new keys;
- mutation targets must be named flat collections;
- RHS values must stay within the flat scalar collection boundary;
- generated Bash remains standalone and must not call `ds`;
- temporary mutation, function-call result mutation, command-result mutation,
  nested mutation, sparse arrays, slice assignment, deletion, references, and
  field-style map assignment remain deferred unless explicitly implemented.

### 2. Basic array assignment parity

#### 2.1 Replace first element

Fixture:

```ds
let items = ["old", "keep"]
items[0] = "new"
echo items[0]
echo items[1]
```

Expected stdout:

```txt
new
keep
```

Assertions:

- VM/Bash stdout/stderr/status match;
- emitted Bash does not call `ds`;
- later array reads observe the replacement.

#### 2.2 Replace last element

Fixture:

```ds
let items = ["a", "b", "c"]
items[2] = "z"
for item in items {
  echo item
}
```

Expected stdout:

```txt
a
b
z
```

Assertions:

- loop traversal observes the updated element;
- no append occurs.

#### 2.3 Index from named integer variable

Fixture:

```ds
let items = ["a", "b", "c"]
let i = 1
items[i] = "B"
echo items[1]
```

Expected stdout:

```txt
B
```

If named-variable indexes are still outside the accepted read-only indexing
surface, this test becomes a rejection test instead and the docs must say so.

#### 2.4 Integer RHS preserves integer kind

Fixture:

```ds
let nums = [1, 2, 3]
nums[1] = 40 + 2
assert nums[1] == 42
echo nums[1]
```

Expected stdout:

```txt
42
```

Assertions:

- arithmetic RHS evaluates once;
- element kind remains integer;
- assertions and interpolation see an integer value.

#### 2.5 Boolean RHS preserves boolean kind

Fixture:

```ds
let flags = [false, false]
flags[1] = true
if flags[1] {
  echo "enabled"
} else {
  echo "disabled"
}
```

Expected stdout:

```txt
enabled
```

Assertions:

- boolean sidecar/kind metadata updates correctly in Bash;
- VM/Bash condition behavior matches.

### 3. Basic map assignment parity

#### 3.1 Replace existing map key

Fixture:

```ds
let ports = { api: 3000, web: 5173 }
ports["api"] = 3001
echo ports["api"]
echo ports["web"]
```

Expected stdout:

```txt
3001
5173
```

#### 3.2 Insert new map key

Fixture:

```ds
let ports = { api: 3000 }
ports["web"] = 5173
echo ports["api"]
echo ports["web"]
```

Expected stdout:

```txt
3000
5173
```

Assertions:

- insertion is supported for maps;
- emitted Bash includes any associative-array guard required by existing map
  behavior;
- sidecar metadata exists for the new key.

#### 3.3 Key from named string variable

Fixture:

```ds
let ports = { api: 3000 }
let name = "worker"
ports[name] = 9000
echo ports["worker"]
```

Expected stdout:

```txt
9000
```

If named-variable keys are still outside the accepted read-only map indexing
surface, this becomes a rejection test and docs must explicitly keep key
expressions conservative.

#### 3.4 Map iteration after mutation

Fixture:

```ds
let ports = { web: 5173 }
ports["api"] = 3000
ports["worker"] = 9000
for name, port in ports {
  echo "{name}:{port}"
}
```

Expected stdout:

```txt
api:3000
web:5173
worker:9000
```

Assertions:

- inserted keys participate in deterministic sorted map iteration;
- map iteration order remains bytewise/ASCII sorted per v0.29;
- VM/Bash behavior does not depend on host locale.

#### 3.5 Map value kind replacement

Fixture:

```ds
let flags = { fast: false }
flags["fast"] = true
if flags["fast"] {
  echo "on"
}
```

Expected stdout:

```txt
on
```

Assertions:

- replacing a map value updates kind sidecars;
- no stale false/string sidecar remains in emitted Bash.

### 4. Mutation composition

#### 4.1 Assignment inside while loop

Fixture:

```ds
let items = ["a", "b", "c"]
let i = 0
while i < 3 {
  items[i] = "x"
  i += 1
}
for item in items {
  echo item
}
```

Expected stdout:

```txt
x
x
x
```

If computed/named indexes are rejected, use three literal assignment statements
for the accepted test and keep this as a rejection/roadmap test.

#### 4.2 Assignment inside array loop to separate target

Fixture:

```ds
let items = ["a", "b"]
let out = ["", ""]
let i = 0
for item in items {
  out[i] = item.upper()
  i += 1
}
for value in out {
  echo value
}
```

Expected stdout:

```txt
A
B
```

Assertions:

- loop variable scalar values can be assigned into another collection;
- loop scoping does not collide with Bash temporaries.

#### 4.3 Assignment inside function persists locally and returns updated collection

Fixture:

```ds
fn build() {
  let xs = ["a", "b"]
  xs[1] = "B"
  return xs
}

let result = build()
echo result[1]
```

Expected stdout:

```txt
B
```

Assertions:

- function-local mutation is reflected in the returned flat collection;
- value-return ABI and Bash sidecars carry the updated value.

#### 4.4 Mutation does not create aliasing by accident

Fixture:

```ds
let a = ["x", "y"]
let b = ["x", "y"]
a[0] = "A"
echo a[0]
echo b[0]
```

Expected stdout:

```txt
A
x
```

Assertions:

- independent collections stay independent;
- no Bash variable-name reuse corrupts another collection.

#### 4.5 Interpolation after mutation

Fixture:

```ds
let xs = ["old"]
xs[0] = "new"
echo "value={xs[0]}"
```

Expected stdout:

```txt
value=new
```

Assertions:

- interpolation reads the updated collection value;
- helper dependency scanning includes any required index/interpolation helpers.

### 5. Bounds and runtime-data failures

#### 5.1 Out-of-range positive array index

Fixture:

```ds
let xs = ["a", "b"]
xs[2] = "c"
echo "unreachable"
```

Expected:

- non-zero status;
- stderr mentions array index out of range or equivalent public diagnostic;
- stdout does not contain `unreachable`;
- VM/Bash status and diagnostic class match.

#### 5.2 Negative array index

Fixture:

```ds
let xs = ["a"]
xs[-1] = "x"
```

Expected:

- either lowerer rejection or matching VM/Bash runtime failure;
- diagnostic explicitly rejects negative indexes;
- no mutation occurs.

#### 5.3 Append-by-assignment rejected

Fixture:

```ds
let xs = ["a", "b"]
xs[2] = "c"
```

Expected:

- rejected/fails as out of range;
- docs point users to `array.push` for append behavior.

#### 5.4 Failed assignment leaves collection unchanged before later side effects

Fixture shape:

```ds
let marker = "TMP_MARKER_PATH"
let xs = ["a"]
xs[5] = "bad"
touch $marker
```

Expected:

- non-zero status;
- marker file is not created;
- emitted Bash does not continue after failed bounds validation.

### 6. Rejected targets and value kinds

Each case should assert `ds check` or `ds emit bash` fails before execution and
side effects.

#### 6.1 Temporary array literal target

```ds
["a", "b"][0] = "x"
```

Expected diagnostic: index assignment requires a named collection target.

#### 6.2 Function-call result target

```ds
fn xs() {
  return ["a", "b"]
}
xs()[0] = "x"
```

Expected diagnostic: cannot assign into a function-call result or temporary.

#### 6.3 Command-result field target

```ds
let r = $(echo hi)
r.stdout[0] = "x"
```

Expected diagnostic: command-result fields are not mutable collection targets.

#### 6.4 Environment field target through index assignment

```ds
env.PATH[0] = "x"
```

Expected diagnostic: environment values are scalar strings, not mutable arrays.

#### 6.5 Nested collection target

```ds
let xs = [["a"]]
xs[0][0] = "x"
```

Expected diagnostic: nested collections/mutation are unsupported. If nested
collection literals are already rejected earlier, assert that earlier diagnostic.

#### 6.6 Map field-style assignment remains rejected unless implemented

```ds
let ports = { api: 3000 }
ports.api = 3001
```

Expected diagnostic: use bracket map assignment or field assignment is deferred.
If field-style assignment is implemented, this test must move to accepted parity
coverage and all docs must describe it.

#### 6.7 Compound index assignment rejected unless implemented

```ds
let xs = [1]
xs[0] += 1
```

Expected diagnostic: compound index assignment is unsupported. If implemented,
add parity tests for `+=`, `-=`, string concatenation rules if any, and overflow
behavior.

#### 6.8 RHS array rejected

```ds
let xs = ["a"]
xs[0] = ["nested"]
```

Expected diagnostic: collection element assignment accepts scalar values only.

#### 6.9 RHS map rejected

```ds
let m = { a: 1 }
m["a"] = { nested: 1 }
```

Expected diagnostic: map values remain flat scalar values only.

#### 6.10 RHS command result rejected

```ds
let xs = ["a"]
xs[0] = $(echo hi)
```

Expected diagnostic: command-result values cannot be stored as collection scalar
elements.

#### 6.11 Wrong collection kind for index/key

Fixtures:

```ds
let xs = ["a"]
xs["name"] = "x"
```

```ds
let m = { a: 1 }
m[0] = 2
```

Expected diagnostics:

- array indexes must be integers;
- map keys must be strings or supported string-like names.

#### 6.12 Unknown or immutable target

Fixtures:

```ds
missing[0] = "x"
```

```ds
fn f(param) {
  param[0] = "x"
}
```

Expected diagnostics:

- unknown target name;
- parameter mutation rejected unless parameters are already mutable collection
  bindings with a documented parity contract.

### 7. Same-map mutation during iteration

Default rejection fixture:

```ds
let ports = { api: 3000 }
for name, port in ports {
  ports["web"] = 5173
}
```

Expected:

- lowerer rejection if the target is statically known to be the same map being
  iterated;
- diagnostic mentions mutation during map iteration is unsupported/deferred;
- no partial execution/emission.

Allowed different-map fixture:

```ds
let src = { api: 3000, web: 5173 }
let dst = { seed: 1 }
for name, port in src {
  dst[name] = port
}
for name, port in dst {
  echo "{name}:{port}"
}
```

Expected stdout:

```txt
api:3000
seed:1
web:5173
```

If same-map mutation is deliberately supported instead, replace the rejection
with tests that prove the documented snapshot/visibility behavior exactly.

### 8. Formatter and debug-output coverage

Add fixtures for:

- `ds fmt` normalizes `items [ 0 ] = "x"` if such spacing parses;
- `ds fmt` is idempotent for array and map assignment;
- `ds ast` shows the assignment target base and index/key;
- `ds hir` shows an explicit collection mutation statement;
- `ds bytecode` remains stable and human-readable for accepted mutations;
- malformed targets produce clear parser/lowerer diagnostics.

Do not assert brittle full debug dumps unless the project already does. Prefer
checking stable substrings such as target names, index/key expressions, and HIR
node names.

### 9. Generated Bash helper hygiene

For representative emitted scripts, assert:

- `bash -n out.sh` succeeds;
- output script does not contain `./ds`, ` ds `, or an absolute path to the local
  compiler;
- array-only assignment does not emit map-only helpers or Bash associative-array
  guards;
- map assignment emits the associative-array guard and only required map helpers;
- helper definitions are not duplicated;
- sidecar variables use reserved `__ds_` names and avoid user-name collisions;
- nested functions/imports/tests do not reuse temporary names unsafely.

Suggested fixtures:

- array assignment with no maps: assert no Bash 4 associative-array guard;
- map assignment with no array mutation: assert required map helper/guard only;
- assignment followed by interpolation: assert helper dependency discovery covers
  both assignment and interpolation;
- assignment inside imported function: assert bundled Bash remains standalone.
