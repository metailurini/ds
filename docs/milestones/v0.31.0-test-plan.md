# v0.31.0 Test Plan — Recursive Glob Patterns

## Purpose

Prove that recursive `**` patterns in `glob` and `glob!` are deterministic,
portable, helper-hygienic, and consistent across VM execution and emitted
standalone Bash.

This suite should verify:

```txt
glob("**/*.ds") supports zero-or-more directory segments
glob!("src/**/*.ds") preserves required-match failure semantics
recursive results are sorted, duplicate-free, and string-kind preserving
dotfile, hidden-directory, symlink, spaces, leading-dash, and no-match behavior is defined
invalid literal recursive patterns fail before execution/emission
invalid dynamic recursive patterns fail at runtime in both VM and emitted Bash
generated Bash is standalone, helper-hygienic, and does not rely on ambient shell options
```

The suite must not require custom glob flags, multiple recursive `**` segments,
brace expansion, extglob, shell expansion inside patterns, streaming iterators,
regex captures/replacement/runtime strings, or v0.33 cleanup work.

## Test suite location

The dedicated suite should live at:

```sh
tests/v0_31/run.sh
```

It should be wired into the normal targets:

## Test conventions

Follow existing version-suite conventions:

- `set -euo pipefail`;
- private deterministic temp directories;
- no network access;
- no timing-sensitive tests;
- no dependence on host locale ordering;
- quote every temporary path;
- create all glob fixtures under a controlled temp tree;
- prefer ASCII file names for ordering tests and add separate path-quoting cases
  for spaces/leading dashes;
- avoid relying on platform-specific symlink permissions unless the suite can
  skip symlink cases cleanly when symlink creation is unavailable;
- run `bash -n` for every emitted Bash script;
- assert emitted Bash does not call `ds`;
- assert recursive-glob helpers stay in the reserved `__ds_` namespace;
- compare VM and Bash stdout, stderr, exit status, and deterministic side effects
  for every accepted feature case;
- for rejections, assert failure happens during `check` or `emit bash` for
  statically known invalid patterns before side effects;
- for dynamic invalid patterns, assert VM and emitted Bash both fail at runtime
  before later side effects;
- normalize absolute temp paths only where unavoidable.

Recommended helper families:

- `write_fixture name source`;
- `make_tree` / `touch_file` / `mkdir_p` helpers scoped to the test temp dir;
- `run_vm file args...`;
- `emit_bash file out args...`;
- `run_bash out args...`;
- `assert_vm_bash_parity file args...`;
- `assert_check_fails file expected_stderr_substring`;
- `assert_emit_fails file expected_stderr_substring`;
- `assert_vm_bash_runtime_failure file expected_stderr_substring`;
- `assert_no_ds_call out.sh`;
- `assert_contains file text`;
- `assert_not_contains file text`;
- `assert_bash_helper_present out.sh helper_name`;
- `assert_bash_helper_absent out.sh helper_name`;
- `assert_file_equals path expected`;
- `assert_no_side_effect path`.

For accepted parity cases:

1. Build a controlled directory tree.
2. Write the fixture.
3. Run `./ds fixture.ds`; capture stdout, stderr, and status.
4. Run `./ds emit bash fixture.ds -o out.sh`; assert success.
5. Run `bash -n out.sh`; assert success.
6. Assert `out.sh` does not contain an invocation of `ds`.
7. Run `bash out.sh`; capture stdout, stderr, and status.
8. Compare stdout, stderr, status, and side-effect files.

For rejected literal patterns:

1. Write the fixture with a literal invalid recursive pattern.
2. Run `./ds check fixture.ds` or `./ds emit bash fixture.ds -o out.sh`, choosing
   the earliest public path that should expose the diagnostic.
3. Assert non-zero status.
4. Assert stderr contains the expected ownership-level message.
5. Assert side-effect marker files were not created.
6. Assert no partial emitted Bash artifact is treated as valid output.

For dynamic invalid patterns:

1. Construct the invalid pattern through variables, function returns, env values,
   or script args so the lowerer cannot decide the value.
2. Assert `ds check` succeeds when the dynamic expression shape is otherwise
   valid.
3. Run VM and emitted Bash.
4. Assert both fail at runtime with matching exit status class and useful stderr.
5. Assert later side-effect markers were not created.

After implementation, assert docs contain the current contract:

- recursive globbing is supported through `glob` and `glob!`;
- `**` is recursive only as a complete path segment;
- the supported default is one recursive `**` segment per pattern unless the spec
  is amended;
- recursive `**` means zero or more directory segments;
- results are sorted, duplicate-free strings;
- `glob` no-match returns an empty collection;
- `glob!` no-match fails before the loop body executes;
- hidden path components are not matched/traversed unless explicitly named;
- directory symlinks are not followed;
- generated Bash is standalone and must not rely on ambient shell options;
- custom glob flags, multiple recursive segments, extglob, brace expansion,
  hidden traversal flags, symlink following, streaming iterators, and regex
  expansion remain deferred unless explicitly implemented.

### 2. Parser, AST, and static tooling smoke tests

Recursive globbing uses ordinary string literals and helper calls, so no new
lexer tokens should be required.

#### 2.1 AST shows helper calls

```ds
  echo file

```

Assertions:

- `ds tokens` succeeds and remains deterministic;
- `ds ast` succeeds and shows normal `glob` / `glob!` calls;
- `ds fmt --check` succeeds or produces only existing formatter limitations;
- `ds fmt --write` preserves `**` string contents exactly when formatting is
  supported for the file.

#### 2.2 HIR and bytecode smoke

Fixture:

```ds
let files = glob("**/*.ds")
for file in files {
  echo file
}
```

Assertions:

- `ds hir` succeeds and shows the helper call in a stable form;
- `ds bytecode` succeeds if bytecode output supports stdlib helper calls;
- debug output is pointer-free and deterministic after normal path filtering.

### 9. Dynamic pattern behavior

#### 9.1 Dynamic valid recursive pattern

Fixture:

```ds
let suffix = "*.ds"
let pattern = "src/**/{suffix}"
for file in glob(pattern) {
  echo file
}
```

Expected stdout matches the static `src/**/*.ds` case.

Assertions:

- pattern expression is evaluated once;
- dynamic valid recursive patterns work in VM and emitted Bash;
- emitted Bash includes recursive helper dependencies discovered through the
  accepted HIR, not literal-only scanning.

#### 9.2 Dynamic invalid recursive pattern fails at runtime

Fixture:

```ds
let bad = "src/**/tests/**/*.ds"
for file in glob(bad) {
  echo file
}
echo "after"
```

Expected behavior:

- `ds check` succeeds if the dynamic string value is not statically folded by the
  lowerer;
- VM execution fails at runtime;
- emitted Bash execution fails at runtime;
- stdout does not contain `after`;
- stderr identifies an invalid recursive glob pattern or equivalent runtime data
  failure.

#### 9.3 Pattern from script arg

Fixture:

```ds
script {
  arg pattern: string
}

for file in glob(pattern) {
  echo file
}
```

Run with:

```sh
"src/**/*.ds"
"src/**/tests/**/*.ds"
```

Assertions:

- valid arg works in VM and Bash;
- invalid arg fails at runtime in VM and Bash;
- diagnostics remain runtime/data diagnostics, not lowerer diagnostics.

#### 9.4 Required dynamic no-match

Fixture:

```ds
script {
  arg pattern: string
}

for file in glob!(pattern) {
  echo file
}
```

Run with a valid recursive pattern that matches nothing.

Assertions:

- VM/Bash both fail with required-glob no-match;
- runtime invalid-pattern and runtime no-match diagnostics are distinguishable
  enough for users to understand the cause.

### 10. Literal invalid pattern diagnostics

Each of these should fail during `ds check` or `emit bash` before side effects:

```ds
glob("src/**file.ds")
glob("src/foo**bar.ds")
glob("src/***.ds")
glob("src/**/tests/**/*.ds")
glob("src/**/**/file.ds")

```

Assertions for each case:

- lowerer-owned diagnostic mentions recursive `**` segment shape or the
  single-recursive-segment limit;
- VM is not invoked for `check`/`emit` diagnostics;
- emitted Bash artifact is not produced as a valid script;
- no side-effect marker files are created.

If the implementation deliberately supports multiple recursive segments, remove
those cases from the rejection set and add accepted parity tests for nested
recursive segments instead.

### 15. Runtime filesystem failures

Create cases only when portable in the test environment:

- unreadable directory under the recursive search root;
- path component that disappears between traversal setup and matching;

Assertions:

### 16. Diagnostics ownership checks

Assert wording/classification for:

- malformed helper call syntax: parser/frontend diagnostic;
- wrong arity: lowerer/stdlib diagnostic;
- non-string static pattern: lowerer diagnostic;
- literal invalid recursive segment: lowerer diagnostic;
- literal multiple recursive segments under default spec: lowerer diagnostic;
- dynamic invalid recursive segment: VM/Bash runtime data diagnostic;
- `glob!` no-match: VM/Bash runtime data diagnostic;
- filesystem permission/traversal failure: VM/Bash runtime/OS diagnostic;
- impossible accepted-HIR helper shape: internal invariant diagnostic only in
  defensive backend paths.

Backend diagnostics must not say a source-language recursive pattern is
unsupported when the pattern was literal and statically knowable; that belongs to
lowering.
