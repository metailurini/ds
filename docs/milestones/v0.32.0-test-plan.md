# v0.32.0 Test Plan — Regex Captures, Replacement, and Runtime Regex Strings

## Purpose

Prove that `v0.32.0` regex expansion is portable, deterministic, and scoped:

```txt
runtime string patterns work with `matches`
regex.match returns flat capture maps
regex.replace performs global capture-aware replacement
literal invalid patterns/replacements fail before execution/emission
dynamic invalid patterns/replacements fail at runtime before later side effects
VM and emitted Bash agree for stdout, stderr, exit status, and side effects
generated Bash remains standalone and helper-hygienic
```

The suite should exercise the accepted surface deeply without drifting into
deferred PCRE, named-capture, regex-split, replace-count, or Unicode semantics.

## Test organization

Create a dedicated suite:

```txt
tests/v0_32/run.sh
```

Add a Makefile target:

```txt
make test-v0-32
```

Include `test-v0-32` in aggregate test targets only after the focused suite is
stable. The suite should follow existing test harness conventions and must be
safe to run from a clean checkout.

Recommended harness behavior:

- build `ds` before running focused fixtures;
- use one temporary directory per test case or per isolated group;
- keep fixture source files under the temp directory;
- run accepted cases in VM mode and through emitted Bash;
- run `bash -n` for every emitted script;
- assert emitted Bash does not call `ds`;
- compare VM/Bash stdout, stderr, exit status, and deterministic side effects;
- assert helper code is emitted only when required;
- assert helpers stay under the reserved `__ds_` namespace;
- verify static rejections happen before side effects;
- verify dynamic runtime failures happen before later side effects;
- avoid locale-dependent expectations;
- normalize temp paths in diagnostics only when diagnostics necessarily include
  absolute paths.

Recommended helper families:

- `write_fixture name source`;
- `run_vm file args...`;
- `emit_bash file out args...`;
- `run_bash out args...`;
- `assert_vm_bash_parity file args...`;
- `assert_check_fails file expected_stderr_substring`;
- `assert_emit_fails file expected_stderr_substring`;
- `assert_vm_bash_runtime_failure file expected_stderr_substring`;
- `assert_no_ds_call out.sh`;
- `assert_bash_n out.sh`;
- `assert_contains file text`;
- `assert_not_contains file text`;
- `assert_bash_helper_present out.sh helper_name`;
- `assert_bash_helper_absent out.sh helper_name`;
- `assert_side_effect_absent path`;
- `assert_file_equals path expected`.

For accepted parity cases:

1. Write a deterministic `.ds` fixture.
2. Run `./ds fixture.ds`; capture stdout, stderr, and status.
3. Run `./ds emit bash fixture.ds -o out.sh`; assert success.
4. Run `bash -n out.sh`; assert success.
5. Assert `out.sh` has no invocation of `ds`.
6. Run `bash out.sh`; capture stdout, stderr, and status.
7. Compare stdout, stderr, status, and side effects.

For literal/static diagnostics:

1. Write a fixture with invalid literal regex/replacement/flags or wrong known
   operand kinds.
2. Run the earliest public path that should expose the diagnostic, usually
   `./ds check fixture.ds`.
3. Assert non-zero status and a source-owned diagnostic substring.
4. Assert no side-effect marker was created.
5. Assert `emit bash` does not produce a usable script for rejected HIR.

For dynamic runtime diagnostics:

1. Build invalid data through args, env, string concatenation, function returns,
   or map/array reads so the lowerer cannot know the final text.
2. Assert `./ds check fixture.ds` succeeds when the expression shapes are valid.
3. Run VM and emitted Bash.
4. Assert both fail before later side effects.
5. Compare status class and useful diagnostic substrings.

### 1. Planning and docs checks

Assert these files exist:

- `docs/milestones/v0.32.0-spec.md`;
- `docs/milestones/v0.32.0-test-plan.md`;
- `docs/roadmap.md`;
- `docs/language.ds`;

- `docs/parity-contracts.md`;
- `docs/diagnostics.md`;
- `docs/concept-map.md`;
- `docs/source-map.md`.

After implementation, assert docs describe the current contract:

- runtime string patterns are supported for `matches`;
- `regex.match(text, pattern[, flags])` returns a flat map;
- match-result keys include `matched`, `full`, `"0"`, and captures `"1"` through
  `"9"` when matched;
- no match is nonfatal for `regex.match`;
- optional unmatched captures are empty strings;
- `regex.replace(text, pattern, replacement[, flags])` is global;
- replacement supports `$0` through `$9` and `$$`;
- invalid dynamic patterns/replacements fail at runtime;
- literal invalid patterns/replacements fail before execution/emission;
- generated Bash is standalone;
- named captures, regex split, replace-first/count options, callbacks,
  lookaround, pattern backreferences, lazy quantifiers, inline flags, Unicode
  classes, and more than nine captures remain deferred/rejected.
