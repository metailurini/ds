# v0.33.0 Test Plan — Collection, Glob, Regex, and Debt Stabilization

## Purpose

`v0.33.0` is a cleanup/stabilization milestone, not a feature-expansion
milestone. The test suite must prove that the combined surface from `v0.25.0`
through `v0.32.0` remains coherent, portable, and accurately documented before
the project moves into signal/job-control work.

The suite should focus on four outcomes:

1. VM and emitted Bash agree for supported flat collections, command results,
   environment access, interpolation, recursive globbing, and regex helpers.
2. Unsupported or deferred forms remain rejected clearly before execution or
   partial emission.
3. Generated Bash remains standalone, helper-hygienic, and independent of
   ambient shell state.
4. The technical-debt audit required by the spec is recorded with concrete
   findings instead of being left as implicit reviewer knowledge.

Do not add tests that imply new user-facing syntax, new APIs, nested
collections, richer glob features, richer regex dialect support, or new
signal/job-control behavior.

## Test suite location

Add the dedicated suite at:

```txt
tests/v0_33/run.sh
```

Wire it into the aggregate test targets in `Makefile` after `v0_32`.

The suite may reuse helper style from adjacent suites, but it should be readable
as a stabilization checklist. Favor small fixtures with exact VM/Bash parity
checks over one large script that is hard to diagnose.

## Required commands

At minimum, the implementation pass must run:

```sh
make
make test-v0-25
make test-v0-26
make test-v0-27
make test-v0-29
make test-v0-30
make test-v0-31
make test-v0-32
make test-v0-33
```

Also run when feasible:

```sh
make test
```

If the aggregate run times out or is interrupted by the environment, record the
exact suite that was running, the last visible passing/failing evidence, and the
focused suites that did complete.

Run sanitizer variants for `v0_33` when the project already exposes equivalent
targets or when a manual ASan/UBSan build is practical. Do not weaken existing
signal or process tests just to make aggregate runtime shorter.

## Test conventions

The suite should provide helpers for:

- creating an isolated temporary workspace per case;
- running `ds check`, `ds ast`, `ds hir`, `ds bytecode`, `ds fmt` where relevant;
- running VM execution and emitted Bash execution;
- checking stdout, stderr, and exit status parity;
- asserting `bash -n` succeeds for emitted scripts;
- asserting emitted Bash does not invoke `ds`;
- asserting helper inclusion/exclusion with exact helper-name greps;
- asserting no duplicate helper definitions;
- asserting fail-fast behavior by creating a side-effect marker after the
  expression that should fail;
- skipping only genuinely host-dependent cases, with a printed reason.

When a case checks VM/Bash parity, compare all deterministic outputs:

```txt
stdout
stderr shape, where deterministic
exit status
filesystem side effects, where deterministic
```

Use bytewise deterministic expectations where ordering matters. Prefer
`LC_ALL=C` for sorted-order assertions unless the case is specifically testing
hostile ambient locale handling.

### 2. Collection contract stabilization

#### 2.1 Flat array return parity

Create a function returning a flat string array containing:

- empty string;
- whitespace;
- shell metacharacters;
- leading dash;
- newline-containing string if current collection rules allow it.

Bind the returned array, index it, interpolate scalar elements, loop over it,
and compare VM/Bash output.

#### 2.2 Flat scalar element kind preservation

Return arrays of strings, ints, and bools from separate functions. Use returned
elements in contexts that reveal kind:

- string methods/interpolation;
- integer comparison/arithmetic, if supported;
- boolean conditions.

Verify Bash structured-value decoding does not collapse all values into strings
where the language promises kind preservation.

#### 2.3 Flat map return parity

Return a flat map containing string, int, and bool values from a function. Bind
the result, access fields/keys, iterate the map, and compare deterministic
VM/Bash output.

#### 2.4 Command-result return parity

Return a captured command result from a function. Verify `stdout`, `stderr`, and
`status` fields compose with interpolation, conditions, and command words
without leaking private Bash transport payloads to user stdout.

#### 2.5 Value-copy behavior, no accidental aliases

Assign one returned array/map to another variable, mutate one named binding, and
verify the other binding does not change in VM or Bash.

#### 2.6 Array index assignment happy paths

Verify replacement of first, middle, and last elements. Include index from an int
variable. Verify RHS string/int/bool kind preservation.

#### 2.7 Array index assignment failures

Verify VM/Bash fail consistently and before later side effects for:

- negative index;
- out-of-range positive index;
- append-by-assignment at `len`;
- non-int index;
- RHS array/map/command-result;
- assignment to temporary/function-call/command-result target.

#### 2.8 Map index assignment happy paths

Verify replacing an existing key and inserting a new key. Include key from a
string variable, leading-dash key, whitespace key, and shell-metacharacter key if
accepted by current map rules.

#### 2.9 Map index assignment failures

Verify consistent rejection/failure for:

- empty key;
- non-string key;
- RHS array/map/command-result;
- assignment to temporary/function-call/command-result target;
- field-style map assignment if still unsupported;
- nested collection values.

#### 2.10 Mutation during iteration

Verify mutating the same map being iterated remains rejected before execution or
emission. Also verify mutating a different map inside the loop remains accepted
when current rules allow it.

#### 2.11 Deterministic map iteration order

Use keys that would reveal locale or insertion-order drift, such as:

```txt
B
a
aa
b
z
```

Verify VM and Bash iterate in the documented bytewise/ASCII order and remain
deterministic across repeated runs.

#### 2.12 Empty collections

Verify loops over empty arrays/maps execute zero iterations and do not trip
`break`/`continue` bodies. Verify returned empty collections preserve the correct
array/map kind.

#### 2.13 Collection composition with control flow

Cover arrays/maps in:

- `if`/`else` through scalar elements;
- `case` through scalar elements;
- loops with `break` and `continue`;
- functions with early `return`;
- `test` blocks;
- imported functions.

#### 2.14 Interpolation and command-word boundaries

Verify normal interpolation and command-word interpolation accept scalar indexed
elements and reject collection-valued or unsupported computed collection forms
with lowerer diagnostics.

### 3. Recursive glob stabilization

#### 3.1 Basic recursive parity

Create a fixture with root files, nested files, and deeper nested files. Verify:

- `glob("**/*.ds")`;
- `glob("src/**/*.c")`;
- zero-directory matches;
- nested matches;
- no duplicates;
- deterministic order.

#### 3.2 Required-match behavior

Verify `glob!("**/*.ds")` succeeds when matches exist and fails before loop
bodies or later side effects when no matches exist.

#### 3.3 Optional no-match behavior

Verify `glob("missing/**/*.ds")` returns an empty array and does not fail.

#### 3.4 Hidden path policy

Create hidden files and hidden directories. Verify default recursive patterns
skip hidden path components unless explicitly named by a non-`**` segment.

Required cases:

- hidden file under visible dir;
- file under hidden dir;
- explicit hidden final segment;
- explicit hidden prefix directory.

#### 3.5 Symlink policy

When the host supports symlinks, verify:

- file symlink matching behavior follows docs;
- directory symlink is not traversed;
- broken matching symlink behavior follows docs.

Skip with a reason only when symlink creation is not available.

#### 3.6 Path quoting and hostile names

Use filenames and directories containing:

- spaces;
- tabs if practical;
- brackets;
- glob metacharacters that are literal path components;
- leading dashes;
- single quotes;
- dollar signs.

Verify VM/Bash parity and emitted Bash quoting safety.

#### 3.7 Dynamic recursive pattern validation

Verify dynamic valid recursive patterns work. Verify dynamic invalid patterns
fail as runtime data errors before side effects:

- partial `**` segment;
- multiple recursive segments;
- recursive pattern containing `..`;
- adjacent recursive segments;
- empty pattern where unsupported.

#### 3.8 Literal recursive pattern diagnostics

Verify literal invalid recursive patterns are rejected by `ds check` and `ds emit
bash` before runtime.

#### 3.9 Runtime filesystem failures

Create an unreadable directory under a recursive traversal root. Verify VM and
Bash exit non-zero before later side effects. If the suite runs as root, attempt
the case under an unprivileged user such as `nobody` when available; otherwise
skip with a clear reason.

#### 3.10 Ambient shell option and environment hygiene

Run emitted Bash recursive glob cases under hostile conditions:

```sh
bash -O globstar -O dotglob -O nullglob -O failglob script.sh
IFS=':' bash script.sh
LC_ALL=C bash script.sh
```

Also run with a best-effort non-C locale when available. Verify output parity and
that shell options do not leak into later user commands.

### 4. Regex stabilization

#### 4.1 Literal `matches` parity

Verify regex-literal `matches` still works without helper emission for basic,
anchored, alternation, character-class, and case-insensitive `/i` cases.

#### 4.2 Runtime string `matches` parity

Verify runtime string patterns from variables, function returns, arguments,
environment values, array access, map access, and command-result stdout.

#### 4.3 `regex.match` map shape

For match success, assert the flat map includes:

- `matched`;
- `full`;
- `0`;
- captures `1` through `9` when present.

For no match, assert the map is still populated consistently and does not fail.

#### 4.4 Capture edge cases

Cover:

- optional unmatched capture as empty string;
- capture that matches an empty string;
- alternation captures;
- nested capture numbering if accepted by the current subset;
- too many captures rejected/failing consistently.

#### 4.5 `regex.replace` global behavior

Verify global replacement for literal and runtime string patterns. Include:

- `$0` full match;
- `$1` through `$9` captures;
- `$$` literal dollar;
- deletion replacement `""`;
- replacement that grows text;
- no-match returns original;
- optional unmatched replacement capture;
- repeated adjacent non-empty matches.

#### 4.6 Replacement precedence and anchor edge cases

Keep regression cases for anchored alternation ordering:

```ds
regex.replace("aba", /^a|a$/, "X")
regex.replace("aba", /a$|^a/, "X")
```

Both must produce `XbX` in VM and emitted Bash.

Also test anchored whole-string patterns and end-anchored suffix patterns that
match only once.

#### 4.7 Flags and `nocasematch` isolation

Verify flags are exactly `""` and `"i"`. Run emitted Bash under normal shell
state and under:

```sh
bash -O nocasematch script.sh
```

Case-sensitive operations must remain case-sensitive; case-insensitive operations
must remain case-insensitive; the caller's prior `nocasematch` state must be
restored afterward.

#### 4.8 Static regex diagnostics

Verify statically knowable invalid patterns, unsupported features, unsupported
flags, too many captures, and invalid replacement references are rejected by the
lowerer/check path before emission/execution.

Unsupported feature fixtures should include at least:

- lookaround;
- pattern backreferences;
- lazy quantifiers;
- inline flags;
- named captures;
- Unicode property classes;
- malformed bracket/paren syntax.

#### 4.9 Dynamic regex runtime failures

Verify invalid dynamic patterns, flags, replacement syntax, nonexistent
replacement groups, too many dynamic captures, and zero-length replacement
matches fail before later side effects in both VM and emitted Bash.

#### 4.10 Regex integration cases

Use regex results in:

- `if`/`else`;
- `case`;
- loops;
- interpolation;
- command words;
- function returns;
- map iteration over `regex.match` result;
- index assignment mutating a `regex.match` result copy;
- imports;
- `test` blocks.

### 5. Generated Bash helper dependency and hygiene

#### 5.1 Literal regex helper exclusion

Scripts that only use literal `matches /.../` should emit no regex helper bodies.
They may emit local case-guard snippets if that is the chosen implementation,
but not the runtime string/match/replace helper catalog.

#### 5.2 Runtime string regex helper inclusion

Scripts using only runtime-string `matches` should emit the base regex test
helper and not emit `regex.match` map or `regex.replace` helpers.

#### 5.3 `regex.match` helper inclusion

Scripts using `regex.match` should emit only the base regex helper and match-map
helper, not the replacement helper.

#### 5.4 `regex.replace` helper inclusion

Scripts using `regex.replace` should emit only the helpers needed for
replacement. If the implementation shares base regex validation, assert the base
helper is present once.

#### 5.5 Recursive glob helper inclusion

Scripts using non-recursive `glob`/`glob!` should not emit recursive traversal
helpers. Scripts using recursive patterns should emit required recursive helpers
exactly once.

#### 5.6 Collection helper inclusion

Scripts with flat collection returns and map iteration should emit required
structured-value/map helpers exactly once and not emit unrelated regex/glob
helpers.

#### 5.7 Helper discovery in all expression positions

Verify helper discovery covers helpers nested inside:

- function-call arguments;
- statement-style user-function call arguments;
- interpolation expressions;
- command-word interpolation;
- loop iterables;
- `if` and `case` conditions;
- `return` expressions;
- `test` blocks;
- imported modules;
- cleanup/defer/trap bodies if current HIR supports those positions.

#### 5.8 Standalone generated Bash

For representative collection/glob/regex scripts, assert emitted Bash:

- passes `bash -n`;
- does not invoke `ds`;
- defines helpers under the reserved `__ds_` namespace;
- has no duplicate helper definitions;
- includes Bash 4+ guards when associative arrays or Bash-4-only behavior are
  required;
- remains compatible with aliases/functions named like common tools where the
  helper should use builtins or guarded command invocations.

#### 5.9 Failure propagation through helpers

Create fixtures where helper failure would be easy to swallow in a pipeline,
process substitution, or subshell. Verify the generated script exits non-zero
and does not continue to later side effects.

Required families:

- recursive glob traversal failure;
- dynamic invalid regex pattern;
- dynamic invalid replacement;
- structured return payload guard if an internal guard can be exercised safely.

### 7. Diagnostics ownership and fail-fast behavior

#### 7.1 Parser-owned syntax failures

Malformed collection literals, malformed index assignment syntax, malformed
regex literals, malformed function calls, and malformed loop headers should fail
as parser diagnostics with source locations.

#### 7.2 Lowerer-owned semantic/parity failures

Statically knowable unsupported forms should fail in `check` and `emit bash`
before execution:

- nested collection values;
- unsupported mutation targets;
- same-map mutation during iteration;
- unsupported direct structured interpolation;
- invalid literal recursive glob patterns;
- invalid literal/static regex patterns, flags, and replacement references.

#### 7.3 Runtime-owned dynamic failures

Dynamic invalid values should fail at runtime in VM and emitted Bash before
later side effects:

- recursive glob traversal errors;
- dynamic invalid glob pattern;
- dynamic invalid regex pattern/flag/replacement;
- array out-of-bounds index assignment;
- map invalid runtime key if only knowable dynamically;
- command-result/process/OS failures where documented as runtime failures.

#### 7.4 Diagnostic consistency

Where exact stderr text is stable, compare VM/Bash diagnostic shape. Otherwise,
assert stable fragments such as the helper name, rejected feature, or invalid
value class. Do not make tests brittle around host-specific OS messages.


#### 9.3 Quoting and injection boundaries

#### 9.4 Temporary file cleanup

already exposes them.
