# v0.35.0 Spec — Core String Parsing Helpers

## Status

Implemented and covered by the dedicated regression suite. The companion test
plan lives at `docs/milestones/v0.35.0-test-plan.md`, and the executable suite
is wired through `tests/v0_35/run.sh` and `make test-v0-35`.

`v0.35.0` is the second milestone in the current DX-priority wave that began
with `v0.34.0`. It should make practical text parsing less dependent on shell
workarounds while preserving the project rule that every accepted production
feature must run in the VM and emit standalone Bash with matching behavior.

## Goal

Add a small, byte-oriented set of string parsing helpers for common shell-native
scripts:

- `value.len()`;
- `value.index_of(needle)`;
- `value.last_index_of(needle)`;
- `value.count(needle)`;
- `value.char_at(index)`;
- `value.slice(start, end)`.

Also close the adjacent DX gap around read-only indexing after method calls so
common chains such as this are supported and documented:

```ds
let head = sig.split("(")[0].trim()
```

The result should let scripts scan and slice lines, signatures, paths, and
simple delimited data without repeatedly binding temporary split variables or
falling back to external tools like `cut`, `awk`, `sed`, `expr`, or `printf`.

## Motivation

While writing `scripts/analyze_c_functions_pure.ds`, the project hit a concrete
set of text-processing pain points recorded in `docs/dx-issues.md`:

- finding delimiter positions required shelling out or awkward split-based
  approximations;
- extracting prefixes and suffixes required temporary arrays or external tools;
- checking one byte/character at a position had no direct helper;
- counting delimiters or occurrences required loops with too much ceremony;
- `sig.split("(")[0].trim()` was expected to work but had to be written as two
  separate bindings.

`v0.34.0` removed the literal-brace string workaround and quieted common
broken-pipe output. `v0.35.0` should remove the next layer of text parsing
friction without widening the language into a full parser-combinator, regex
split, Unicode, or data-frame milestone.

## Product principles preserved

The project principles remain unchanged:

```txt
Every accepted production feature runs in the VM.
Every accepted production feature emits standalone Bash.
Generated Bash must not call ds.
VM and emitted Bash must agree on stdout, stderr shape, exit status, and side effects.
Accepted helpers must have clear diagnostics for unsupported values and arity.
Generated Bash helpers must be portable, helper-hygienic, and independent of ambient shell options.
Lowering owns statically knowable semantic/parity gates.
VM and Bash helpers own runtime data-dependent failures.
```

## Supported syntax and behavior

### 1. Method surface

`v0.35.0` adds these string methods to the existing `v0.19.0` string-method
surface:

| Method | Result | Required arguments | Summary |
| --- | --- | --- | --- |
| `value.len()` | int | receiver only | Byte length of the string. |
| `value.index_of(needle)` | int | receiver, string | First zero-based byte offset of `needle`, or `-1` if missing. |
| `value.last_index_of(needle)` | int | receiver, string | Last zero-based byte offset of `needle`, or `-1` if missing. |
| `value.count(needle)` | int | receiver, string | Number of non-overlapping occurrences of `needle`. |
| `value.char_at(index)` | string | receiver, int | One-byte string at zero-based byte offset `index`. |
| `value.slice(start, end)` | string | receiver, int, int | Bytes in the half-open range `[start, end)`. |

The existing methods remain in scope and must keep their documented behavior:

- `trim()`;
- `upper()`;
- `lower()`;
- `replace(from, to)`;
- `contains(sub)`;
- `split(sep)`;
- `starts_with(pre)`;
- `ends_with(suf)`.

Method names are exact and case-sensitive. Unknown string methods should produce
a diagnostic whose supported-method list includes both the existing methods and
the new `v0.35.0` methods.

### 2. Byte indexing model

All new helpers are byte-oriented in `v0.35.0`:

- indexes are zero-based byte offsets;
- lengths are byte counts;
- `char_at` returns one byte as a string, not a Unicode scalar value or grapheme
  cluster;
- `slice` boundaries are byte offsets and may split a UTF-8 sequence;
- emitted Bash must not drift under a non-`C` locale;
- NUL bytes remain unsupported because the current string representation and
  generated Bash transport are text/string based.

This deliberately matches the current ASCII-oriented string helper contract from
`v0.19.0` and avoids introducing locale- or Unicode-dependent behavior before a
dedicated text model exists.

### 3. Search helpers

`index_of` searches left-to-right for the first non-overlapping occurrence of
`needle` in `value`.

Rules:

- `"abc".index_of("a")` returns `0`;
- `"abc".index_of("b")` returns `1`;
- `"abc".index_of("z")` returns `-1`;
- `"abc".index_of("abc")` returns `0`;
- `"abc".index_of("abcd")` returns `-1`;
- `"abc".index_of("")` returns `0`.

`last_index_of` searches right-to-left for the last occurrence of `needle` in
`value`.

Rules:

- `"ababa".last_index_of("ba")` returns `3`;
- `"abc".last_index_of("z")` returns `-1`;
- `"abc".last_index_of("abc")` returns `0`;
- `"abc".last_index_of("abcd")` returns `-1`;
- `"abc".last_index_of("")` returns `3`, the byte length of the receiver.

Missing matches are not errors. They are ordinary integer results so scripts can
branch without exception-style control flow.

### 4. Counting helpers

`len()` returns the byte length of the receiver.

Rules:

- `"".len()` returns `0`;
- `"abc".len()` returns `3`;
- `"a\nb".len()` returns `3`;
- a non-ASCII UTF-8 character returns its encoded byte length, not a code-point
  count.

`count(needle)` returns the number of non-overlapping occurrences of `needle`,
scanning left-to-right.

Rules:

- `"aaaa".count("aa")` returns `2`;
- `"abababa".count("aba")` returns `2` because matches are non-overlapping;
- `"abc".count("z")` returns `0`;
- `"".count("x")` returns `0`;
- `"abc".count("")` returns `4`, the number of zero-width byte boundaries;
- `"".count("")` returns `1`.

The empty-needle count rule is intentionally explicit so VM and Bash do not
diverge or loop forever. Scripts that do not want this behavior can reject an
empty needle with an ordinary condition before calling `count`.

### 5. Character and slice helpers

`char_at(index)` returns one byte at `index` as a string.

Rules:

- `"abc".char_at(0)` returns `"a"`;
- `"abc".char_at(2)` returns `"c"`;
- `"abc".char_at(3)` is an out-of-range error;
- `"".char_at(0)` is an out-of-range error;
- negative indexes are errors.

`slice(start, end)` returns bytes in the half-open range `[start, end)`.

Rules:

- `"abc".slice(0, 2)` returns `"ab"`;
- `"abc".slice(1, 3)` returns `"bc"`;
- `"abc".slice(1, 1)` returns `""`;
- `"abc".slice(0, 3)` returns `"abc"`;
- `"abc".slice(0, 4)` is an out-of-range error;
- `"abc".slice(2, 1)` is an invalid-range error;
- negative start or end indexes are errors.

`slice` is strict in `v0.35.0`: it does not clamp out-of-range boundaries and it
does not accept negative indexes. This keeps accidental off-by-one bugs visible
and leaves Python-style negative indexing or clamping for a deliberate future
design if needed.

### 6. Argument kind rules

The receiver must be a known string value or a value the current lowerer already
classifies as string-compatible, such as:

- string literals;
- string variables;
- string-valued command-result fields such as `result.stdout` and
  `result.stderr`;
- string-valued function calls;
- string-valued map/array index reads where the element/value kind is known;
- string-valued method chains;
- parenthesized string expressions where already supported.

Arguments must match each helper:

- `index_of`, `last_index_of`, and `count` take string needles;
- `char_at` takes one int index;
- `slice` takes two int indexes;
- `len` takes no explicit argument.

Wrong arity, wrong receiver kind, and wrong argument kind must fail before
partial execution or Bash emission when statically knowable. Runtime
data-dependent bounds failures must fail in both VM execution and emitted Bash
with matching exit status and comparable diagnostic wording.

### 7. Read-only indexing after method calls

`v0.35.0` must audit and close the direct indexing DX issue from
`docs/dx-issues.md`.

The accepted read-only forms are:

```ds
let first = value.split(",")[0]
let clean = value.split(",")[0].trim()
let nested = (value.trim().split(","))[1].lower()
```

The accepted scope is expression index reads where the indexed expression has a
known flat array or map result kind and the element/value kind can be preserved
for later operations. At minimum, `string.split(...)[index]` must work for both
VM and emitted Bash and must preserve string element kind so string methods can
continue after the index read.

The following remain unsupported in `v0.35.0`:

```ds
value.split(",")[0] = "x"      # mutation through a temporary
value.slice(0, 1)[0]            # string indexing syntax; use char_at
value.split(",")[0][0]          # nested indexing through a string
make_rows()[0].field            # row/record work belongs to v0.37.0
```

If a form was already supported by earlier milestones, keep it supported. If the
parser/lowering currently supports only a subset of the intended read-only
postfix shape, add the smallest parser/lowering support needed for the examples
above rather than redesigning expression parsing broadly.

### 8. Composition with existing string features

The new helpers should compose with existing string methods, interpolation,
conditions, integer expressions, loops, functions, imports, command results, and
emitted Bash helper dependency scanning.

Examples:

```ds
let line = "int main(void) {{"
let open = line.index_of("(")
let name = line.slice(4, open).trim()

if line.contains("{{") && line.char_at(line.len() - 1) == "{{" {
  echo "function-ish: {name}"
}

let parts = "api:web:worker".split(":")
echo parts[1].slice(0, 1).upper()
```

Integer-returning helpers may participate in supported integer arithmetic and
comparisons from `v0.21.0`. String-returning helpers may continue normal string
method chains. Boolean conditions are not added or changed by this milestone.

## Non-goals

Do not implement any of these in `v0.35.0`:

- Unicode scalar, grapheme, normalization, width, or locale-aware text
  semantics;
- negative indexing;
- clamped slicing;
- `slice(start)` or `slice(start, length:)` overloads;
- search-from-offset overloads such as `index_of(needle, start)`;
- regex split or regex-backed string methods;
- parser-combinator helpers;
- string-to-int parsing, numeric scanners, or tokenizers;
- `string[index]` syntax;
- mutable string operations;
- nested collection indexing beyond already-supported flat read paths;
- temporary/function-result mutation;
- row/record fields, data frames, sorting helpers, or in-memory row buffers;
- broad function parameter type inference beyond what is required to keep
  existing known string/int values flowing through the helpers;
- native or alternate shell backends.

If implementation uncovers a useful helper that is not in the supported method
surface above, record it as deferred rather than silently adding it.

## VM behavior

The VM must implement the accepted helpers without shelling out.

Required behavior:

- operate on the current internal string byte buffer and length;
- return `DS_VALUE_INT` for `len`, `index_of`, `last_index_of`, and `count`;
- return `DS_VALUE_STRING` for `char_at` and `slice`;
- preserve source-located diagnostics where the VM currently reports helper
  runtime failures;
- reject out-of-range `char_at` and `slice` data failures with non-zero status;
- avoid signed/unsigned overflow when converting string lengths and indexes to
  integer values;
- preserve exact bytes for spaces, tabs, newlines, quotes, `$`, backticks,
  braces, brackets, and other shell metacharacters.

Runtime helpers must not mutate receiver strings or global state.

## Bash emission behavior

Generated Bash must remain standalone and must not invoke `ds`.

Required behavior:

- emit only the helper functions needed by the lowered program;
- include helper dependencies recursively when a new helper is nested inside an
  index read, method chain, interpolation expression, or helper argument;
- keep helper names under the existing `__ds_` namespace convention;
- avoid duplicate helper definitions;
- preserve byte-oriented behavior independent of ambient `LC_ALL`, `LANG`,
  `IFS`, `set -e`, `set -u`, aliases, shell functions, or hostile variables;
- report `char_at`/`slice` bounds failures clearly and exit non-zero;
- quote helper arguments so strings with whitespace, newlines, quotes, command
  substitutions, braces, glob characters, and leading dashes are data.

Because Bash substring and length behavior can become locale-sensitive, the
implementation must deliberately force byte semantics for these helpers, either
inside the helper bodies or through an equivalent local mechanism that does not
leak locale changes to user code.

## Diagnostics and debugging behavior

Diagnostics should follow the current project style:

- wrong arity reports the method name, expected count, and actual count;
- wrong receiver kind reports that the string method requires a string receiver;
- wrong needle/index argument kind reports the specific expected kind;
- static out-of-range literals may be rejected by lowering/checking if both the
  receiver and index/range are known;
- dynamic out-of-range failures report the helper name and invalid index/range;
- unsupported temporary mutation and string indexing forms fail before emission;
- unknown string-method diagnostics list the new methods as supported.

Debug commands should make the lowered shape visible enough to diagnose helper
dependency and parity issues:

- `ds ast` should preserve the source-level method and postfix-index shape;
- `ds hir` should show helper calls and index reads in a stable way;
- `ds bytecode` should show the relevant call/index operations without losing
  return-kind information;
- `ds fmt` should preserve method chains and `split(...)[index]` syntax without
  introducing ambiguous spacing.

## Examples

### Delimiter scanning

```ds
let sig = "static int parse_name(const char *s) {{"
let open = sig.index_of("(")

if open >= 0 {
  let before_args = sig.slice(0, open).trim()
  let last_space = before_args.last_index_of(" ")
  let name = before_args.slice(last_space + 1, before_args.len())
  echo "name={name}"
}
```

### Suffix inspection

```ds
let path = "src/main.c"
let dot = path.last_index_of(".")

if dot >= 0 {
  let ext = path.slice(dot + 1, path.len())
  echo "extension={ext}"
}
```

### Counting and one-byte inspection

```ds
let line = "api:web:worker"
let field_count = line.count(":") + 1
echo "fields={field_count}"

if line.char_at(0) == "a" {
  echo "starts with a"
}
```

### Direct indexing after split

```ds
let sig = "int main(void)"
let fn_name = sig.split("(")[0].trim().split(" ")[1]
echo "function={fn_name}"
```

## Acceptance criteria

`v0.35.0` is complete when:

- all six new helpers are implemented for VM execution;
- all six new helpers emit standalone Bash with matching behavior;
- helper metadata reports correct arity and return kind;
- `char_at` and `slice` enforce strict zero-based bounds in VM and Bash;
- empty-needle behavior for search/count helpers matches this spec;
- byte-oriented behavior is stable under hostile locale settings;
- direct read-only indexing after `split` works in method chains with preserved
  string element kind;
- unsupported temporary mutation and string indexing remain rejected clearly;
- new helper diagnostics are source-located and comparable across VM/Bash where
  applicable;
- generated Bash remains helper-hygienic, standalone, `bash -n` clean, and free
  of `ds` runtime calls;
- `docs/language.ds`, `docs/status.md`, `docs/runtime.md`, `docs/diagnostics.md`,
  and `docs/dx-issues.md` are updated if implementation changes current claims;
- the dedicated `v0.35.0` test suite follows the companion test plan;
- regression suites for prior string, collection-index, function, regex, and
  text-DX milestones still pass or have documented environment-limited skips;
- deferred items and technical debt are recorded.

## Deferred items

Deferred by design:

- Unicode-aware text model;
- negative indexing and clamped slicing;
- offset-based search overloads;
- regex split;
- parser-combinator or tokenizer libraries;
- `string[index]` syntax;
- mutable strings;
- row/record parsing helpers and sort-by-field APIs;
- typed function parameter inference, except for any narrow bug fix needed to
  preserve already-known string/int helper arguments.
