# v0.35.0 Test Plan — Core String Parsing Helpers

## Status

Implemented. The executable suite lives at `tests/v0_35/run.sh` and is wired
through `make test-v0-35` after the `v0.34.0` suite. This document remains the
source checklist for the covered behavior and should be amended only when the
spec is deliberately amended.

## Purpose

The `v0.35.0` suite must prove that the new string parsing helpers and direct
post-method indexing behavior are practical, portable, and tightly scoped.

The suite should show that:

1. `len`, `index_of`, `last_index_of`, `count`, `char_at`, and `slice` have
   matching VM and emitted-Bash behavior.
2. Indexes and lengths are zero-based byte offsets, not locale-sensitive
   characters or Unicode graphemes.
3. Missing matches are ordinary integer results while invalid indexes/ranges are
   diagnostics/failures.
4. `value.split(sep)[index].trim()` works without temporary bindings and
   preserves string element kind.
5. Unsupported adjacent forms remain rejected before partial execution or Bash
   emission.
6. Generated Bash remains standalone and helper-hygienic.

Do not add tests that imply Unicode semantics, regex split, negative indexes,
clamped slices, mutable strings, parser-combinator APIs, row/record APIs, or
broader function parameter kind inference.

## Test suite location

Add the dedicated suite at:

```txt
tests/v0_35/run.sh
```

Wire it into aggregate test targets in `Makefile` after `v0_34`.

Favor small fixtures with exact expectations. Use the shared test helpers from
`tests/lib/testlib.sh` where possible, especially the VM/Bash parity helper that
emits Bash, validates it with `bash -n`, runs both backends from isolated
working directories, and compares stdout/stderr/status.

## Test conventions

The suite should provide or reuse helpers for:

- isolated temporary workspaces per case;
- writing focused `.ds` fixtures;
- running `ds check`, `ds ast`, `ds hir`, `ds bytecode`, and `ds fmt` where
  relevant;
- running VM execution and emitted Bash execution;
- checking stdout, stderr shape, and exit status parity;
- asserting generated Bash passes `bash -n`;
- asserting generated Bash does not invoke `ds`;
- asserting helper inclusion/exclusion with exact helper-name greps;
- asserting no duplicate helper definitions;
- asserting fail-fast behavior with a side-effect marker after the expression
  that should fail;
- running cases under hostile ambient shell settings such as `IFS`, aliases,
  functions, `set` options, `LC_ALL`, and `LANG` when feasible;
- skipping only genuinely host-dependent cases, with a printed reason.

For VM/Bash parity cases, compare all deterministic outputs:

```txt
stdout
stderr shape where deterministic
exit status
filesystem side effects where deterministic
```

Use exact bytewise expectations. For locale-sensitive checks, deliberately run
with a non-`C` locale when available and assert that helper results remain byte
oriented.

| `char_at` | first byte | one-byte string |

| `char_at` | index == length | failure |
| `char_at` | negative index | failure |
| `slice` | empty range | empty string |
| `slice` | full range | original string |
| `slice` | start > end | failure |
| `slice` | end > length | failure |
| Postfix index | `split(...)[0]` | accepted |
| Postfix index | `split(...)[0].trim()` | accepted |
| Temporary mutation | `split(...)[0] = "x"` | rejected |
| String indexing | `"abc"[0]` | rejected; use `char_at` |
