# v0.38.0 Spec — Recursive Walk Helpers and DX Integration Cleanup

## Status

Implementation and dedicated test pass complete. This milestone was implemented
after `v0.37.0` as the final pass in the current script-writing DX wave that
began with `v0.34.0`, with scoped v0.38 coverage now wired through
`make test-v0-38`.

The implementation work must preserve the project-wide VM/Bash parity rule:
accepted source programs lower to the shared HIR contract and have defined,
matching behavior in direct VM execution and standalone emitted Bash.

`v0.38.0` is both a small feature milestone and an integration cleanup
milestone. The only new production API should be the scoped recursive file-walk
helper surface described here. The rest of the work is documentation, examples,
regression coverage, and cleanup of obsolete DX workarounds from the previous
four milestones.

## Goal

Add a boring, portable recursive file-walk helper for the common case that made
the pure `ds` analyzer shell out to `find`:

```ds
for path_name in dir.walk_ext(root, [".c", ".h"]) {
  echo "{path_name}"
}
```

The supported public surface is intentionally small:

```ds
dir.walk(root)
dir.walk_ext(root, extensions)
dir.walk!(root)
dir.walk_ext!(root, extensions)
```

The helper returns deterministic string arrays of regular file paths under a
root directory. The `!` forms require at least one matched file. The extension
form keeps multi-extension source-file walking readable without adding shell
brace expansion, glob flags, or a general options object.

After adding the helper, audit the DX wave (`v0.34.0` through `v0.38.0`) in
realistic scripts and docs. Move solved notes in `docs/dx-issues.md` into a
resolved section, leave unsolved notes with a current priority, and make the
preferred file-scanning/data-processing workflow visible in examples.

## Motivation

`docs/dx-issues.md` records that the analyzer needed this shell command for
recursive source walking:

```ds
find '{root}' -type f \( -name '*.c' -o -name '*.h' \)
```

`v0.31.0` added safe recursive `glob("**")`, so a script can already write
forms such as:

```ds
for file in glob("src/**/*.c") {
  echo file
}
```

That contract is intentionally conservative and remains useful. It is still not
the best fit for analyzer-style workflows that need to start from a dynamic
root, collect multiple extensions, and avoid rewriting a path pattern string.

`v0.38.0` should make the common case simple while keeping the underlying safety
rules aligned with recursive glob:

- deterministic bytewise ordering;
- duplicate-free results;
- hidden descendants skipped by default;
- directory symlinks not traversed;
- no shell-dependent globstar, brace expansion, extglob, or ambient shell
  options;
- standalone emitted Bash.

This milestone also closes the DX wave by reconciling the old notes with the
implemented fixes: literal braces, direct post-method indexing, parameter kind
inference, row arrays/sort-by-field, and recursive walking.

## Product principles preserved

This milestone preserves these project principles:

- **Shell-native scripts stay direct.** Commands such as `find`, `sort`, and
  `grep` remain available, but common file-walk logic should not require shell
  quoting gymnastics.
- **Every feature runs in the VM.** `dir.walk*` helpers must be implemented in
  the direct execution path.
- **Every feature emits standalone Bash.** Generated Bash must not call `ds`,
  must not depend on the C runtime, and must not depend on ambient shell options.
- **Bash emission shapes the API.** The helper avoids callbacks, iterator
  objects, hidden stateful handles, and options maps until the project has a
  broader typed/nested-collection story.
- **Boring semantics over clever syntax.** No new syntax is introduced. The
  feature is just four standard-library helper names returning string arrays.
- **Clear diagnostics over implicit fallback.** Bad roots, invalid extension
  filters, unsupported values, and filesystem errors should fail with useful
  diagnostics instead of silently delegating to platform-specific shell behavior.

## Chosen API

`v0.38.0` adds these helper calls to the existing `dir` namespace:

```ds
dir.walk(root)
dir.walk_ext(root, extensions)
dir.walk!(root)
dir.walk_ext!(root, extensions)
```

### 1. `dir.walk(root)`

`dir.walk(root)` returns a string array containing every regular file reachable
under `root`, recursively, using the safety defaults defined below.

```ds
let files = dir.walk("src")

for file in files {
  echo file
}
```

The `root` argument must be a string. Literal non-string values are lowering
errors. Dynamic non-string values are runtime data errors in both backends.

The root path must name an existing directory. If the root does not exist, is not
a directory, or cannot be opened, the helper fails at runtime with a diagnostic
that includes the helper name and the root path where practical.

Returned paths should use the same path spelling base that the user supplied:

```ds
dir.walk("src")      # returns paths such as "src/main.c"
dir.walk("./src")    # returns paths such as "./src/main.c"
dir.walk(".")        # returns paths such as "./README.md" or implementation-equivalent stable relative paths
```

The exact `.` spelling must be pinned by implementation tests and current docs.
The important contract is that VM and Bash agree, paths are usable as command
arguments, and ordering is deterministic.

### 2. `dir.walk_ext(root, extensions)`

`dir.walk_ext(root, extensions)` returns only files whose extension is exactly
one of the requested extensions:

```ds
for path_name in dir.walk_ext("src", [".c", ".h"]) {
  echo "{path_name}"
}
```

The `extensions` argument must be a non-empty string array. Each extension must:

- be a string;
- be non-empty;
- begin with `.`;
- not contain `/` or NUL;
- match exactly and bytewise against `path.ext(file)`.

Duplicate extensions are allowed but must not create duplicate output paths.
Extension order does not affect result ordering; results are sorted by path.

Files without an extension are not matched by `dir.walk_ext` in this milestone.
An empty-string extension filter and glob-style extension patterns such as
`"*.c"` are rejected with a diagnostic that suggests using `".c"`.

Case sensitivity is bytewise and platform-neutral for the supported surface:
`".C"` and `".c"` are different filters.

### 3. Bang forms

`dir.walk!(root)` and `dir.walk_ext!(root, extensions)` are required-match
variants. They have the same traversal and filtering behavior as the non-bang
forms, but fail if the resulting array would be empty:

```ds
for path_name in dir.walk_ext!("src", [".c", ".h"]) {
  echo "{path_name}"
}
```

The failure should happen before the loop body runs. In emitted Bash, the
generated helper should return a non-zero status and a clear diagnostic instead
of returning an empty array.

The non-bang forms return an empty string array when the root is valid but no
files match.

### 4. Safety defaults

All four helpers use these defaults:

- traverse recursively from a user-supplied directory root;
- return regular files only;
- return string arrays sorted in deterministic bytewise order;
- remove duplicates if traversal can observe the same file spelling more than
  once;
- skip hidden file and directory descendants by default;
- allow an explicitly hidden root path such as `.config`, but still skip hidden
  descendants below that root unless they are the root itself;
- do not follow directory symlinks;
- do not return symlink entries in this milestone;
- do not cross into platform-specific watcher/indexer behavior;
- do not depend on current Bash shell options, locale, or `find` output format.

The hidden-entry rule is intentionally simple: after the root has been accepted,
any descendant path segment whose basename begins with `.` is skipped.

The symlink rule is intentionally stricter than recursive `glob("**")` to keep
`dir.walk*` close to “regular source files under this tree.” If later users need
symlinked files, that should be a separate explicit option with parity tests.

### 5. Sorting and duplicate policy

Results are sorted by path string in bytewise/ASCII order, the same ordering
family used by deterministic map iteration and recursive glob.

VM and emitted Bash must agree for:

- ordinary ASCII names;
- spaces and tabs in names;
- leading-dash path components;
- braces, brackets, parentheses, quotes, dollar signs, semicolons, and other
  shell metacharacters in file names;
- duplicate extension filters;
- empty directory trees.

Generated Bash should force deterministic helper sorting, for example through a
known `LC_ALL=C` sort path or an equivalent standalone implementation. It must
not inherit ambient locale-sensitive ordering.

### 6. Root path boundaries

The helper accepts ordinary relative and absolute path strings. It does not add
special expansion rules:

- no `~` expansion;
- no shell variable expansion;
- no brace expansion;
- no extglob;
- no raw Bash globstar passthrough;
- no implicit current-directory search beyond the user-supplied root string.

`..` segments in the root path are allowed as literal filesystem path segments,
unlike recursive glob patterns where `..` inside a recursive pattern is rejected.
This keeps `dir.walk(path.join(root, ".."))` a filesystem helper rather than a
glob pattern language. Tests must still cover that VM and Bash agree.

NUL bytes in the root string are rejected.

### 7. Extension filtering boundaries

Extension matching is not glob matching. These are accepted:

```ds
dir.walk_ext("src", [".c"])
dir.walk_ext("src", [".c", ".h"])
dir.walk_ext("src", [".ds"])
```

These are rejected:

```ds
dir.walk_ext("src", [])
dir.walk_ext("src", [""])
dir.walk_ext("src", ["c"])
dir.walk_ext("src", ["*.c"])
dir.walk_ext("src", [".c/.h"])
dir.walk_ext("src", [".c", 1])
```

The diagnostic for `"*.c"` should point users to the extension form:

```txt
dir.walk_ext expects extensions such as ".c", not glob patterns such as "*.c"
```

### 8. Composition with existing language features

The returned value is a normal string array, so it must compose with existing
array and string behavior:

```ds
let files = dir.walk_ext("src", [".c", ".h"])

if files.contains("src/main.c") {
  echo "main is present"
}

let first = files[0]
echo "{path.basename(first)}"
echo "{path.ext(first)}"
```

It must also compose with newer DX features:

```ds
fn is_test_file(file) {
  return path.basename(file).contains("test")
}

let rows = []

for path_name in dir.walk_ext("src", [".c", ".h"]) {
  let text = file.read(path_name)
  let line_count = text.count("\n") + 1
  rows.push({ file: path_name, ext: path.ext(path_name), line_count: line_count })
}

for row in rows.sort_by("line_count", "desc") {
  echo "{row.line_count}\t{row.file}"
}
```

The example above is illustrative for the composition contract. The final
implementation must use the exact supported file-read, string-count, and
arithmetic API names that exist at that point in the project.

### 9. HIR/debug visibility

`dir.walk*` calls should appear in debug output as ordinary stdlib calls with
known return kind `array<string>`. The implementation does not need a new HIR
node for walking unless the existing stdlib call representation cannot carry the
required helper identity, bang/no-bang behavior, and return-kind metadata.

The checker/lowerer should record enough metadata for VM and Bash to avoid
re-deriving whether a helper is required-match or extension-filtered.

## Non-goals

Do not implement any of these in `v0.38.0`:

- new syntax;
- shell-style brace expansion;
- extglob;
- `~` expansion;
- shell variable expansion inside helper arguments;
- raw Bash globstar passthrough;
- multiple recursive glob segments beyond the existing recursive-glob contract;
- hidden traversal flags or options objects;
- symlink-following traversal;
- max-depth options;
- streaming iterators or lazy filesystem handles;
- directory result rows, file metadata rows, stat structs, permissions, owners,
  timestamps, sizes, or hashes;
- filesystem watcher/indexer APIs;
- Windows-specific path semantics;
- callbacks/predicates passed to the walker;
- custom comparators or custom sort options;
- nested row/file metadata collection support beyond `v0.37.0` row arrays;
- a broad glob library redesign.

If an implementation issue suggests one of these is needed, defer it and keep the
current milestone focused on deterministic file lists by root and extension.

## VM behavior

The VM helper must:

- validate root and extension arguments;
- reject embedded NUL bytes in root or extension strings;
- open and traverse the root directory without invoking a shell;
- skip hidden descendants;
- skip symlink entries and never traverse directory symlinks;
- collect regular-file paths as owned strings;
- filter by exact extension for `dir.walk_ext*`;
- sort bytewise and deduplicate results;
- return a string array value with correct element-kind metadata;
- fail required-match variants when the final array is empty;
- close directory handles and release temporary memory on success and failure;
- report filesystem/data errors through the shared diagnostic path.

The VM may use an iterative traversal stack instead of recursion if that keeps
deep trees safer. Directory read order from the host filesystem must not leak
into user-visible result ordering.

## Bash emission behavior

Generated Bash must remain standalone.

For accepted `dir.walk*` calls, emitted Bash must:

- include helper definitions only when needed;
- deduplicate helper definitions;
- use reserved `__ds_` helper names;
- avoid calling `ds`;
- avoid relying on ambient `globstar`, `dotglob`, `nullglob`, `failglob`, locale,
  aliases, shell functions, or user `IFS` values;
- preserve file names containing spaces, tabs, newlines, leading dashes, and shell
  metacharacters where Bash can represent them safely;
- return a Bash-side string array with the same type sidecar metadata used for
  other string-array stdlib results;
- fail bang forms before the consuming loop body runs;
- agree with the VM for sorting, hidden-entry skipping, symlink policy, and
  extension filtering.

The Bash helper may use standard POSIX-ish tools that the project already allows
for generated Bash, but it must not use `find` in a way that makes ordering,
hidden-entry treatment, symlink treatment, or hostile names diverge from the VM.
If `find` is used internally, tests must prove the accepted filename surface is
safe and deterministic. A pure Bash traversal is acceptable if it is easier to
keep standalone and parity-safe.

## Diagnostics and debugging behavior

Diagnostics should be phase-owned:

- parser: no new syntax, so parser errors should only cover ordinary call/array
  syntax mistakes;
- lowerer/checker: statically known wrong argument counts, literal non-string
  roots, literal invalid extension arrays, and unsupported whole-result uses;
- VM/Bash runtime helpers: dynamic bad roots, permissions, dynamic invalid
  extension values, too-deep or unreadable directories, and OS data errors.

Required diagnostic qualities:

- include the helper name (`dir.walk`, `dir.walk_ext`, `dir.walk!`, or
  `dir.walk_ext!`);
- include the bad root or extension value when safe and useful;
- explain the expected extension format for extension-filter failures;
- distinguish a valid root with no matches from an invalid/unreadable root;
- distinguish non-bang empty results from bang required-match failures;
- preserve source spans for statically knowable failures;
- avoid backend-specific wording differences where tests can reasonably compare
  stderr shape.

## Examples

### Recursive file listing

```ds
for path_name in dir.walk("src") {
  echo "{path_name}"
}
```

### Source extension filtering

```ds
for path_name in dir.walk_ext("src", [".c", ".h"]) {
  echo "{path.ext(path_name)}\t{path_name}"
}
```

### Required source files

```ds
for path_name in dir.walk_ext!("src", [".c"]) {
  echo "{path_name}"
}
```

If there are no `.c` files under `src`, the script fails before the loop body
runs.

### Analyzer-style flow after the DX wave

```ds
let rows = []

for path_name in dir.walk_ext("src", [".c", ".h"]) {
  let text = file.read(path_name)
  let line_count = text.count("\n") + 1
  rows.push({ file: path_name, ext: path.ext(path_name), line_count: line_count })
}

for row in rows.sort_by("line_count", "desc") {
  echo "{row.line_count}\t{row.ext}\t{row.file}"
}
```

The final implementation should adjust this example to the exact supported
standard-library and arithmetic surface if any name differs.

## Acceptance criteria

`v0.38.0` is complete when:

- `dir.walk`, `dir.walk_ext`, `dir.walk!`, and `dir.walk_ext!` are documented and
  implemented as the only new public helper names for this milestone;
- all four helpers run in the VM;
- all four helpers emit to standalone Bash;
- VM and Bash agree on successful results, empty results, required-match
  failures, invalid roots, hidden descendants, symlink policy, extension filters,
  ordering, duplicates, and hostile file names;
- returned values are ordinary string arrays and compose with array loops,
  indexing, membership, `path.ext`, string helpers, function returns, and row
  arrays where supported;
- bad literal extension filters are rejected statically where possible;
- dynamic data failures are reported in both backends with clear helper-focused
  diagnostics;
- generated Bash helper bodies are included only when needed and deduplicated;
- current docs and examples are reconciled with the DX wave;
- `docs/dx-issues.md` has a resolved section for completed DX-wave items and a
  fresh open-items list;
- the dedicated `v0.38.0` tests from the companion test plan are implemented and
  wired into the aggregate test target;
- the completion review below is filled in.

## Deferred to later milestones

- Hidden traversal options such as `include_hidden`.
- Symlink-following traversal and deterministic cycle handling.
- Max-depth and min-depth options.
- Directory result listings and file metadata rows.
- File size, mtime, permissions, owner, inode, and hash helpers.
- Streaming/lazy filesystem iterators.
- Callback or predicate-based file filters.
- Glob brace expansion, extglob, shell variable expansion, `~` expansion, and
  raw Bash globstar passthrough.
- A broader path API for platform-specific path semantics.
- Regex capture ergonomics, which remain an open analyzer DX item outside this
  milestone.
