# v0.8.0 Test Plan — Cleanup: Command Model and Bash Parity

## Purpose

This test plan verifies that the `v0.8.0` cleanup preserves the complete
supported behavior from `v0.1.0` through `v0.7.0` while making command internals
and parity tests easier to reuse.

Because `v0.8.0` is a cleanup milestone, tests should be regression-heavy. The
goal is not to prove new syntax. The goal is to prove that refactors of command
representation, command-result field helpers, process execution, Bash helper
generation, diagnostics, and test infrastructure do not change the user-facing
language.

Every accepted fixture that already worked in VM mode must still work in VM
mode. Every accepted fixture that can emit to Bash must still emit standalone
Bash with matching behavior. Every rejected fixture must continue to fail before
execution/emission where practical.

## Test categories

The version should include tests for:

- full regression of all previous version suites;
- command representation ownership and cloning/freeing;
- command-word validation and backend rendering consistency;
- command-result field descriptor consistency;
- plain command process behavior;
- captured command process behavior;
- redirection file behavior and open-failure diagnostics;
- Bash helper dependency generation;
- failed Bash artifact cleanup;
- diagnostic consistency across `check`, `bytecode`, `run`, direct execution,
  and `emit bash`;
- shared VM/Bash parity helper behavior;
- no new syntax accepted accidentally;
- generated Bash remaining standalone;
- ASAN/UBSAN cleanup confidence.

Do not use `docs/language.ds` as an executable fixture. It intentionally contains
future syntax.

## Baseline regression commands

Before cleanup work starts, run:

```sh
make check
make test
make test-v0-7
```

If sanitizer targets are available in the environment, also run:

```sh
make asan
make ubsan
```

Failure rule:

- If a predecessor suite fails before cleanup starts, fix or explicitly record
  the predecessor regression before refactoring.
- Do not delete or weaken predecessor tests to make cleanup pass.
- If a golden changes because diagnostics are intentionally improved, update the
  golden and explain the improvement in the completion review.

After implementation, `make test` must include `tests/v0_8/run.sh` in addition
to all prior version suites, and `Makefile` should expose a `test-v0-8` target.

## Public command smoke matrix

Run a representative supported fixture through every public command family:

```sh
ds tokens <fixture.ds>
ds ast <fixture.ds>
ds check <fixture.ds>
ds bytecode <fixture.ds>
ds run <fixture.ds> [args...]
ds <fixture.ds> [args...]
ds emit bash <fixture.ds> -o <fixture.sh>
bash -n <fixture.sh>
bash <fixture.sh> [args...]
```

Required representative fixtures:

- basic v0.1.0/v0.2.0 script;
- VM expression/block script;
- script-args fixture;
- import fixture;
- command-result capture fixture;
- redirection fixture;
- capture plus script args;
- capture plus imports.

Assertions:

- `tokens` and `ast` remain debug-oriented and pointer-free;
- `check` validates but does not execute commands;
- `bytecode` is deterministic and pointer-free;
- direct execution and `ds run` match;
- generated Bash passes `bash -n`;
- generated Bash does not reference the `ds` executable;
- output, exit status, and generated files match VM behavior where parity is
  expected.

## Shared parity helper tests

Move reusable VM/Bash parity logic into shared test helpers, then test those
helpers by using them from `v0_8/run.sh` and updating at least the command-heavy
`v0_7` parity checks to use the shared helper.

The shared helper should support:

- fixture path;
- optional script arguments;
- isolated VM working directory;
- isolated Bash working directory;
- emitted Bash path;
- expected exit status;
- stdout comparison;
- stderr comparison;
- optional output file comparison list;
- clear failure dumps.

Required parity cases:

```txt
capture_success
capture_failure
capture_stderr
capture_args_with_shell_metacharacters
field_interpolation
redirect_stdout
redirect_stderr
redirect_combined
import_capture
script_args_capture
plain_fail_fast
```

Edge cases:

- expected non-zero status from a plain command should match between VM and
  Bash;
- captured non-zero command status should not make the script fail unless the
  script explicitly exits/fails;
- output files should be compared by content and missing-file behavior;
- parity helpers must not accidentally run fixtures from the repository root
  unless a test explicitly requests it;
- script arguments containing spaces, `$`, backticks, semicolons, and braces
  must survive VM and Bash execution without command injection.

## Command model unit tests

If `v0.8.0` introduces a shared command representation or helpers, add unit tests
for ownership and cloning.

Suggested C unit coverage:

- initialize an empty command;
- append literal words with spans;
- clone a command with multiple words;
- clone a command with redirection metadata;
- free original and clone independently;
- clear and reuse a command;
- preserve target/operator spans;
- reject or handle allocation-free empty command consistently;
- no leaks under ASAN.

Integration fallback:

- If no direct unit API is exposed, exercise equivalent behavior through a
  lowered fixture and `ds bytecode` / `ds run` / `ds emit bash`.

Assertions:

- no pointer addresses in debug output;
- no source span collapse after clone/free;
- redirection target remains intact after lowering and bytecode generation;
- repeated lowering/freeing of the same source does not leak or double-free.

## Command-result field descriptor tests

Test the shared field descriptor/helper directly if available.

Required fields:

| Field | Kind | Expected runtime value |
| --- | --- | --- |
| `stdout` | string | captured stdout |
| `stderr` | string | captured stderr |
| `code` | int | process exit code |
| `ok` | bool | `code == 0` |
| `failed` | bool | `code != 0` |

Required rejected fields:

```txt
missing
status
exit_code
out
err
stdout.trim
```

Assertions:

- `ds check` accepts every supported field in expressions, command arguments,
  and string interpolation;
- `ds check` rejects unsupported fields before execution;
- `ds bytecode` prints supported field names deterministically;
- VM execution returns the expected values;
- Bash emission returns the same values;
- adding/removing a field in only one backend is caught by tests.

## Process execution tests

Process cleanup should be tested through VM execution and, where helpful, direct
C unit tests for any new wrapper.

### Plain command behavior

Fixtures:

```ds
printf "ok"
```

```ds
sh -c "exit 7"
echo "unreachable"
```

```ds
definitely-not-a-real-command-for-ds
```

Assertions:

- success streams stdout/stderr normally;
- non-zero exit status stops the script;
- subsequent statements are not executed after fail-fast command failure;
- command-not-found is non-zero and reports a useful command diagnostic;
- behavior matches emitted Bash where Bash can produce equivalent behavior;
- no descriptors or temporary files are leaked.

### Captured command behavior

Fixtures:

```ds
let r = run printf "ok"
echo r.stdout
echo r.code
```

```ds
let r = run sh -c "echo out; echo err >&2; exit 9"
echo r.stdout
echo r.stderr
echo r.code
echo r.failed
```

```ds
let r = run definitely-not-a-real-command-for-ds
echo r.code
echo r.failed
echo r.stderr
```

Assertions:

- captured stdout is not streamed during execution;
- captured stderr is not streamed during execution;
- stdout/stderr fields preserve contents separately;
- exit code is captured as an integer;
- non-zero captured command status is inspectable and non-fatal;
- command launch failure follows the documented capture behavior;
- empty output is represented as an empty string;
- large output within the existing practical test limit is not truncated;
- repeated captures do not reuse stale stdout/stderr/code values.

### Executable/argument edge cases

Test command words containing or expanding to:

- spaces;
- quotes;
- backslashes;
- `$HOME`;
- `$(echo hacked)`;
- backticks;
- semicolons;
- braces;
- UTF-8 bytes.

Assertions:

- each value is passed as one argv word where expected;
- no command substitution-looking value is executed accidentally;
- VM and Bash emitted behavior match;
- diagnostics still point to the right word when a bad `$name` or bad field is
  present.

## Redirection tests

Regression-test all six supported operators in VM and emitted Bash:

| Operator | File mode | Stream behavior |
| --- | --- | --- |
| `|>` | truncate | stdout only |
| `|>>` | append | stdout only |
| `!>` | truncate | stderr only |
| `!>>` | append | stderr only |
| `&>` | truncate | stdout and stderr |
| `&>>` | append | stdout and stderr |

Assertions:

- VM writes the expected file content;
- emitted Bash writes the same file content;
- truncate clears previous content;
- append preserves previous content;
- stdout-only redirection does not capture stderr;
- stderr-only redirection does not capture stdout;
- combined redirection preserves deterministic ordering for deterministic
  commands;
- redirected plain command failures remain fail-fast;
- missing parent directory produces source-located diagnostics;
- directory target or permission-denied target produces source-located
  diagnostics where the environment supports it;
- failed redirection does not execute the child command;
- failed `emit bash` for malformed redirection removes stale output artifacts.

## Bash helper generation tests

Use fixtures that require no helpers, capture helpers, redirection only, and both
capture plus redirection in one script.

Assertions:

- scripts without `run` do not emit command capture helpers;
- scripts with `run` emit the capture helper exactly once;
- helper names use the `__ds_` prefix;
- generated Bash contains no references to the local `ds` binary path;
- generated Bash passes `bash -n`;
- generated Bash works when copied to and executed from another directory;
- capture helper preserves separate stdout/stderr and exit code;
- strict mode remains present;
- helper ordering is deterministic in golden output;
- failed emission removes or truncates stale output artifacts according to the
  documented CLI behavior.

Golden tests should verify representative helper output, but avoid making every
small internal formatting decision painful to change. Prefer one or two focused
goldens plus behavior parity tests.

## Diagnostic consistency tests

For each fixture below, run the relevant public commands and compare source
location/message shape:

```sh
ds check fixture.ds
ds bytecode fixture.ds
ds run fixture.ds
ds fixture.ds
ds emit bash fixture.ds -o out.sh
```

Lexer/parser/lowering errors should generally match across commands that parse
or lower. Runtime-only errors may only appear in `run`/direct execution.

Required diagnostics:

- `let r = run`
- `let r = run |> "out.txt"`
- `let r = run printf "x" &> "out.txt"`
- `printf "x" | grep x`
- `printf "x" > out.txt`
- `printf "x" &>`
- `printf "x" &> "a" &> "b"`
- `echo $missing`
- `echo result.`
- `echo result.missing`
- `let s = "x"; echo s.stdout`
- `echo "{result.missing}"`
- redirection target with a missing parent directory.

Assertions:

- command exits non-zero;
- diagnostic line starts with `path:line:column: error:`;
- highlighted span points at the relevant token or target;
- `check` does not execute commands;
- `emit bash` does not leave a successful-looking output script after failure;
- unsupported future syntax is rejected before VM/Bash backend execution.

## Import and script-arg interaction tests

Because `v0.5.0` and `v0.6.0` are part of the current supported surface, command
cleanup must preserve their interaction with command results.

Required cases:

- imported file defines a command-result variable used by root code;
- imported file uses a captured command and root file emits standalone Bash;
- root file with `script { ... }` passes an arg into a captured command;
- script arg with spaces/metacharacters is captured as data, not executed;
- unknown imported command variable still reports the imported file location;
- import-cycle diagnostics are unchanged by command refactors;
- imported files still cannot declare their own script block in the current
  supported model.

Assertions:

- VM and emitted Bash output match;
- emitted Bash remains one standalone file;
- diagnostics retain the correct source file after import composition;
- script `--help` output is unchanged.

## No new syntax / unsupported feature tests

`v0.8.0` should not accidentally unlock future syntax.

Rejected examples:

```ds
cat a | grep x
let r = run cat a | grep x
cmd < "input.txt"
cmd << "EOF"
cmd &
cmd && other
cmd || other
let r = run cmd &> "out.txt"
fn deploy() {}
for x in xs {}
while true {}
```

Assertions:

- rejected by parser/lowering with clear diagnostics;
- not executed;
- not emitted;
- failed emission leaves no stale artifact;
- diagnostics do not mention unrelated features or internal C types.

## Static boundary checks

Add lightweight scripted checks when practical. These should guard cleanup goals
without becoming brittle.

Recommended checks:

- generated Bash helper names start with `__ds_`;
- generated Bash does not contain the absolute path to the local `ds` binary;
- bytecode and AST output contain no pointer addresses such as `0x...`;
- version-local tests do not duplicate a large parity helper if a shared helper
  exists;
- unrelated code does not include or call staged hashmap internals directly;
- backend code does not parse raw source text for command-result fields when the
  lowered representation already provides them.

Avoid fragile checks that forbid harmless implementation details. Static checks
should fail only on real boundary regressions.

## Sanitizer and leak-oriented tests

Run the full regression suite under available sanitizers:

```sh
make asan
make ubsan
```

At minimum, targeted `v0.8.0` tests should run under sanitizer builds if the full
suite is too slow in the environment:

```sh
make clean
make CFLAGS="-std=c99 -Wall -Wextra -Wpedantic -g -fsanitize=address" all
ASAN_OPTIONS=detect_leaks=0:abort_on_error=1 DS_SKIP_BUILD=1 ./tests/v0_8/run.sh

make clean
make CFLAGS="-std=c99 -Wall -Wextra -Wpedantic -g -fsanitize=undefined" all
DS_SKIP_BUILD=1 ./tests/v0_8/run.sh
```

Sanitizer-sensitive cases:

- repeated command cloning/freeing;
- repeated command captures;
- captured large output;
- redirection open failure;
- process launch failure;
- malformed command diagnostics;
- failed Bash emission with stale output cleanup;
- import composition plus command capture.
